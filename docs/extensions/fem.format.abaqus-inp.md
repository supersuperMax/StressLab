# Модуль `fem.format.abaqus-inp`: импорт входных файлов Abaqus

Встроенный нативный модуль (`extensions/fem.format.abaqus-inp/`, C++): читает `.inp` Abaqus и CalculiX в Model IR —
сетки и наборы ядра, объекты `fem.model.structural` (`docs/extensions/fem.model.structural.md`). Всё, чего в модели
нет, сохраняется объектами «Ключевое слово Abaqus» со своим местом в файле, чтобы экспорт (задача 3.3) вернул их.
Решения и причины — `docs/adr/0024-abaqus-inp-import.md`.

## Как вызвать

- В окне: **Файл → Импорт…**, фильтр «Входной файл Abaqus (*.inp)». Объекты добавляются в текущую модель; перед
  импортом проект делает автоматическую версию (`snapshotBefore`). Предупреждения — во вкладке «Проблемы».
- Из Python и в журнале: `stresslab.cmd("inp.import", path="деталь.inp")`, необязательный `encoding="windows-1251"`.
  Команда возвращает id объекта файла (`abaqus_input`). Без окна предупреждения печатаются в stderr.
- Модуль загружается при первом открытии `.inp` (`onOpenFile:*.inp`) или первом вызове команды.

Ошибка, из-за которой файл не прочитать (нет файла `*INCLUDE`, элемент ссылается на несуществующий узел, повтор
метки, не число в данных, незакрытый `*PART`, `*NGEN`/`*NCOPY`/`*SYSTEM`/`*PARAMETER`), отменяет импорт: модель не
меняется, во вкладке «Проблемы» — что и где (`файл:строка`), в Python — `stresslab.ExtensionError`.

## Что читается

| Ключевое слово | В модели |
|---|---|
| `*HEADING` | свойство `heading` объекта файла `abaqus_input` |
| `*INCLUDE, INPUT=` | строки файла встают на место `*INCLUDE` (путь — относительно включающего файла; кириллица и пробелы в путях допустимы); цикл включений — ошибка |
| `*NODE` (`NSET`) | узлы сетки; `SYSTEM` кроме `R` — ошибка |
| `*ELEMENT` (`TYPE`, `ELSET`) | блок сетки на каждый тип Abaqus; строки данных продолжаются по числу узлов |
| `*NSET`, `*ELSET` (`GENERATE`, `INSTANCE`, наборы в строках, `*NSET, ELSET=`) | `node_set`, `element_set`; повторное объявление дополняет набор |
| `*SURFACE` (`TYPE=ELEMENT`, грани `S1`…`S6`) | `surface`: грань Abaqus — сторона нейтральной формы с теми же углами |
| `*PART`, `*ASSEMBLY`, `*INSTANCE` (перенос и поворот) | сетка на каждый инстанс; узлы сборки — сетка с именем сборки |
| `*MATERIAL` + `*ELASTIC` (изотропный, одна строка), `*DENSITY` | `material` |
| `*SOLID SECTION`, `*SHELL SECTION` (толщина, точки, `OFFSET`), `*BEAM SECTION` (`RECT`, `CIRC`, `PIPE`, направление) | `solid_section`, `shell_section`, `beam_section`; интегрирование — по типам элементов набора |
| `*STEP` (`NAME`, `INC`) + `*STATIC` | `static_step` (`initialIncrement`, `timePeriod`, `maxIncrements`) |
| `*BOUNDARY` (степени 1–6, диапазоны, значение, `ENCASTRE`, `PINNED`, `X/Y/ZSYMM`, `X/Y/ZASYMM`) | `boundary_condition`: в данных модели — в корне (во всех шагах), в шаге — ребёнок шага |
| `*CLOAD` (степени 1–6) | `concentrated_load`; одинаковые степени одной цели складываются |
| `*DLOAD` (`P1`…`P6` — давление на грани, `P` — на оболочки, `GRAV`) | `pressure` (на поверхность или набор оболочек), `gravity` (пустая цель — вся модель) |
| `*DSLOAD` (`P`) | `pressure` на поверхность |
| `*OUTPUT, FIELD` (`VARIABLE=PRESELECT`/`ALL`), `*NODE OUTPUT`, `*ELEMENT OUTPUT`, `*NODE FILE`, `*EL FILE` → `results`; `*NODE PRINT`, `*EL PRINT` → `table` | `output_request` (`U`, `RF`, `S`, `E`, частота) |

Имена — как в файле, ссылки — без учёта регистра. Объекты без имени в `.inp` получают имя цели: сечение — имя
набора (`<инстанс>.<набор>`, если у детали несколько инстансов), нагрузка и ГУ — имя набора. Узлы и элементы,
заданные метками в строке нагрузки, собираются в служебные наборы `_Cload-1`, `_Boundary-1`, `_Dload-1`… (метки с
одинаковыми значениями — в один набор). При повторном импорте в ту же модель занятые имена получают `-2`, `-3`…

### Типы элементов

| Форма | Типы этапа 3 | Читаются с предупреждением |
|---|---|---|
| `tet4`, `tet10` | C3D4, C3D10 | C3D4H, C3D10H, C3D10M, C3D10MH, C3D10HS, C3D10I |
| `hex8`, `hex20` | C3D8, C3D8R, C3D20, C3D20R | C3D8H, C3D8I, C3D8IH, C3D8RH, C3D20H, C3D20RH |
| `wedge6`, `wedge15` | — | C3D6, C3D6H, C3D15, C3D15H |
| `tri3`, `quad4`, `tri6`, `quad8` | S3, S4, S4R | S3R, S4R5, S6, S8R, S8R5 |
| `line2`, `line3` | B31 | B31H, B32, B32H |

Порядок узлов этих типов совпадает с нейтральной нумерацией (ADR 0002 п. 7). Тип Abaqus каждого блока записан в
`abaqus_element_types.blocks` — для экспорта и проверок решателя. Прочие типы (CPS4, CAX4, R3D4, SPRINGA…) —
в passthrough вместе с их `*ELEMENT`; их метки в наборах пропускаются с предупреждением.

## Что сохраняется без интерпретации

Объект `abaqus_keyword` (дерево: «Ключевое слово Abaqus»), только для чтения:

| Свойство | Значение |
|---|---|
| `keyword` | `*CONTACT CONTROLS` |
| `text` | строка ключевого слова и строки данных, как в файле, без комментариев |
| `file`, `line` | файл (относительно главного, через `/`) и строка ключевого слова |
| `index` | номер ключевого слова в файле с подставленными включениями, от 0 — порядок для экспорта |
| `part`, `assembly`, `instance`, `material`, `step` | где было ключевое слово, если внутри |

Родитель — шаг, в котором оно было, материал (его неподдержанные подопции: `*PLASTIC`, `*EXPANSION`…) или
объект файла. Попадает сюда:

- любое ключевое слово, которого нет в таблице выше (`*AMPLITUDE`, `*TIE`, `*CONTACT PAIR`, `*RESTART`,
  `*OUTPUT, HISTORY` вместе со своими `*NODE OUTPUT`…);
- шаг другой процедуры (`*FREQUENCY`, `*DYNAMIC`, `*STATIC, RIKS`…) целиком, от `*STEP` до `*END STEP`;
- ключевое слово с параметром, меняющим смысл (`OP=NEW`, `AMPLITUDE=`, `TYPE=VELOCITY`, `FOLLOWER`, сечение с
  `ORIENTATION`, материал с `DEPENDENCIES`…);
- строки ключевого слова, которых модель не понимает (температурная степень свободы в `*BOUNDARY`, `BX` в
  `*DLOAD`, переменная `ENER` в `*EL FILE`): понятые строки — в модели, остальные — passthrough с той же
  строкой ключевого слова;
- ссылка на неизвестное имя или на то, что само ушло в passthrough (давление на узловую поверхность);
- `*ELASTIC`/`*DENSITY` с значениями по температуре; поверхности `TYPE=NODE`, `SPOS`/`SNEG`, рёбер.

На каждое такое место — предупреждение во вкладке «Проблемы» («*CONTACT CONTROLS сохранено без интерпретации»);
одинаковые сводятся в одно с числом.

## Кодировки и числа

BOM UTF-8 и UTF-16 (LE/BE) распознаются сами. Без BOM файл читается как UTF-8, а если байты не UTF-8 —
`encoding`: `auto` берёт Windows-1252 и предупреждает, `windows-1251` — кириллица, `latin-1`, `utf-8` — отказ.
Переводы строк CRLF, LF и CR. Числа — `12`, `-3.`, `.5`, `2.1e5`, `7.85D-9`, независимо от локали.

## Единицы

В `.inp` единиц нет: значения записываются в системе единиц модели (`Document::units`) без пересчёта, о чём импорт
сообщает строкой подсказки. Перед импортом файла в мм–т–с переключите единицы модели (`model.set_units`).
