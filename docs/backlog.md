# Backlog

Замеченное по ходу задач, но не входящее в их объём (CLAUDE.md, «Как работать над задачей», п. 4).
Формат: что сделать, откуда взялось, когда нужно.

- **SessionStart-хук для облачных сессий Claude Code** (компилятор, CMake, Ninja, Python, `calculix-ccx`).
  Задача 1.1 делалась локально, хук не создавался. Нужен до первой облачной сессии.
- **Qt и Qt ADS линкуются статически на Linux и macOS.** Триплеты vcpkg по умолчанию (`x64-linux`, `arm64-osx`)
  статические, а LGPL требует динамической линковки (или выдачи объектных файлов) в распространяемых сборках.
  Перейти на `*-dynamic` триплеты (хотя бы для Qt) до задачи 3.11 «Поставка».
- **CI на macOS x64.** `docs/architecture.md` §8 упоминает macOS arm64 и x64, а план и CLAUDE.md — только arm64.
  Решить при задаче 3.11 (Universal 2 всё равно потребует x64-сборку).
- **VTK в фиче `gui` vcpkg.** Не добавлен в 1.1, чтобы не собирать VTK в CI без пользы; добавить в задаче 3.7.
- **ccache/sccache в CI** (`docs/architecture.md` §9). Пока хватает бинарного кэша vcpkg; добавить, когда сборка
  собственного кода станет заметной.
- **Round-trip тесты сериализации для `mesh`, `node_set`, `element_set`, `surface`** (CLAUDE.md, правило 6).
  Типы появились в 1.2, а сериализации ещё нет. Сделать в 2.1 (описание объектов) и 2.2 (массивы в блоках).
- **Имена объектов и регистр в файловой системе.** В Model IR имена уникальны с учётом регистра (`Top` и `top` —
  разные наборы), а файловые системы Windows и macOS регистр не различают. Учесть при именовании файлов
  `model/…` в задаче 2.1 (например, имя файла по id или с суффиксом при совпадении).
- **Стороны «верх/низ» оболочечных элементов в поверхностях.** Сейчас сторона 2D-элемента — это его ребро
  (ADR 0002). Поверхности на гранях оболочек понадобятся для давления на оболочки через поверхность —
  решить в задачах 3.1/3.2.
- **Большие наборы в хранилище проекта.** Раскладка `model/sets/…` предполагает JSON, а набор может содержать
  сотни тысяч индексов. В задачах 2.1/2.2 хранить массивы наборов блоками, а в JSON — только ссылку.
- **Товарный знак StressLab.** Не проверялся (`resources/branding/stresslab-kit/guidelines.md` §8): нужен поиск
  по базам Роспатента, WIPO, EUIPO и обратный поиск изображений логотипа. Сделать до первого публичного релиза (3.11).
- **Лицензия на логотип и иконки.** `LICENSE` (MIT) сейчас покрывает весь репозиторий, включая
  `resources/branding/`. Решить, исключать ли бренд-кит из MIT (отдельная политика использования знака, как
  у многих открытых проектов). Появилось в 1.2a; нужно до 3.11.
- **CI `full` на macOS падает с момента слияния 1.1.** Порт `libb2` (зависимость `qtbase`) собирается через
  autotools, а на раннере `macos-14` нет `autoconf`, `autoconf-archive`, `automake` и `libtoolize`. На Linux они ставятся шагом
  apt в `.github/workflows/build.yml`; для macOS нужен такой же шаг (`brew install autoconf autoconf-archive automake libtool`).
  Замечено в 1.2a; нужно до 1.11 (первая GUI-задача).
- **Загрузка проекта мимо Command Bus.** После 1.3 изменить `Document` можно только командой, а загрузка папки
  проекта — не изменение модели и должна создавать объекты с сохранёнными id без журнала и undo. Нужен отдельный
  путь загрузки (например, построитель документа в ядре). Решить в 2.1 (ADR 0004, «Последствия»).
- **Лимит стека undo.** Сейчас стек не ограничен; записи держат удалённые объекты и прежние сетки. Сделать
  настройкой в 1.7.
- **Команда «изменить одно свойство».** `model.set_properties` заменяет все свойства объекта, и в журнале правка
  одного поля выглядит как весь словарь. Для генератора форм (1.13) добавить `model.set_property` (путь к полю и
  значение).
- **Меню «Правка» и кнопки отмены.** Ключи `history.canUndo`/`history.canRedo` есть с 1.4
  (`fem::context::CoreKeys`), подписи шагов — `CommandBus::undo_label`/`redo_label`. Показать в 1.12.
- **Объявление context keys в манифесте.** `docs/architecture.md` §4.3 говорит, что модули объявляют свои ключи,
  а в таблице contribution points §4.2 точки для этого нет. После 1.4 модуль объявляет ключи кодом
  (`ContextKeys::declare`); решить в 1.5, нужна ли точка `contextKeys` (имя, тип, начальное значение), чтобы
  ключи выключенного модуля были видны без загрузки его кода (ADR 0005, «Последствия»).
- **«Почему недоступно» в палитре команд.** `docs/interface-design.md` хочет показывать недоступные команды
  серым с причиной. Нужен разбор условия `when`: какая часть ложна и какие ключи в ней (например, «нет сетки»
  для `model.hasMesh`). Сделать в 1.12 поверх `WhenExpression`.
- **Операторы порядка и прочие операторы `when` из VS Code.** В 1.4 сделаны `&&`, `||`, `!`, `==`, `!=`, `in`.
  `<`, `<=`, `>`, `>=` (например, `selection.count > 1`), `not in` и `=~` добавить, когда понадобятся условию
  из манифеста; смысл существующих условий от этого не меняется (ADR 0005).
- **Имена Python-обёрток для id команд с дефисом.** Id команды может содержать `-` (`fem.format.ansys-cdb.export`),
  а `stresslab.<module>.<command>(...)` требует идентификаторов Python. Выбрать правило преобразования в 1.8.
- **Включение модулей в журнале.** Журнал воспроизводится тождественно, только если включены те же модули, а
  включение пока не пишется в журнал. Сделать его командой в 1.5/1.15 (`stresslab.extensions.enable/disable`).
- **`std::to_chars(double)` и deployment target macOS.** Журнал форматирует числа через `std::to_chars`, которому
  в libc++ нужен macOS ≥ 13.3. При выборе минимальной версии macOS в 3.11 либо держать ≥ 13.3, либо заменить
  форматирование (например, на {fmt}).
