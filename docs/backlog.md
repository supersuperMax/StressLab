# Backlog

Замеченное по ходу задач, но не входящее в их объём (CLAUDE.md, «Как работать над задачей», п. 4).
Формат: что сделать, откуда взялось, когда нужно.

- **SessionStart-хук для облачных сессий Claude Code** (компилятор, CMake, Ninja, Python, `calculix-ccx`).
  Задача 1.1 делалась локально, хук не создавался. Нужен до первой облачной сессии.
- **Qt и Qt ADS линкуются статически на Linux и macOS.** Триплеты vcpkg по умолчанию (`x64-linux`, `arm64-osx`)
  статические, а LGPL требует динамической линковки (или выдачи объектных файлов) в распространяемых сборках.
  Перейти на `*-dynamic` триплеты (хотя бы для Qt) до задачи 3.11 «Поставка».
- **CI на macOS x64.** `docs/architecture.md` §8 упоминает macOS arm64 и x64, а план и CLAUDE.md — только arm64.
  Решить при задаче 3.11 (Universal 2 всё равно потребует x64-сборку).
- **VTK в фиче `gui` vcpkg.** Не добавлен в 1.1, чтобы не собирать VTK в CI без пользы; добавить в задаче 3.7.
- **ccache/sccache в CI** (`docs/architecture.md` §9). Пока хватает бинарного кэша vcpkg; добавить, когда сборка
  собственного кода станет заметной.
- **Round-trip тесты сериализации для `mesh`, `node_set`, `element_set`, `surface`** (CLAUDE.md, правило 6).
  Типы появились в 1.2, а сериализации ещё нет. Сделать в 2.1 (описание объектов) и 2.2 (массивы в блоках).
- **Имена объектов и регистр в файловой системе.** В Model IR имена уникальны с учётом регистра (`Top` и `top` —
  разные наборы), а файловые системы Windows и macOS регистр не различают. Учесть при именовании файлов
  `model/…` в задаче 2.1 (например, имя файла по id или с суффиксом при совпадении).
- **Стороны «верх/низ» оболочечных элементов в поверхностях.** Сейчас сторона 2D-элемента — это его ребро
  (ADR 0002). Поверхности на гранях оболочек понадобятся для давления на оболочки через поверхность —
  решить в задачах 3.1/3.2.
- **Большие наборы в хранилище проекта.** Раскладка `model/sets/…` предполагает JSON, а набор может содержать
  сотни тысяч индексов. В задачах 2.1/2.2 хранить массивы наборов блоками, а в JSON — только ссылку.
- **Товарный знак StressLab.** Не проверялся (`resources/branding/stresslab-kit/guidelines.md` §8): нужен поиск
  по базам Роспатента, WIPO, EUIPO и обратный поиск изображений логотипа. Сделать до первого публичного релиза (3.11).
- **Лицензия на логотип и иконки.** `LICENSE` (MIT) сейчас покрывает весь репозиторий, включая
  `resources/branding/`. Решить, исключать ли бренд-кит из MIT (отдельная политика использования знака, как
  у многих открытых проектов). Появилось в 1.2a; нужно до 3.11.
- **Загрузка проекта мимо Command Bus.** После 1.3 изменить `Document` можно только командой, а загрузка папки
  проекта — не изменение модели и должна создавать объекты с сохранёнными id без журнала и undo. Нужен отдельный
  путь загрузки (например, построитель документа в ядре). Решить в 2.1 (ADR 0004, «Последствия»).
- **Операторы порядка и прочие операторы `when` из VS Code.** В 1.4 сделаны `&&`, `||`, `!`, `==`, `!=`, `in`.
  `<`, `<=`, `>`, `>=` (например, `selection.count > 1`), `not in` и `=~` добавить, когда понадобятся условию
  из манифеста; смысл существующих условий от этого не меняется (ADR 0005).
- **Включение модулей в журнале.** Журнал воспроизводится тождественно, только если включены те же модули, а
  включение пока не пишется в журнал. В 1.5 оставлено: план 1.15 называет вызовы
  `stresslab.extensions.enable/disable`, а команда ядра для них требует решить, что делает откат транзакции,
  внутри которой включили модуль (модуль остаётся включённым), и кто владеет командами менеджера (команды
  `fem.core` нельзя снять с шины). Сделать в 1.15 поверх `ExtensionManager::enable/disable` (ADR 0006).
- **`std::to_chars(double)` и deployment target macOS.** Журнал форматирует числа через `std::to_chars`, которому
  в libc++ нужен macOS ≥ 13.3. При выборе минимальной версии macOS в 3.11 либо держать ≥ 13.3, либо заменить
  форматирование (например, на {fmt}).
- **Схемы `propertySchemas` и `settings` в отдельных файлах.** В 1.5 схема пишется inline-таблицей TOML, что
  неудобно для больших JSON Schema. Добавить ссылку на файл модуля (`schema = "schemas/job.json"`) с проверкой
  при разборе манифеста (`form::parse`, ADR 0014). Генератору форм 1.13 и настройкам 1.7 inline-схем хватило;
  нужно к первым большим схемам статики (3.1).
- **События активации от команд ядра.** `onCommand:` срабатывает на команды модулей (они идут через прокси
  Extension Manager), но не на `model.*`. Если модулю понадобится ждать команд ядра, нужен сигнал шины «команда
  начинается» (ADR 0006 п. 2).
- **Удаление и обновление модулей.** Менеджер умеет ставить модули из папок, но не удалять их из индекса и не
  заменять версию; нативная библиотека новой версии к тому же подхватится только после перезапуска
  (ADR 0006 п. 12). Сделать в 1.14 вместе с менеджером модулей; подписи пакетов — этап 6.
- **Большие данные через C ABI.** Нативный модуль меняет модель только командами с JSON-аргументами, поэтому
  не может передать сетку или поле результатов. Расширить `FemHostApi` (массивы без копирования), когда первый
  нативный модуль (формат, мешер) этого потребует — этапы 3 и 5.
- **Ключ `job.solver`.** В 1.12 сделаны `job.running` и `job.active` (`fem::job::JobKeys`, ADR 0013 п. 15), а
  условию вроде `job.running && job.solver == 'calculix'` (`docs/architecture.md` §4.1) нужен решатель задания;
  Job Manager решателей не знает. Добавить вместе с адаптером CalculiX (3.5): решатель в `SubmitOptions` или
  ключ, который ставит адаптер.
- **Сериализация `JobSpec`** (детерминированный JSON, round-trip тест по правилу 6). Нужна удалённому исполнителю
  и, возможно, для сохранения заданий в проекте. Появилось в 1.6; сделать вместе с первым удалённым исполнителем.
- **Полный лог задания на диске.** `Job` держит в памяти только хвост (`log_tail_lines`); полный вывод доступен
  лишь подписчикам `subscribe_log`. Писать лог решателя в рабочую папку задания — в адаптере CalculiX (3.5)
  или в Job Manager, если понадобится всем адаптерам.
- **Кодировка вывода программ на Windows.** Вывод передаётся байтами как UTF-8; консольные программы, пишущие в
  кодовой странице OEM (cp866), дадут «кракозябры». Перекодировать в адаптере, знающем свой решатель (3.5),
  при необходимости — опция `JobSpec`. Появилось в 1.6.
- **Мягкая остановка на Windows.** `LocalExecutor` завершает дерево процессов сразу (`TerminateJobObject`), без
  аналога `SIGTERM` с паузой. Если решателю нужно успеть сохранить состояние — `CTRL_BREAK_EVENT` в отдельной
  группе консоли. Решить в 3.5 по поведению ccx.
- **Изменения настроек в журнале и настройки в Python.** Настройки меняются мимо Command Bus (ADR 0008 п. 7),
  поэтому сценарий, который меняет, например, число потоков решателя, не воспроизводится журналом. В 1.8
  настройки (как и локализация, Job Manager и Extension Manager) в Python не выведены — задача их не называла
  (ADR 0009, «Последствия»). Решить в 1.15 вместе с `stresslab.extensions`: `stresslab.settings` и запись
  `stresslab.settings.set(...)` в журнал без undo, или настройки проекта как часть модели.
- **Формат чисел по языку.** Переводы подставляют числа с точкой и без разделителей разрядов
  (`fem::l10n::to_text`), а по-русски пишут `48 312` и `2,5`. Добавить форматирование по языку (например,
  `{count:n}`). С 1.13 формы принимают десятичную запятую, но показывают числа с точкой (ADR 0014 п. 5), как и
  пределы в текстах проблем; решить вместе для форм и переводов.
- **Файлы `.pyi` для обёрток команд.** Обёртки `stresslab.<module>.<command>` строятся из реестра во время
  работы (ADR 0009 п. 7), поэтому IDE не подсказывает их без запущенной программы. Генерировать заглушки
  `.pyi` (и `.pyi` нативного модуля через `nanobind.stubgen`) из реестра включённых модулей — вместе с
  документацией API из реестра на этапе 8 (SDK).
- **Python, поставляемый с программой.** Встроенный интерпретатор берёт stdlib и site-packages у Python
  сборки, путь к нему и к пакету `stresslab` зашит при компиляции (`FEM_PYTHON_HOME`, `FEM_PYTHON_SITE_DIR`).
  В задаче 3.11 искать Python и пакет рядом с исполняемым файлом (и в `.app`/AppImage), зашитые пути оставить
  только для сборки разработчика. Появилось в 1.8.
- **Время жизни объектов Python в документе приложения.** Слушатели и команды Python, подключённые к
  документу приложения, снимаются при `Interpreter::detach` и при выходе из Python. Когда оболочка (1.11)
  начнёт открывать и закрывать документы, она должна вызывать `detach`/`attach` при смене документа, иначе
  Python будет держать закрытый документ. Появилось в 1.8.
- **Недействительный stdin во встроенном Python на Windows.** В CI (Windows, Debug) `subprocess.run` внутри
  `stresslab --python -m pytest` однажды получил недействительный хэндл stdin (`WinError 6` из
  `DuplicateHandle`); повторить локально не удалось, тест обходит это через `stdin=subprocess.DEVNULL`.
  Возможная причина — две CRT в Debug-сборке (`ucrtbased` программы и `ucrtbase` Python) и перехват fd 0
  pytest'ом. В 1.10 скрипт `--headless run-script` запускает `subprocess` с унаследованным stdin
  (`test_a_script_may_start_processes_with_the_inherited_input`) — локально в Debug зелёный, 10 прогонов подряд;
  если CI повторит ошибку, смотреть на перехват fd 0 pytest'ом во встроенном прогоне. Появилось в 1.8.
- **Общий extension host для группы python-модулей.** Сейчас у каждого активного python-модуля свой процесс
  (ADR 0010 п. 1) — изоляция зависимостей и падений ценой памяти на интерпретатор. Если модулей станут десятки,
  добавить группировку в один хост (протокол уже позволяет). Появилось в 1.9.
- **`stresslab` в процессе хоста как прокси протокола.** Код модуля пишется на `stresslab_host`, а быстрые скрипты в
  приложении — на `stresslab` (ADR 0010 п. 8); один API для обоих удобнее авторам. Решить к SDK модулей (этап 8).
- **Зависимости python-модулей.** Установка (`pip install --target <user_site_packages>/<id>/site-packages`) и
  обработка `.pth` в site-packages модуля (ADR 0010 п. 9). Задача 1.14 (менеджер модулей).
- **Таймауты хоста модулей в настройках.** Падение модуля с 1.12 видно во вкладке «Проблемы» и в строке-подсказке
  (ADR 0013 п. 14); таймауты хоста (`call_timeout`, ping) всё ещё зашиты в `HostRuntimeOptions`. Вынести в
  настройки ядра, когда понадобится менять их пользователю. Появилось в 1.9.
- **Код модулей для других точек расширения через протокол.** Сейчас по протоколу идут команды, ключи, события
  модели и задачи; `detect()`/`validate()` решателей и чтение/запись форматов (§4.6 п. 6) добавятся методами
  протокола с задачами 3.3–3.5.
- **Фоновые команды модулей в журнале.** Команда модуля, которая запускает работу в фоне (поток, задача), пишется
  в журнал, а команды, которые эта работа потом выполняет через приложение (`extension.execute`), — отдельными
  строками. Воспроизведение журнала запустит фоновую работу снова и выполнит записанные строки: изменения
  удвоятся. Решить с первым модулем с такой работой (решатели, 3.x): не журналировать команды «сами по себе»
  во время воспроизведения, помечать их в журнале комментарием или требовать от модуля идемпотентности.
  Появилось в 1.10 (видно в ручном прогоне headless с `headless.task_make`).
- **Консоль при запуске окна из Проводника.** `stresslab.exe` — консольная программа (ради `--headless` и
  `--python`), поэтому при запуске окна из Проводника на мгновение появляется консоль, которую окно сразу
  отпускает (ADR 0012 п. 9). В поставке (3.11) — отдельный оконный запускатель (`stresslabw.exe`, как
  `pythonw`) или ярлык на него. Появилось в 1.11.
- **Шрифт Inter в интерфейсе.** Бренд-кит рекомендует Inter (`guidelines.md` §5), в 1.11 оставлен системный
  шрифт: файлов шрифта в репозитории нет. Встроить Inter (OFL, текст лицензии рядом) вместе с поставкой (3.11)
  и проверить кириллицу и хинтинг на Windows. Появилось в 1.11.
- **Малый символ на тёмном заголовке окна.** Задача 1.11 велит рисовать иконку ≤ 32 px из
  `stresslab-symbol-small-color.svg`; это графитовый знак без плитки, и на тёмном заголовке окна (Windows в
  тёмной теме) он почти не виден. В ките нет малой версии `reversed`. Решить с автором кита: малый `reversed`
  или плитка, как у иконок приложения (`icons/windows/png/stresslab-16.png`). Появилось в 1.11.
- **Переводы самого Qt.** Строки стандартных виджетов Qt (контекстное меню поля ввода, кнопки диалогов,
  которые оболочка не подписывает сама) остаются английскими: `qtbase_ru.qm` не подключён. Подключить
  `QTranslator` с переводами Qt по языку локализации, когда появятся такие диалоги (1.13–1.14) или в поставке
  (3.11). Появилось в 1.11.
- **Встроенные активности оболочки.** «Модель», «Модули», «Настройки» (`docs/interface-design.md` §4) появятся в
  1.13–1.14, а `ContributionUi` очищает панель активностей при каждой пересборке (ADR 0013, «Последствия»).
  Держать активности оболочки отдельной группой перед активностями модулей. Появилось в 1.12.
- **Содержимое панелей и вкладок модулей.** Активность и вкладка нижней панели модуля в 1.12 — пустые панели с
  заглушкой: точки расширения для их содержимого (дерево своих объектов, поток лога решателя, график
  сходимости) нет, а рисовать модулю нельзя (правило 4). Нужна декларативная точка (например, вкладка-лог по
  потоку задания) — с монитором решателя в 3.5. Появилось в 1.12.
- **Клавиши в нативном меню macOS.** Пункт меню модуля показывает клавишу через `Qt::WidgetShortcut`, а
  срабатывает она через действие окна, которое проверяет `when` (ADR 0013 п. 10). В нативной строке меню macOS
  это не проверялось (нет macOS локально); проверить на macOS, что клавиша не срабатывает дважды и в обход `when`.
  Появилось в 1.12.
- **Поле выбора объекта в формах.** Ссылки между объектами (сечение → материал) в Model IR — зависимости, а
  не свойства, и формы 1.13 их не показывают (ADR 0014, «Последствия»). Нужно поле выбора объекта (список
  объектов типа, перетаскивание из дерева), пишущее `model.add_dependency`/`remove_dependency`. Сделать с
  типами статики (3.1). Появилось в 1.13.
- **Формы аргументов команд.** С 1.13 команда получает `object` из выделения в дереве, а прочие обязательные
  аргументы по-прежнему делают её недоступной из меню и палитры. Генератор форм уже есть: схема из `ArgSpec`
  и форма в панели свойств с кнопкой «Выполнить». Нужно первой команде модуля с такими аргументами
  (импорт с параметрами, 3.2). Появилось в 1.13.
- **Множественный выбор в дереве.** Выделение в 1.13 одиночное; правка поля сразу у нескольких объектов одного
  типа (одна транзакция) и ключ числа выбранных — когда понадобятся (нагрузки, наборы). Появилось в 1.13.
- **Перетаскивание узлов дерева** («материал на тело», `docs/interface-design.md` §4). Нужна декларативная
  точка: какой тип на какой тип бросается и какой командой. С типами статики (3.1). Появилось в 1.13.
- **Клик по этапу раскрывает его узел.** `docs/interface-design.md` §4: клик по этапу раскрывает узел этапа в
  дереве. Связи «этап → узел» в Model IR нет; решить вместе со статусами этапов (3.9). Появилось в 1.13.
- **Единицы показа: общий выбор и запоминание.** В 1.13 единица выбирается на поле и помнится до выхода
  (ADR 0014 п. 4). Общий выбор на величину («напряжения в МПа») и хранение между сессиями — настройкой
  пользователя, когда попросят. Появилось в 1.13.
- **Режимы «Базовый» и «Эксперт»** (`docs/interface-design.md` §3 п. 3): какие секции «Дополнительно»
  развёрнуты по умолчанию. В 1.13 «Дополнительно» всегда свёрнуто и помнит раскрытие на сессию. Настройка
  ядра и чтение её генератором форм. Появилось в 1.13.
- **Ссылка на справку модуля в подсказке поля** (`docs/interface-design.md` §11). Подсказка 1.13 — описание,
  величина и проблема; точка расширения для справки модуля появится с документацией модулей (этап 8).
  Появилось в 1.13.
- **Массивы чисел в формах.** Векторы (направление силы тяжести, компоненты) — массив из 2–4 чисел с одной
  величиной; в 1.13 массив показывается JSON-текстом только для чтения. Сделать со схемами нагрузок (3.1).
  Появилось в 1.13.
