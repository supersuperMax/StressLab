# StressLab: план разработки для Claude Code

Версия 1.0 от 11.10.2026. Составлен по `architecture.md` (v0.1) и `interface-design.md`, с учётом решений: первый релиз только линейная статика, ядро под MIT, облака в первых версиях нет (но архитектура его допускает).

План рассчитан на то, что код пишет Claude Code, а человек ставит задачи, проверяет PR и принимает этапы. Каждая задача ниже: цель, что сделать, критерий готовности и готовый промпт.

---

## 0. Как пользоваться планом

### Подготовка (делает человек, один раз)

1. Создать репозиторий на GitHub, например `StressLab`, лицензия MIT.
2. Положить в него:
   - `CLAUDE.md` из этой папки — в корень;
   - `docs/architecture.md` и `docs/interface-design.md` — копии проектных документов;
   - `docs/plan.md` — этот файл.
3. Где запускать Claude Code:
   - **Локально (рекомендуется для этапов с GUI).** Qt 6, VTK и позже OCCT собираются через vcpkg долго (час и больше при первой сборке) и требуют десятков гигабайт. На своей машине кэш vcpkg сохраняется между сессиями.
   - **Claude Code в облаке** хорошо подходит для задач, помеченных ниже `[core]`: они собираются пресетом `core-debug` без Qt GUI и VTK. Для облака стоит настроить SessionStart-хук, который ставит компилятор, CMake, Ninja, Python и `calculix-ccx` (пакет Ubuntu). Это можно попросить сделать самого Claude Code в задаче 1.1.
4. Включить в репозитории GitHub Actions; CI появляется в задаче 1.1.

### Порядок работы над одной задачей

1. Новая сессия Claude Code (или `/clear`), одна задача на сессию.
2. Вставить промпт задачи. Для крупных задач Claude Code сначала покажет план (plan mode); проверить его, особенно границы между `core/` и модулями.
3. Claude Code делает ветку `task/<номер>-<кратко>`, пишет тесты и код, открывает PR.
4. Проверить PR по чек-листу из раздела 7, смёржить.
5. Отметить задачу в этом файле (Claude Code делает это сам в конце PR).

### Метки задач

- `[core]` — собирается без GUI, подходит для облачной сессии.
- `[gui]` — нужны Qt/VTK, лучше локально.
- `[решение]` — перед задачей человек должен принять решение; вопрос указан в задаче.

### Общий шаблон промпта

Любой промпт ниже можно дополнить этим заголовком, если сессия начинается «с нуля»:

```
Работаем над StressLab. Прочитай CLAUDE.md и docs/plan.md, раздел задачи <N>.
Соблюдай архитектурные правила из CLAUDE.md. Сначала покажи план, потом реализуй.
В конце: тесты зелёные, PR открыт, задача отмечена в docs/plan.md.
```

## 1. Этап 1 — Каркас (MVP-0)

**Результат этапа:** пустая оболочка, которая ничего не знает про МКЭ, но умеет загружать модули по манифестам, показывать их кнопки по условиям `when`, выполнять команды с undo и журналом на Python, и убирать всё при выключении модуля без перезапуска.
**Приёмка этапа:** демонстрационный модуль добавляет кнопку, команду и вкладку; при выключении модуля они исчезают, при включении возвращаются; то же из Python-консоли и из `stresslab --headless`. CI зелёный на Windows, macOS, Linux.
