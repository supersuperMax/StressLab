# Как написать модуль StressLab

Руководство для авторов модулей на примере встроенного модуля `fem.demo` (`extensions/fem.demo/`). Модуль
ничего не знает про МКЭ: он хранит в модели заметки. Но в нём есть по одному элементу каждого вида, который
видит пользователь: команда, кнопка на контекстной панели с условием `when`, этап на полосе этапов, вкладка
нижней панели, тип узла дерева с формой свойств и настройка. Всё это появляется при включении модуля и
исчезает при выключении, без перезапуска.

Подробности, на которые опирается руководство: система модулей — `docs/architecture.md` §4 (старые имена файлов
переведены таблицей из `CLAUDE.md`), протокол внепроцессных модулей — `docs/extensions/protocol.md`, решения —
ADR 0006 (менеджер модулей), 0010 (extension host), 0013 (оболочка из реестра), 0014 (формы), 0016 (этот модуль
и `stresslab.extensions`).

## 1. Главное правило: модуль встраивается, а не рисует

Модуль не создаёт окон и виджетов. Всё, что он показывает, описано в манифесте `stresslab-extension.toml`, а
оболочка сама строит из манифеста меню, кнопки, этапы, вкладки, формы и настройки. Код модуля загружается
только при первой нужде (по событию активации) и меняет модель только командами. Отсюда три следствия:

- меню и кнопки модуля видны сразу после включения, даже если его код ещё не запускался;
- всё, что модуль сделал с моделью, отменяется (undo) и попадает в журнал сессии `.slpy`;
- выключенный модуль не оставляет в интерфейсе ничего, а его объекты остаются в модели непрозрачными:
  они скрыты, но сохраняются и возвращаются при включении.

## 2. Папка модуля

```
fem.demo/
  stresslab-extension.toml    манифест: кто модуль и что он добавляет
  fem_demo/__init__.py        код: функция activate(extension)
  l10n/en.json, l10n/ru.json  строки интерфейса на двух языках
  icons/note.svg              монохромная иконка
```

Имя папки может быть любым, модуль определяется полем `id`. Python-модуль может положить свои зависимости в
`site-packages/` внутри папки: у каждого модуля свой путь поиска, модули не мешают друг другу (ADR 0010 п. 9).

## 3. Манифест

### 3.1 Заголовок

```toml
[extension]
id = "fem.demo"
name = "%name%"
description = "%description%"
author = "StressLab"
version = "1.0.0"
engine = "^0.1"
kind = "python"
entry = "fem_demo:activate"
activation = ["onCommand:demo.*"]
```

- `id` — уникальный id модуля. Он же `owner` всего, что модуль добавляет, и его объектов в модели.
- `version` — semver, `engine` — с какими версиями платформы модуль работает (диапазон как в npm). Если версия не
  подходит, менеджер модулей показывает модуль несовместимым и не включает его.
- `kind` — `python` (код в отдельном процессе, extension host), `process` (свой исполняемый файл с тем же
  протоколом) или `native` (библиотека на C через `fem/extension_abi.h`). Модуль без `kind` и `entry` — модуль
  без кода: он может добавлять меню на чужие команды, переводы, настройки.
- `entry` — для python: `пакет.модуль:функция`, путь считается от папки модуля.
- `activation` — когда запускать код: `onStartup`, `onCommand:<id или маска>`, `onOpenFile:<маска>`,
  `onSolverRequested:<id>`. Код запускается и при первом вызове команды модуля, даже без события. `fem.demo`
  ждёт своей первой команды, поэтому, пока заметку не добавили, процесс модуля не запущен.
- Модулю может требоваться другой модуль: `requires = ["fem.format.abaqus-inp>=1.0"]`. Менеджер включает
  требуемые модули раньше, а при их выключении выключает и этот модуль.

Тексты вида `%key%` — ключи строк из каталогов модуля (п. 3.8). Так пишутся все строки, которые видит
пользователь: интерфейс с первого дня на русском и английском.

### 3.2 Команда

```toml
[[contributes.commands]]
id = "demo.add_note"
title = "%command.addNote%"
category = "%category%"
icon = "icons/note.svg"
args = [{ name = "text", type = "string", default = "" }]
```

Команда — единственный способ изменить модель. У неё есть id, подпись для меню и палитры, иконка и схема
аргументов. Типы аргументов: `string`, `integer`, `number`, `boolean`, `path`, `object` (объект модели), `list`,
`dict`, `any`. Аргумент с `default` можно не передавать, обязательный без значения делает команду недоступной
из меню. Аргумент `object` оболочка подставляет сама из выделенного узла дерева.

Каждая команда сразу доступна:

- в палитре команд (`Ctrl/Cmd+Shift+P`) — в том числе когда модуль выключен (с кнопкой «Включить»);
- из Python: `stresslab.cmd("demo.add_note", text="…")` или обёртка `stresslab.demo.add_note(text="…")`;
- в журнале: вызов пишется строкой `stresslab.cmd("demo.add_note", text="…")`.

Поле `enablement = "<when>"` делает команду серой, пока условие ложно, и палитра объясняет почему.

Поле `snapshotBefore = true` помечает рискованную операцию: перестроение сетки, импорт поверх модели, запуск
расчёта. Перед такой командой проект сам делает автоматическую версию (если в модели есть изменения и у проекта
есть папка), так что результат всегда привязан к точной версии модели, а откатиться можно на шаг до операции.
В журнал пишется только сама команда: автоматическая версия из неё следует (`docs/adr/0019-history.md`).

### 3.3 Кнопка на контекстной панели и условие `when`

```toml
[[contributes.contextToolbar]]
command = "demo.add_note"
when = "stage == 'demo.review'"
```

Контекстная панель над 3D-видом показывает команды, полезные сейчас. Кнопка `fem.demo` видна только на этапе
модуля «Проверка». Условие `when` — выражение над ключами контекста, как в VS Code: `&&`, `||`, `!`, `==`, `!=`,
`in`, скобки, строки в одинарных кавычках. Ключи, которые есть уже сейчас:

| Ключ | Что значит |
|---|---|
| `stage` | текущий этап: `geometry`, `mesh`, `materials`, `steps`, `solve`, `results` или этап модуля |
| `model.hasMesh` | в модели есть сетка |
| `tree.selectedNodeType`, `tree.selectedNodeOwner` | тип и модуль выделенного узла дерева |
| `history.canUndo`, `history.canRedo` | есть что отменить или повторить |
| `job.running`, `job.active` | идёт задание; сколько заданий в очереди или идёт |

Модуль объявляет свои ключи в `[[contributes.contextKeys]]` (`name`, `type`, `default`) и меняет их из кода
(`extension.context.set(...)`).

Так же устроены меню (`[[contributes.menus]]`, `location = "solve"` или путь подменю `"tools/demo"`, порядок —
`group = "1_run@2"`) и контекстные меню дерева и 3D-вида (`[[contributes.contextMenus]]`, `location = "tree"`
или `"viewport"`).

### 3.4 Этап

```toml
[[contributes.stages]]
id = "demo.review"
title = "%stage.review%"
slot = "after:results"
```

Стандартные этапы оболочки (геометрия, сетка, материалы, шаги и нагрузки, расчёт, результаты) переставлять
нельзя. Модуль добавляет этап только в слот `before:<этап>` или `after:<этап>`. Щелчок по этапу меняет ключ
`stage`, поэтому кнопки «своего» этапа модуль показывает условием `stage == '<id этапа>'`.

### 3.5 Вкладка нижней панели

```toml
[[contributes.bottomPanelTabs]]
id = "demo.notes"
title = "%tab.notes%"
```

Вкладка встаёт рядом с «Журналом», «Консолью Python», «Заданиями» и «Проблемами» и тоже может иметь `when`.
**Ограничение текущей версии:** содержимое вкладки пока не описывается манифестом, и оболочка показывает
заглушку. Декларативная точка для содержимого (поток лога задания, график) появится с монитором решателя
(задача 3.5, `docs/backlog.md`). То же относится к боковой панели модуля (`[[contributes.activityBar]]`).

### 3.6 Тип узла дерева и форма свойств

```toml
[[contributes.treeNodeTypes]]
type = "demo_note"
title = "%node.note%"
icon = "icons/note.svg"

[[contributes.propertySchemas]]
type = "demo_note"
version = 1

[contributes.propertySchemas.schema]
type = "object"
required = ["text"]

[contributes.propertySchemas.schema.properties.text]
type = "string"
title = "%note.text%"
x-order = 1
# ... priority (enum + x-enumTitles), offset (x-quantity = "length", x-advanced = true)
```

Объекты модели с `owner = "fem.demo"` и `type = "demo_note"` показываются в дереве с этой подписью и иконкой.
Когда узел выделен, панель свойств строит форму по JSON Schema. Правка поля — команда `model.set_property`:
она отменяется и пишется в журнал. Расширения схемы для форм (ADR 0014):

| Расширение | Что делает |
|---|---|
| `x-quantity = "length"` | физическая величина: значение хранится в единицах модели, рядом с полем — единица, её можно сменить. Величины: `length`, `area`, `volume`, `mass`, `time`, `force`, `pressure`, `density`, `temperature` и другие из `fem/core/model/quantity.h` |
| `x-advanced = true` | поле в свёрнутой секции «Дополнительно» |
| `x-order = 1` | порядок полей (TOML не сохраняет порядок ключей) |
| `x-enumTitles = [...]` | подписи значений `enum`, можно `%key%` |
| `format = "path"` | путь к файлу с кнопкой выбора |

Обязательное пустое поле подсвечено в форме, а у узла в дереве — значок ✕. Ошибку в схеме (неизвестная
величина, `x-order` не целое) менеджер покажет при установке модуля как ошибку манифеста с указанием
поля.

`version` схемы записывается в объект (`schema_version`). Меняя смысл свойств, повышайте версию.

Большую схему удобнее держать в JSON-файле модуля: `schema = "schemas/material.json"` (путь относительно
папки модуля, через `/`, без `..`). Файл читается и проверяется при разборе манифеста так же, как таблица;
пример — `extensions/fem.model.structural`.

Ссылки между объектами (сечение → материал) — не свойства, а зависимости модели (`model.add_dependency`):
ядро хранит их явно, чтобы не удалить то, от чего зависит объект выключенного модуля. Большие массивы
объекта модуля (поле результатов) — данные `stresslab.ArrayData` (именованные массивы с общим числом строк),
их передаёт команда модуля, а не журнал (ADR 0023).

### 3.7 Настройка

```toml
[contributes.settings]
"demo.defaultText" = { type = "string", default = "TODO", scope = "user", title = "%setting.defaultText%", description = "%setting.defaultText.description%" }
```

Раздел модуля в «Настройках» оболочка строит тем же генератором форм, что и свойства. Кнопка «Настроить» в
карточке модуля открывает этот раздел. Типы: `boolean`, `integer`, `number`, `string`, `path`; ограничения —
`enum`, `minimum`, `maximum`. `scope = "user"` — только в настройках пользователя (пути к программам), по
умолчанию настройку можно задать и в проекте, и проект побеждает. `default` — значение, а не текст интерфейса,
поэтому его не переводят.

### 3.7a Ключевые показатели результатов

```toml
[[contributes.resultIndicators]]
id = "structural.mass"
title = "%indicator.mass%"
quantity = "mass"
```

Показатель — число, которое модуль нашёл в результате расчёта: масса, наибольшее напряжение, запас прочности,
первая частота. Экран «Сравнение» панели «История» показывает показатели двух версий рядом и разницу в
процентах. Значения модуль кладёт вместе с результатом: `stresslab.results.put(..., indicators={"structural.mass":
412.5})` (или `ResultCache::put` в C++), в единицах модели. `quantity` — величина из
`core/include/fem/core/model/quantity.h` (`mass`, `pressure`, `length`...): оболочка подпишет единицу модели и
сравнит значения в СИ, даже если у версий разные единицы. Без `quantity` значение показывается как есть. Id
показателя глобален, как id команды.

### 3.8 Строки на двух языках

```toml
[[contributes.localization]]
language = "en"
path = "l10n/en.json"

[[contributes.localization]]
language = "ru"
path = "l10n/ru.json"
```

```json
{
  "format": "stresslab.l10n",
  "formatVersion": 1,
  "strings": {
    "command.addNote": "Добавить заметку",
    "stage.review": "Проверка"
  }
}
```

Если строки нет в каталоге языка, берётся английская, а если нет и её — сам ключ. Есть подстановки `{name}` и
формы множественного числа по `count` (`"one"`, `"few"`, `"many"`, `"other"`). Тест
`DemoModule.EveryTextOfTheManifestIsTranslatedToEnglishAndRussian` проверяет, что у `fem.demo` все ключи есть
на обоих языках; для своего модуля полезно завести такой же.

## 4. Код модуля

```python
from stresslab_host import Call, Extension

OWNER = "fem.demo"
NOTE = "demo_note"


def activate(extension: Extension) -> None:
    @extension.command("demo.add_note")
    def add_note(call: Call, text: str = "") -> int:
        if not text:
            text = call.setting("demo.defaultText")
        number = len(call.objects(type=NOTE, owner=OWNER)) + 1
        return call.create_object(
            NOTE, OWNER, name=f"#{number}", properties={"text": text, "priority": "normal"}
        )
```

Код python-модуля работает в отдельном процессе, extension host, и видит приложение через пакет
`stresslab_host` (`python/stresslab_host/`, протокол — `docs/extensions/protocol.md`):

- `activate(extension)` вызывается один раз, при активации. В ней модуль регистрирует код команд, объявленных в
  манифесте: `@extension.command("id")` или `extension.register_command(id, handler)`. Команду, которой нет в
  манифесте, зарегистрировать нельзя.
- Обработчик получает `Call` и аргументы по именам. Модель он меняет только через `call`:
  `call.create_object(...)`, `call.execute("model.set_property", ...)`, `call.set_data(...)`. Все изменения одного
  вызова — один шаг undo и одна строка журнала (сама команда модуля, а не то, что она сделала). Если обработчик
  бросил исключение, изменения откатываются, а пользователь видит ошибку.
- Чтение: `call.object(id)`, `call.objects(type=..., owner=...)`, `call.data(id)` (сетки — массивы numpy без
  копирования через shared memory), `call.setting(key)` — значение настройки в силе. Об изменении настройки
  модуль не уведомляется, поэтому читайте её, когда она нужна.
- Долгая работа: верните `call.run_task("Название", work)`. `work(control)` выполняется в потоке, сообщает
  прогресс (`control.set_progress(0.5)`), проверяет отмену (`control.check_cancelled()`). Окно не блокируется.
- Ключи контекста: `extension.context.declare/set/evaluate/watch`; события модели:
  `extension.on_model_changed(callback)`; лог: `extension.log.info(...)`.
- Вне команды (из фонового потока) модель меняют командой целиком: `extension.execute("id", ...)` выполнится,
  когда приложение свободно, отдельным шагом undo.

Модуль может упасть или зависнуть: приложение перезапустит его процесс, команда откатится, модель останется
целой, а пользователь увидит сообщение во вкладке «Проблемы».

## 5. Установка и проверка

**В окне.** «Модули» на панели активностей → «Установить из папки…» → папка модуля. Модуль из папки
помечается «Локальный» и подключается по ссылке на папку: правьте файлы на месте, а изменения манифеста
подхватит вкладка «Обновления». Переключатель в списке включает и выключает модуль, карточка показывает, что
он добавляет в интерфейс.

**Из консоли Python** (вкладка нижней панели) или любого скрипта в приложении:

```python
import stresslab

stresslab.extensions.installed()          # установленные модули
stresslab.extensions.get("fem.demo")      # <stresslab.ExtensionInfo fem.demo 1.0.0 enabled>
note = stresslab.demo.add_note()          # команда модуля
stresslab.extensions.disable("fem.demo")  # этап, кнопка, вкладка, узел, настройка исчезли
stresslab.active_document()[note].is_opaque   # True: заметка в модели, но непрозрачна
stresslab.extensions.enable("fem.demo")   # всё вернулось
```

Включение и выключение записываются в журнал сессии строками `stresslab.extensions.enable("fem.demo")` и
`disable(...)` (не шаг undo) и запрещены внутри команды и транзакции. Ошибки — `stresslab.ExtensionError` с
`code`: `unknown_extension`, `incompatible`, `unresolved_dependency`, `invalid_state`…

**Без окна.** Тот же сценарий — скриптом:

```bash
stresslab --headless --extensions <папка с модулями> --journal session.slpy run-script check.py
stresslab --headless --extensions <папка с модулями> run-script session.slpy   # журнал — тоже скрипт
```

`--extensions` ставит модули из подпапок указанной папки (каждая подпапка — модуль); включаются все
совместимые модули, встроенные тоже, а с `--profile <файл>` — только модули профиля. Код возврата 0 — скрипт прошёл, 1 — исключение (traceback в stderr). Так удобно писать автотесты своего
модуля: `python/tests/test_demo.py` проверяет `fem.demo` именно этим способом.

## 6. Чего пока нет

- Содержимого вкладок и боковых панелей модулей (п. 3.5) — с монитором решателя (3.5).
- Установки зависимостей python-модулей через `pip` — кладите их в `site-packages/` модуля сами.
- Каталога модулей и подписи архивов `.slext` — этап 6.
- `stresslab.settings` в Python и записи изменений настроек в журнал — вместе с настройками проекта (2.1).
- Уведомления модуля об изменении настройки — когда понадобится первому модулю.
