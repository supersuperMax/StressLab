# FEM-APP: устройство интерфейса

Документ описывает, что видит и с чем работает пользователь. Как модули технически подключаются к оболочке (манифесты, API, загрузка), решает тред «Архитектура и технологический стек»; здесь зафиксировано, какие места интерфейса модуль может заполнить и как это должно выглядеть.

Источники: публичная документация и устройство интерфейсов Ansys Workbench / Mechanical / Discovery, Abaqus/CAE, COMSOL Multiphysics, SolidWorks Simulation, Autodesk Fusion, FreeCAD, Salome, PrePoMax, SimScale, а также VS Code и Blender как эталоны модульной оболочки. Оценки «хорошо/плохо» ниже — мой вывод из устройства этих продуктов, а не результаты юзабилити-тестов.

## 1. Коротко

1. **Окно как у VS Code, работа как в Ansys Mechanical.** Слева узкая панель активностей, рядом дерево модели, в центре 3D-вид, справа свойства выбранного объекта, снизу журнал и консоль.
2. **Сквозная полоса этапов** сверху: Геометрия → Сетка → Материалы → Шаги и нагрузки → Расчёт → Результаты. У каждого этапа статус (готово / требует обновления / ошибка), как ячейки в Ansys Workbench.
3. **Контекстная панель инструментов** вместо ленты на сотню кнопок: показывает только команды текущего этапа и выбранного объекта.
4. **Нет модуля — нет кнопки.** Всё, что не является ядром (решатели, форматы, сеточники, оптимизация, динамика), появляется в интерфейсе только из подключённого модуля. Отключил модуль, и его этап, узлы дерева, команды и настройки исчезают сразу, без перезапуска.
5. **Палитра команд (Ctrl/Cmd+Shift+P)** находит любое действие любого модуля по названию. Это главный способ не держать редкие команды на экране.
6. **Каждое действие пишется в журнал как Python-скрипт** (как .rpy в Abaqus). Сессию можно повторить, поправить и превратить в свой плагин.
7. **История версий и варианты конструкции в духе git**: граф истории с ключевыми показателями расчёта на каждой версии, сравнение двух вариантов бок о бок, перенос отдельных правок, откат без потери работы (раздел 12).

## 2. Что делают лидеры

| Продукт | Что берём | Чего избегаем |
|---|---|---|
| **Ansys Workbench** | Схема проекта из «систем»: блоки Geometry → Model → Setup → Solution → Results со статусами ячеек (зелёная галочка, молния «нужно обновить», знак вопроса). Пользователь всегда видит, что устарело после правки. Передача данных между системами перетаскиванием. | Отдельные окна-приложения на каждый этап (DesignModeler/SpaceClaim, Mechanical, CFD-Post) с разной логикой. Схема и работа над моделью у нас в одном окне. |

Фильтр выбора (вершина/ребро/грань/тело) на панели. | Перегруженная лента в новых версиях; глубоко вложенные контекстные меню. |

Прогрессивное раскрытие: секции свёрнуты по умолчанию, «Show more options». Model Wizard на старте. | Лента с десятком вкладок у опытной модели. |

SolidWorks: дерево исследования (Study) с папками Connections / Fixtures / External Loads / Mesh / Results, понятное новичку. | Обязательная облачная привязка (Fusion). |
| **FreeCAD** | **Workbenches**, которые подгружаются как модули, сторонние workbenches через Addon Manager. Это подтверждает, что модель «модуль = свой набор инструментов» работает в открытом ПО. | Каждый workbench добавляет свои панели, и они не исчезают при переключении; несогласованный стиль разных workbenches. Вывод: модулям нужен строгий набор точек встраивания, а не свобода рисовать что угодно. |
| **Salome / PrePoMax** | Salome: модули GEOM, SMESH, ParaVis в одной оболочке. PrePoMax (оболочка над CalculiX): простое дерево Model / Results, импорт .inp, всё на одном экране; близко к нашему сценарию. | Только Windows (PrePoMax), тяжёлые диалоги в Salome. |
| **SimScale** | Веб-интерфейс со строгим деревом настройки сверху вниз, валидация каждого узла, понятные ошибки. | Зависимость от браузера и облака для расчёта. |
| **VS Code** | Панель активностей, палитра команд, **точки вклада** (contribution points) расширений с условиями `when`, менеджер расширений внутри приложения, настройки как формы с поиском и как JSON. | — |
| **Blender** | Рабочие пространства (вкладки сверху) с сохранёнными раскладками; поиск операций по F3; ко всему есть Python. | Непривычная навигация мышью без пресетов. |

Общий вывод: у всех лидеров один и тот же скелет (дерево модели + 3D-вид + панель свойств), различие в том, как подаются команды. Лучшие решения: дерево как источник истины (Mechanical, COMSOL), команды по контексту (Mechanical context toolbar, Abaqus modules), статусы этапов (Workbench), журнал на Python (Abaqus), поиск команд (VS Code, Blender).

## 3. Принципы

1. **Дерево модели — главный объект.** Всё, что влияет на расчёт, видно в дереве. Нет скрытого состояния в диалогах.
2. **Контекст вместо изобилия.** На экране только команды текущего этапа и выбранного объекта. Остальное через палитру команд и контекстное меню.
3. **Прогрессивное раскрытие.** В панели свойств сначала основные поля, «Дополнительно» свёрнуто. Режимы «Базовый» и «Эксперт» меняют только то, что развёрнуто по умолчанию, но не возможности.
4. **Видно, чего не хватает.** Незаданные обязательные поля и этапы подсвечены; кнопка «Рассчитать» неактивна с объяснением, почему (подсказка «Не задан материал у тела Part-1», клик ведёт к нужному узлу).
5. **Нет модальным окнам.** Свойства правятся в боковой панели, расчёт идёт в фоне, приложение не блокируется.
6. **Всё отменяемо и всё записывается.** Undo/redo для любой операции с моделью; журнал действий на Python.
7. **Модуль встраивается, а не рисует.** Модуль заполняет заранее определённые места интерфейса стандартными элементами. Так сохраняется единый стиль и исчезновение модуля не оставляет «дыр».
8. **Одинаково на Windows, macOS и Linux**, с учётом привычек платформы (раздел 10).

## 4. Каркас окна

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ Меню (на macOS в системной строке)            [Поиск команд  Ctrl+Shift+P] │
├─────────────────────────────────────────────────────────────────────────────┤
│ Геометрия ✓ › Сетка ✓ › Материалы ⚠ › Шаги и нагрузки ✓ › Расчёт ○ › Результаты ○ │  ← полоса этапов
├──┬───────────────┬──────────────────────────────────────────┬───────────────┤
│▣ │ ДЕРЕВО МОДЕЛИ │  [контекстная панель: команды этапа]     │ СВОЙСТВА      │
│◇ │ ▾ Модель-1    │                                          │ Сталь 20      │
│⚙ │   ▸ Геометрия │                                          │ E  2.1e11 Па  │
│▶ │   ▸ Сетка     │              3D-вид                      │ ν  0.3        │
│📊│   ▾ Материалы │                                          │ ▸ Дополнительно│
│  │     • Сталь 20│        [фильтр выбора: ● ╱ ▢ ⬛]          │               │
│🧩│   ▸ Шаги      │                              [ViewCube]  │               │
│  │ ▸ Результаты  │                                          │               │
├──┴───────────────┴──────────────────────────────────────────┴───────────────┤
│ Подсказка: Выберите грани для закрепления. [Готово] [Отмена]                │  ← строка-подсказка
├─────────────────────────────────────────────────────────────────────────────┤
│ Журнал │ Консоль Python │ Задания (CalculiX: 43%, осталось ~2 мин) │ Проблемы (1) │  ← нижняя панель
└─────────────────────────────────────────────────────────────────────────────┘
```

Зоны:

- **Панель активностей** (крайняя левая): Модель, Библиотеки (материалы, сечения), Задания, Результаты, Модули 🧩, Настройки ⚙. Модули могут добавлять сюда свои иконки (например, «Оптимизация»), но не больше одной на модуль.
- **Дерево модели**: структура модели и результатов, контекстное меню на узлах, перетаскивание (например, материал на тело), значки статуса узлов.
- **Полоса этапов**: навигация и статус. Клик по этапу раскрывает его узел в дереве и меняет контекстную панель. Этапы появляются от модулей (раздел 6).
- **3D-вид**: геометрия, сетка, граничные условия значками, результаты. Фильтр выбора и ViewCube внутри вида, а не на внешней панели.
- **Контекстная панель**: 5–12 команд текущего контекста, крупные иконки с подписями. Редкие команды в выпадающем «⋯».
- **Свойства**: форма выбранного узла, обязательные пустые поля подсвечены, единицы рядом со значением и переключаются.
- **Строка-подсказка**: пошаговая подсказка для команд, требующих выбора в 3D (идея Abaqus prompt area).
- **Нижняя панель**: журнал действий, консоль Python, очередь заданий с прогрессом и логом решателя, список проблем модели.

Все панели можно скрывать и перетаскивать; раскладки сохраняются как **рабочие пространства** (например, «Препроцессинг», «Постобработка», «Два вида рядом»), как в Blender.

## 5. Рабочий процесс по этапам

Полоса этапов задаёт порядок, но не навязывает его: можно сразу открыть .inp и перейти к расчёту. Каждый этап показывает статус:

- ✓ готово и актуально;
- ⚡ устарело (изменилась геометрия, значит сетка и результаты требуют обновления, как в Workbench);
- ⚠ есть предупреждения;
- ✕ ошибка или не задано обязательное;
- ○ не начато.

Кнопка **«Обновить всё»** пересчитывает устаревшие этапы по цепочке.

Для сравнения вариантов есть **вкладка «Проект»** (аналог схемы Workbench, но не обязательная): карточки моделей и исследований со связями «общая геометрия», «общий материал». Новичок её может не открывать.

## 6. Как модули проявляются в интерфейсе

Это главная «фишка», поэтому правило строгое: модуль может добавить только элементы из списка ниже, и всё добавленное исчезает при отключении.

| Место | Что модуль добавляет | Пример |
|---|---|---|
| Полоса этапов | Новый этап или подэтап | Модуль «Оптимизация» добавляет этап «Оптимизация» после «Результатов» |
| Дерево модели | Типы узлов и их контекстное меню | «Динамика» добавляет узлы «Модальный анализ», «Демпфирование» |
| Контекстная панель | Команды с условием показа (`when`: этап, тип выбранного узла, тип выбора в 3D) | «Сетка Gmsh» показывает «Построить сетку», «Сгустить у кромки» только на этапе «Сетка» |
| Свойства | Формы для своих узлов (декларативно: поля, единицы, допустимые значения) | Параметры решателя CalculiX |
| Палитра команд и меню | Команды | «Экспорт в Ansys .rst» |
| Открыть / Импорт / Экспорт | Форматы файлов | Модуль «Форматы Abaqus» даёт .inp и .odb |
| Список решателей | Решатель с проверкой доступности | CalculiX, Abaqus |
| Панель активностей | Одна иконка с собственной боковой панелью | «Оптимизация»: история итераций |
| Нижняя панель | Вкладка | Лог решателя, графики сходимости |
| 3D-вид | Слои отображения и инструменты постобработки | Отображение форм колебаний |
| Настройки | Раздел настроек | Путь к Abaqus, сервер лицензий |

Модуль **не может**: рисовать собственное окно поверх приложения, менять чужие панели, вешать модальные окна при старте.

### Менеджер модулей

Открывается иконкой 🧩 на панели активностей (как Extensions в VS Code):

- вкладки **Установленные** / **Каталог** / **Обновления**; поиск;
- карточка модуля: описание, версия, автор, что добавляет в интерфейс (список из таблицы выше), зависимости, требуемое внешнее ПО;
- переключатель **Вкл/Выкл**, кнопка **Настроить** (открывает раздел настроек модуля), **Удалить**;
- состояние зависимостей внешнего ПО: «Abaqus: найден, 2025, лицензия доступна» или «Abaqus: не найден. Указать путь»;
- предупреждение при отключении: «В открытой модели 3 узла модуля Динамика. Они будут скрыты, но сохранятся в файле.» Данные не удаляются, при включении всё возвращается;
- самописные модули ставятся из папки или файла, помечены «Локальный».

### Профили

Наборы включённых модулей и раскладок сохраняются как **профили** («Прочность стали», «Тепловой анализ», «Минимальный»). Профиль можно передать коллеге файлом. При открытии модели, которой нужны отключённые модули, появляется полоса сверху: «Модели нужны модули Динамика, Форматы Abaqus. [Включить] [Открыть без них]».

## 7. Палитра команд и поиск

- **Ctrl+Shift+P / Cmd+Shift+P**: все команды всех включённых модулей, с подсказкой горячей клавиши и модуля-источника. Недоступные в текущем контексте показываются серым с причиной.
- **Поиск в дереве** (фильтр по имени и типу узла) и **поиск в настройках**.
- Поиск команды отключённого модуля: «Экспорт в Ansys есть в модуле Форматы Ansys (выключен). [Включить]». Так модульность не прячет возможности от того, кто не знает, где они.

## 8. Сценарий из запроса: .inp → CalculiX или Abaqus → результат для Ansys

1. **Файл → Открыть** (или перетащить файл в окно). Выбран `bracket.inp`. Формат распознан модулем «Форматы Abaqus».
2. Дерево заполняется: детали, сетка, материалы, шаги, нагрузки. Полоса этапов: всё ✓, «Расчёт» ○. В «Проблемах» предупреждения импорта, если какие-то ключевые слова .inp не поддержаны («*CONTACT CONTROLS проигнорировано»).
3. Этап **«Расчёт»**: в свойствах выбор решателя из списка подключённых. Рядом статус: «CalculiX 2.22: встроен», «Abaqus 2025: найден, лицензия: проверить». Если Abaqus не установлен, пункт серый с подсказкой «Не найден. Указать путь».
4. **Проверка совместимости** до запуска: «CalculiX не поддерживает в этой модели: элементы C3D10M (будут заменены на C3D10), *DYNAMIC EXPLICIT». Пользователь видит это до расчёта, а не в логе после.
5. **Рассчитать**. Задание идёт в фоне, во вкладке «Задания» прогресс, лог решателя, графики сходимости. Можно продолжать работу или поставить в очередь ещё один вариант.
6. Этап **«Результаты»** открывается сам по завершении: поля напряжений и перемещений, анимация деформаций, зонды, сечения.
7. **Файл → Экспорт результатов → Ansys** (формат дал модуль «Форматы Ansys»). Диалог экспорта короткий: формат, какие поля, какие шаги; предупреждение, что именно потеряется при конвертации.

Каждый шаг записан в журнал; «Сохранить журнал как скрипт» даёт Python, который повторяет весь сценарий без интерфейса.

## 9. Выбор и навигация в 3D

- **Фильтр выбора**: вершины / рёбра / грани / тела / узлы / элементы, переключение клавишами 1–6. Рамка, лассо, «выбрать смежные по углу» (как в Mechanical).
- **Пресеты мыши**: «Наш», «Как в Ansys», «Как в Abaqus», «Как в SolidWorks», «Как в Blender». Выбирается при первом запуске; это сильно снижает порог входа для переходящих пользователей.
- ViewCube, стандартные виды, «вписать выбранное», разрез плоскостью, скрыть/изолировать.
- Граничные условия и нагрузки показываются значками в 3D; клик по значку выделяет узел в дереве и наоборот.

## 10. Кроссплатформенность в интерфейсе

- Cmd на macOS, Ctrl на Windows и Linux; подписи горячих клавиш подставляются автоматически.
- На macOS главное меню в системной строке, стандартные пункты «О программе», «Настройки» (Cmd+,), полноэкранный режим; жесты трекпада для вращения и масштаба (важно: многие пользователи macOS работают без мыши).
- Корректная работа на HiDPI/Retina, векторные иконки.
- Светлая и тёмная темы, по умолчанию как в системе.
- Диалоги файлов системные.
- Локализация с первого дня: русский и английский, строки модулей тоже переводимы.

## 11. Ошибки, проверки, помощь

- Значок на узле дерева (⚠/✕) и вкладка «Проблемы» с переходом к узлу по клику.
- Ошибки решателя переводятся на человеческий язык там, где это известно («Zero pivot у узла 1532: вероятно, тело не закреплено»), с исходным текстом под спойлером.
- Подсказка при наведении на любое поле: определение, единицы, ссылка на справку модуля.
- Стартовый экран: последние файлы, «Открыть .inp», шаблоны («Статика детали», «Модальный анализ»), короткий интерактивный тур.

## 12. Версии и варианты проекта

У Ansys и Abaqus сохранение одностороннее: файл перезаписывается, варианты живут копиями `wing_v3_final2.cae`, а история изменений теряется. У нас под капотом git-подобное хранилище (устройство решает тред архитектуры), но пользователь работает с ним инженерными словами, без `commit`, `branch` и `merge`.

### Словарь

| Видит пользователь | Аналог в git | Смысл |
|---|---|---|
| **Версия** | коммит | Зафиксированное состояние модели с подписью «Добавил нервюру 7» |
| **Вариант** | ветка | Отдельная линия проектирования: «Крыло: 3 лонжерона», «Крыло: композитная обшивка» |
| **Основной вариант** | main | Вариант, который считается текущим решением |
| **Перенести изменения** | merge / cherry-pick | Взять из одного варианта правки в другой |
| **Вернуться к версии** | checkout / revert | Посмотреть или восстановить прошлое состояние |
| **Метка** | tag | «Отправлено на согласование 12.10», «Прошло сертификацию» |

Для тех, кто знает git, в настройках есть режим с git-терминами, а консоль Python даёт полный доступ.

### Панель «История»

Отдельная иконка на панели активностей (часы с веткой). Внутри граф:

```
 Основной   ●──●──●────────●──● «Перенёс обшивку из варианта B»   ← вы здесь
                 \        /
 Вариант B        ●──●──●  «Композитная обшивка, масса −12%»
                 \
 Вариант C        ●──● «3 лонжерона»  ⚠ результаты устарели
```

- Каждая точка: подпись, автор, время, значки того, что изменилось (геометрия, сетка, материал, нагрузки, есть результаты).
- Рядом с вариантом **ключевые показатели последнего расчёта**: масса, максимальное напряжение, запас прочности, первая частота. Какие показатели выводить, пользователь выбирает сам. Так граф показывает не только «что меняли», но и «к чему это привело».
- Клик по точке открывает версию **только для просмотра** (полоса сверху: «Вы смотрите версию от 10.10. [Вернуться к текущей] [Сделать вариантом отсюда] [Восстановить]»).
- Фильтры: только с результатами, только с метками, по автору.
- Свернуть ветку в одну строку, если граф разросся.

### Ежедневная работа

- **Ctrl/Cmd+S** сохраняет файл как обычно, без лишних вопросов. Автосохранение тоже работает. Эти сохранения не засоряют историю: они копятся как «несохранённые в истории изменения».
- **Зафиксировать версию** (Ctrl/Cmd+Shift+S или кнопка в панели истории): короткое окно в боковой панели с полем подписи и автоматически составленным списком изменений («Изменён материал Обшивка: Д16Т → КМ-1; Пересчитана сетка»). Подпись можно оставить автоматической.
- **Автоматические версии** создаются перед опасными действиями (перестроение сетки, импорт поверх модели, запуск расчёта) и помечаются серым; их можно скрыть.
- Расчёт всегда привязан к версии: в результатах видно, по какой версии они посчитаны, и при изменении модели они помечаются ⚡ устаревшими, а не пропадают.

### Варианты конструкции (сценарий с крылом)

1. На графе правый клик по версии → **«Новый вариант отсюда»**, имя «Композитная обшивка».
2. Полоса этапов и дерево переключаются на этот вариант; заголовок окна и полоса этапов показывают имя текущего варианта цветом, чтобы не перепутать.
3. Переключение между вариантами в один клик в панели истории или выпадающем списке в заголовке. Несохранённые изменения предлагается зафиксировать или отложить.
4. **Сравнение вариантов**: выбрать два варианта или версии → **«Сравнить»**. Открывается экран из трёх частей:
   - таблица различий модели по разделам дерева (геометрия, материалы, нагрузки, сетка) с подсветкой «было / стало»;
   - два 3D-вида рядом с синхронной камерой, изменённые тела подсвечены, плюс режим наложения;
   - таблица и графики ключевых показателей результатов, разница в процентах.
5. **Перенести изменения**: в сравнении отметить галочками нужные правки (например, только смену материала обшивки) и нажать «Перенести в Основной». Если правки конфликтуют (одно поле изменено в обоих вариантах), показывается конфликт в форме свойств: значение A, значение B, выбрать или ввести своё. Геометрию построчно не сливаем: при конфликте по геометрии выбирается одна сторона целиком.
6. Вариант, признанный решением, можно сделать **основным** одной командой; старые варианты архивируются (скрыты, но остаются в истории).

### Откат

- **Отмена (Ctrl+Z)** работает внутри сессии как обычно; история версий её не заменяет.
- **«Восстановить эту версию»** не стирает последующие, а создаёт новую версию поверх (как `git revert`): потерять работу откатом нельзя.
- Можно восстановить **часть**: только материалы, только нагрузки, одно тело. Это делается из экрана сравнения.
- Удаление вариантов и версий только явной командой с подтверждением и с корзиной на 30 дней.

### Тяжёлые данные

Результаты и сетки занимают гигабайты. Пользователь видит у каждой версии значок «результаты сохранены / результаты удалены, можно пересчитать». В настройках задаётся, хранить ли результаты всех версий, только помеченных меткой или только последней в каждом варианте. Очистка: «Освободить место» показывает, сколько займут результаты по вариантам.

### Совместная работа

Проект можно отправить коллеге или положить на общий сервер (git-удалённое хранилище). В панели истории тогда видны версии коллег, кнопки **«Получить изменения»** и **«Отправить»**. Это вторая очередь; в первой версии достаточно локальной истории и экспорта проекта одним файлом.

## 14. Что интерфейсу нужно от механизма расширений

Передаю треду «Архитектура и технологический стек» как требования:

1. Декларативный манифест модуля с точками вклада из раздела 6 и условиями показа (`when`), чтобы оболочка знала, что показать, не загружая код модуля.
2. Включение и отключение без перезапуска, с событием для оболочки «убрать всё, что внёс модуль».
3. Формы свойств описываются схемой (поля, типы, единицы, ограничения), оболочка рисует их сама.
4. Модель данных хранит узлы отключённых модулей нетронутыми.
5. Каждая команда — функция, доступная из Python; оболочка пишет вызовы в журнал.
6. Решатели и форматы сообщают о доступности (найден ли внешний бинарник, есть ли лицензия) и о том, что из модели они не поддерживают.
7. Долгие операции асинхронные, с прогрессом и отменой.
8. Хранилище версий умеет: структурное сравнение двух версий модели по узлам дерева (не по байтам файла), перенос выбранных изменений, привязку результатов к версии и раздельное хранение тяжёлых данных (сетки, результаты), чтобы их можно было удалять и пересчитывать. Модули должны уметь сравнивать и сливать свои узлы.
