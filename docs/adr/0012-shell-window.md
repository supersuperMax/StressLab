# ADR 0012. Окно оболочки: зоны, тема, рабочие пространства, бренд

- Статус: принято
- Дата: 2026-10-13
- Источник: `docs/interface-design.md` §4 и §10, `docs/architecture.md` §8, CLAUDE.md правила 4 и 9,
  задача 1.11 из `docs/plan.md`, `resources/branding/stresslab-kit/guidelines.md`
- Код: `shell/` (`main_window.h`, `workspaces.h`, `theme.h`, `brand.h`, `keys.h`, `strings.h`,
  `about_dialog.h`, каталоги `shell/l10n/`), `app/` (`application.h`, `window.h`, `log_slot.h`,
  `module_pump.h`, `main.cpp`, `stresslab.rc.in`, `Info.plist.in`), `cmake/Branding.cmake`

## Контекст

До 1.11 оболочки не было: `shell/` только проверял, что Qt и Qt Advanced Docking System (ADS) находятся.
Задача — каркас окна по §4: меню, полоса этапов, панель активностей, дерево, 3D-зона, свойства,
строка-подсказка, нижняя панель с вкладками. Всё скрывается и перетаскивается, раскладки сохраняются как
рабочие пространства, тема следует за системой, есть HiDPI и Ctrl/Cmd, подключён бренд. МКЭ-кнопок нет:
содержимое зон придёт из реестра в 1.12. Бэклог ждал от 1.11 ещё несколько решений: общий класс приложения
для окна и headless, язык системы из Qt (macOS), лог нескольких окон, цикл хоста модулей в цикле событий Qt.

## Решения

1. **Зоны.** `fem::shell::MainWindow` (`QMainWindow`). Полоса этапов и панель активностей — `QToolBar`
   сверху и слева (перетаскиваются по ручке, плавающими не бывают). 3D-вид — центральная область ADS: она
   есть всегда и в меню «Вид» не скрывается. Дерево, свойства, строка-подсказка и четыре вкладки нижней
   панели — панели ADS. Строка-подсказка — своя область на всю ширину между основным рядом и нижней панелью,
   без заголовка (`HideSingleWidgetTitleBar`): как строка состояния она только скрывается, а не
   перетаскивается. У каждой зоны постоянный `objectName` (`stageBar`, `activityBar`, `viewport`,
   `modelTree`, `properties`, `promptLine`, `journal`, `pythonConsole`, `jobs`, `problems`): сохранённые
   раскладки ссылаются на зоны по нему, поэтому имена не меняются.

2. **Меню только уровня оболочки.** «Файл» → «Выход» (`QuitRole`, `Mod+Q`); «Вид» → переключатели зон,
   «Рабочие пространства», «Полноэкранный режим»; «Справка» → «О программе» (`AboutRole`). На macOS меню
   нативное (системная строка), а «О программе» и «Выход» Qt переносит в меню приложения. Полоса этапов и
   панель активностей пусты; тест проверяет, что в меню нет других пунктов (правило 4).

3. **Рабочие пространства.** `WorkspaceStore`: именованные раскладки и раскладка с геометрией окна на момент
   закрытия («сессия»), файл `workspaces.json` в папке настроек пользователя (`fem::user_folders().config`).
   Раскладка = состояние ADS (XML без сжатия) + `QMainWindow::saveState` (панели инструментов, base64).
   Формат — детерминированный JSON (`QJsonObject` сортирует ключи, `\n`), сохранить → загрузить → сохранить
   даёт те же байты; запись через `QSaveFile`. Битый файл не мешает запуску: предупреждение в лог и
   пустое хранилище. Окно открывается с раскладкой сессии; «Сбросить раскладку» возвращает раскладку, с
   которой окно построено. Изменения раскладки после открытия пространства в него сами не пишутся: их
   сохраняет «Сохранить рабочее пространство как…» (то же имя заменяет пространство).

4. **Тема: Fusion на всех ОС.** Палитры из цветов бренда: светлая — окна «бумага» #F4F5F7, поля белые, текст
   графит #1B1F24; тёмная — окна графит, текст «бумага». Акцент (`QPalette::Accent`), выделение и ссылки —
   коралловый #FF5A36; текст на выделении графитовый (контраст ≈ 5,3 : 1, белый дал бы ≈ 3 : 1). Тест
   проверяет контраст текста на всех фонах (WCAG AA). Тема следует за `QStyleHints::colorScheme` и меняется
   на лету; неизвестная схема — светлая. Нативные стили (Windows 11, macOS) игнорируют часть палитры, а
   единый вид окна на трёх ОС важнее (выбор подтверждён в обсуждении плана). Таблица стилей ADS рисует
   разделители и подписи неактивных вкладок цветом `palette(dark)` (тяжёлые линии в светлой теме,
   нечитаемые вкладки в тёмной); окно правит эти правила в её тексте после создания панелей: вкладки —
   `placeholder-text`, линии — `mid` (дописанные после правила не побеждают, а правка до создания панелей до
   них не доходит). Тест проверяет цвета на пикселях.

5. **HiDPI и иконки.** Масштабирование Qt 6 по умолчанию. Картинки бренда — SVG, рисуются `QSvgRenderer`
   под плотность экрана (`brand::render_svg`). Иконка окна (`brand::application_icon`) собирается из
   растров 16–256 px: до 32 px включительно — `stresslab-symbol-small-color.svg`, крупнее — иконка
   приложения кита (`FEM_BRANDING_ICON_SVG`, графитовая плитка). Порог считается в пикселях устройства:
   16 pt при 2× — это 32 px, ещё малый символ.

6. **Бренд из кита как есть.** Файлы попадают в ресурсы Qt по путям `cmake/Branding.cmake` (новая переменная
   `FEM_BRANDING_ICON_SVG`); тест сверяет байты ресурсов с файлами кита. Windows — `.ico` в ресурсе exe
   (`stresslab.rc` из `stresslab.rc.in`). macOS — в сборке с окном `stresslab` становится `.app`:
   `StressLab.icns` в `Contents/Resources`, `CFBundleIconFile` и `NSHighResolutionCapable` в `Info.plist`.
   Linux — правила `install` кладут исполняемый файл, дерево hicolor и `stresslab.desktop`, окно называет
   себя `setDesktopFileName("stresslab")`. «О программе» — горизонтальный логотип шириной 240 px
   (минимум кита 96 px): `color` на светлой палитре, `reversed` на тёмной, переключается при смене темы.

7. **Ctrl/Cmd.** `key_sequence("Mod+Shift+P")` читает клавиши в формате манифестов (`keybindings`, ADR 0006):
   `Mod` — это `Qt::CTRL`, то есть Ctrl на Windows и Linux и Cmd на macOS. Подписи — `NativeText` Qt
   («Ctrl+Shift+P» и «⇧⌘P»). Горячие клавиши оболочки задаются так же.

8. **Строки.** Каталоги `shell/l10n/{en,ru}.json` в формате каталогов ядра встроены в ресурсы и добавляются
   в `Localization` под владельцем `fem.shell`; окно переводится заново по `on_language_changed`. Тест
   сверяет ключи и подстановки языков, как у каталогов ядра. Кнопки диалогов Qt подписываются из своих
   каталогов: переводы самого Qt не подключаются.

9. **Один исполняемый файл.** `stresslab` без аргументов открывает окно (в сборке без GUI печатает справку,
   как раньше), `--headless` и `--python` не меняются. На Windows программа остаётся консольной (иначе
   headless и `--python` теряют stdout); окно, запущенное из Проводника, отпускает созданную для него
   консоль (`FreeConsole`, если в консоли только этот процесс). Короткое мелькание консоли — до поставки
   (3.11, в бэклоге). Qt на Windows находит плагины по `qt.conf` рядом с исполняемым файлом
   (`fem_write_qt_conf`): копии DLL рядом с ним (`fem_copy_runtime_dlls`) иначе ищут плагины не там.

10. **Общий класс приложения.** `fem::app::Application` — документ, шина, ключи, настройки пользователя,
    локализация, Extension Manager с `HostRuntime` и связки; headless и окно собираются из него одинаково
    (бэклог 1.10, ADR 0011 «Последствия»). `ModulePump` стал общим: ему передают «выполнить скоро» —
    `Interpreter::call_soon` в headless, очередь событий Qt (`QMetaObject::invokeMethod`, `QueuedConnection`)
    в окне; `poll()` по-прежнему только вне команд (`CommandBus::is_idle`).

11. **Язык системы.** Окно передаёт первый язык `QLocale::system().uiLanguages()` в `bind_language`
    (новый параметр); пустая настройка `general.language` означает этот язык (бэклог 1.7: на macOS у
    приложения из Finder нет `LANG`).

12. **Лог нескольких окон.** Каждое окно пишет свой файл: первое — `stresslab.log`, следующие —
    `stresslab-2.log`… (до 8), слот держит `QLockFile` рядом с файлом; блокировку умершего процесса Qt
    снимает сам. Ротации разных окон не пересекаются (бэклог 1.7). Если все слоты заняты, окно пишет без
    файла.

13. **Тесты** — GoogleTest с одним `QApplication` на платформе Qt `offscreen` (одинаково на трёх ОС и в CI).
    С переменной `STRESSLAB_SCREENSHOT_DIR` тест рисует окно (`QWidget::grab`) в светлой и тёмной теме в PNG;
    CI `full` запускает его отдельным шагом на платформе ОС (`windows`, `cocoa`; на Linux — `offscreen`, у
    которой шрифты есть через fontconfig, а на Windows их нет) и сохраняет артефактом `screenshots-<ОС>`.

## Рассмотренные альтернативы

- **Нативные стили ОС.** Привычнее на каждой ОС, но палитру бренда macOS почти не применяет, а Windows 11 —
  частично; окно выглядело бы по-разному. Отклонено (п. 4).
- **Перспективы ADS** (`addPerspective`/`savePerspectives` в `QSettings`). Хранят только панели ADS, без
  панелей инструментов и геометрии, а формат `QSettings` (реестр Windows, plist) не детерминирован и не
  переносится файлом. Отклонено в пользу своего JSON (п. 3).
- **Строка-подсказка как `QStatusBar` или нижняя панель инструментов.** Обе оказываются под нижней панелью,
  а §4 ставит подсказку над ней. Отклонено (п. 1).
- **Отдельный исполняемый файл для окна** (`stresslabw`, как `pythonw`). Убирает консоль на Windows, но
  `stresslab --headless` из CLAUDE.md и тесты завязаны на один файл. Отложено до поставки (3.11).
- **Один экземпляр окна** (второй запуск передаёт файлы первому). Для расчётов удобно держать несколько
  моделей в разных окнах; нужен будет вместе с открытием файлов из ОС (3.10–3.11).
- **Шрифт Inter.** Рекомендован китом, но файлов шрифта в репозитории нет; встраивание (OFL) — вместе с
  поставкой. Пока системный шрифт интерфейса (бэклог).

## Последствия

- 1.12 наполняет зоны из реестра: этапы — в `stageBar`, активности — в `activityBar`, вкладки модулей — в
  область нижней панели, команды — в меню; `key_sequence` читает `keybindings`. Пересборка при вкл/выкл
  модуля не должна трогать раскладку: раскладки ссылаются на зоны по `objectName`, а вкладки модулей
  получат id модуля в имени.
- Профили (1.14) могут хранить раскладку тем же `Layout`.
- Изменение имён зон или `layout_version` в `main_window.cpp` делает старые раскладки нечитаемыми: окно тогда
  открывается с раскладкой по умолчанию.
- На macOS исполняемый файл сборки с GUI лежит в `stresslab.app/Contents/MacOS/stresslab`; тесты берут его
  через `$<TARGET_FILE:stresslab>`.
- `crash_message` упавшего модуля окно пока только пишет в лог; показ в интерфейсе — с уведомлениями (1.12).
