# ADR 0014. Дерево модели, генератор форм свойств и настроек, единицы величин

- Статус: принято
- Дата: 2026-10-14
- Источник: `docs/interface-design.md` §3–4, §11, §14 п. 3; `docs/architecture.md` §3 («Единицы»), §4.2
  (`treeNodeTypes`, `propertySchemas`, `settings`), §4.6 пп. 3–4; задача 1.13 из `docs/plan.md`; пункт бэклога
  «Команда „изменить одно свойство“»; следствие ADR 0013 «контекстное меню `tree`, ключи `tree.*`»
- Код: `core/include/fem/core/form/` (`form.h`, `status.h`), `core/include/fem/core/model/quantity.h`,
  `core/include/fem/core/command/model_commands.h` (`model.set_property`), `shell/` (`model_tree.h`,
  `form_widget.h`, `property_panel.h`, `settings_panel.h`, `commands.h`, `icons.h`, `workbench.h`,
  `main_window.h`), `app/src/window.cpp`

## Контекст

После 1.12 зоны «Дерево модели» и «Свойства» — пустые заглушки. Модули уже объявляют `treeNodeTypes` и
`propertySchemas` (ADR 0006), но схема хранилась как произвольный JSON без правил: архитектура говорит лишь
«JSON Schema + расширения для единиц» и «один генератор форм для свойств и настроек». Модель хранит систему
единиц (`UnitSystem`), а значения свойств — числа без единиц. Менять свойства можно было только целиком
(`model.set_properties`), и правка одного поля попадала бы в журнал всем словарём.

## Решения

1. **Разбор схемы и проверка значений — в ядре** (`fem::form`, без Qt). `form::parse` читает схему один раз в
   `FormSpec` — поля по порядку, с типом, единицей, ограничениями и допустимыми значениями; `form::check`
   проверяет значения по нему. Так форма, значок узла дерева и (позже) headless и Python одинаково решают, что
   не так, а тесты по фикстурам идут в `core-debug` на трёх ОС. Оболочка только рисует.

2. **Схема — JSON Schema с расширениями StressLab.** Стандартные ключи: `type`, `title`, `description`,
   `default`, `enum`, `minimum`, `maximum`, `exclusiveMinimum`/`exclusiveMaximum` (число по draft 6+ и флаг по
   draft 4), `required`, `properties`, `readOnly`, `additionalProperties`. Расширения:

   | Ключ | Значение |
   |---|---|
   | `x-quantity = "pressure"` | физическая величина (п. 3): значение в единицах модели, форма показывает единицу и даёт её сменить |
   | `x-advanced = true` | поле в свёрнутой секции «Дополнительно» своей группы |
   | `x-order = 10` | порядок полей: TOML и `nlohmann::json` сортируют ключи, порядок манифеста теряется. Сначала поля с `x-order` по нему, затем остальные по ключу |
   | `x-enumTitles = [...]` | подписи значений `enum` (можно `%key%`) |
   | `format = "path"` | текстовое поле с путём к файлу и кнопкой системного диалога |

   Вложенный `type = "object"` с `properties` — группа полей (рамка с заголовком). Что форма показать не умеет
   (`oneOf`, `$ref`, массивы, `type` списком, объект без `properties`) — поле «только чтение» с JSON-текстом, не
   ошибка. Неверные значения расширений и стандартных ключей (неизвестная величина, `x-order` не целое,
   `x-enumTitles` другой длины, корень не объектная схема) — ошибка разбора манифеста с указанием свойства;
   форма строится без ошибочного.

3. **Каталог величин** (`fem/core/model/quantity.h`): length, area, volume, mass, time, temperature
   (абсолютная, со сдвигом), temperatureDifference, force, pressure (давление и напряжение), density, energy,
   moment, velocity, acceleration, frequency, angle, thermalExpansion. У каждой — размерность и единицы показа с
   множителем в СИ (и сдвигом для °C/°F), СИ первой. Значение хранится в единицах модели; перевод идёт через
   СИ (`to_si`/`from_si` по `UnitSystem`). Единица модели — единица каталога с тем же множителем и сдвигом
   (`model_unit`: МПа для давления в мм-т-с, psi в in-slinch-s); если такой нет, подпись собирается из базовых
   единиц системы (`compose_symbol`: «kg·in⁻¹·s⁻²»). Подписи единиц и величин переводятся строками ядра
   `unit.<id>`, `quantity.<id>` («МПа»/«MPa»).

4. **Единица показа выбирается на поле**, список рядом со значением; смена меняет только то, что показано,
   значение модели не трогается. Выбор запоминается на сессию по «контексту» формы (владелец и тип объекта) и
   полю. Целые числа с величиной показывают только единицу модели: другая единица дала бы дробь.

5. **Генератор форм** (`FormWidget`) один для свойств и настроек; источник значений — интерфейс `FormSource`
   (значение поля, запись, владелец текстов, система единиц, пометка под полем). Флажок и список пишут сразу,
   текстовые поля — по окончании правки и только если текст изменился. Пустое поле убирает значение. Ввод,
   который не число или выходит за ограничения, не пишется: поле остаётся с набранным текстом, подсвечено, с
   причиной в подсказке. Обязательное пустое поле и значение, не подходящее схеме, подсвечены (фон поля
   смешан с коралловым акцентом), подпись обязательного — со звёздочкой. Десятичная запятая читается как точка.
   Числа показываются с 12 значащими цифрами. Подсказка поля: описание, величина и единица модели, проблема.

6. **`model.set_property`** — новая команда ядра: `object`, `key`, `value`. `key` — имя свойства или путь во
   вложенный объект в виде JSON Pointer без ведущего `/` (`solver/tolerance`; `~1` — `/`, `~0` — `~`),
   недостающие объекты на пути создаются; `value=None` удаляет свойство. Undo — через ту же запись, что у
   `set_properties`. Журнал: `stresslab.cmd("model.set_property", object=5, key="E", value=210000.0)`.
   Python-обёртка `stresslab.model.set_property` строится из реестра сама. Панель свойств пишет только так:
   правка поля — команда Command Bus, отмена из меню «Правка» возвращает и форму.

7. **Статус узла** (`form::object_problems`): ✕ — обязательное свойство пусто, значение не подходит схеме,
   зависимость на удалённый объект; ⚠ — объект записан по другой версии схемы, чем у `propertySchemas`,
   или в закрытом объекте (`additionalProperties = false`) есть свойство, которого схема не описывает. Узел
   показывает худший статус своего поддерева (свёрнутая папка тоже видна); подсказка перечисляет проблемы
   узла и говорит, что внутри есть ещё. Значки — фиксированные цвета (янтарный ⚠, коралловый ✕), на выделенной
   строке — цветом текста выделения. Статусы этапов и переход из «Проблем» — задача 3.9.

8. **Дерево** — `QAbstractItemModel` над `Document`. Объекты выключенных модулей (непрозрачные) скрыты вместе с
   поддеревом и возвращаются при включении. Заголовок — имя объекта, иначе заголовок типа из `treeNodeTypes`;
   типы ядра (`mesh`, наборы, поверхности) подписаны строками оболочки. Иконка — из `treeNodeTypes` или
   иконка модуля по умолчанию, одинаковая у раскрытого и свёрнутого узла. Изменение свойств и имён обновляет
   строки; создание и удаление объектов, вкл/выкл модуля и смена языка перестраивают дерево с сохранением
   раскрытых узлов и выделения. Фильтр — строка поиска над деревом (без учёта регистра, по имени и заголовку
   типа, найденный узел показывается с родителями, найденная папка — с содержимым).

9. **Выделение и ключи.** Выделение одиночное. Оболочка объявляет ключи `tree.selectedNodeType` и
   `tree.selectedNodeOwner` (текст, пусто — ничего не выбрано). Контекстное меню узла — пункты `contextMenus`
   с `location = "tree"` по их `when`, затем пункты оболочки «Переименовать» (F2, правка имени в дереве →
   `model.rename`) и «Удалить» (Del → `model.remove`). Удаление, которое потеряло бы объекты выключенного
   модуля, не запускается: причина — в строке-подсказке по `removal_blockers`. Команда с обязательным
   аргументом `object` типа `object` получает выбранный узел, откуда бы её ни вызвали (меню, палитра,
   контекстная панель); без выделения она недоступна с причиной «Выберите объект в дереве модели». После смены
   выделения доступность элементов модулей пересчитывается.

10. **Настройки** — та же форма: `form::settings_form` превращает записи `settings` в поля (раздел на модуль,
    ядро первым под заголовком «Общие»). Панель «Настройки» — вкладка рядом со свойствами, закрыта, пока её не
    откроют пунктом «Файл → Настройки…» (`Mod+,`, на macOS — `PreferencesRole` в меню приложения). Правка идёт
    в уровень пользователя и сразу сохраняется (`Workbench::save_settings`, файл `settings.json` пользователя);
    пустое поле возвращает значение по умолчанию; значение проекта, если оно задано, подписано под полем.
    Настройки по-прежнему мимо Command Bus (ADR 0008 п. 7). В манифесте у настройки появился необязательный
    `title`; у настроек ядра — строки `setting.<ключ>.title`.

11. **`Workbench`** получил `settings::Settings&` и `save_settings`. Приложение (`app/src/window.cpp`) пишет
    настройки пользователя в файл, из которого их читает.

## Рассмотренные альтернативы

- **Разбор схемы в оболочке.** Меньше кода в ядре, но статусы узлов, тесты по фикстурам без Qt и будущие
  проверки из Python пришлось бы делать отдельно. Отклонено (п. 1).
- **Полный JSON Schema валидатор** (например, `json-schema-validator`). Новая зависимость, а форме нужны не
  проверки вообще, а поля и их ограничения; неподдерживаемое показывается как есть. Отклонено.
- **Порядок полей массивом на уровне объекта** (`x-order = ["E", "nu"]`). Неудобно сливать при росте схемы и
  не работает для групп без правки родителя. Выбран порядок на поле (п. 2), как `order` настроек VS Code.
- **Единица хранения в схеме** (`unit = "MPa"`) вместо величины. Ломает принцип «модель в одной системе
  единиц» (ADR 0002): значения разных объектов оказались бы в разных единицах. Отклонено (п. 3).
- **Общий выбор единиц показа на величину** (давление везде в МПа). Удобно, но требует настройки и места в
  интерфейсе; пока выбор на поле на сессию (п. 4), общий — в бэклоге.
- **Запись поля через `model.set_properties`.** Журнал содержал бы весь словарь на каждую правку (пункт
  бэклога). Отклонено (п. 6).
- **Статус во втором значке той же ячейки через свой делегат.** Второй столбец со значком проще, работает с
  фильтром и подсказками без своего рисования. Выбран столбец.

## Последствия

- `docs/architecture.md` §4.2 говорит о «расширениях для единиц» без подробностей — они описаны здесь (п. 2–3);
  `title` у настроек и ключи `tree.*` — тоже здесь.
- Модули типов статики (3.1) пишут `propertySchemas` с `x-quantity`; новые величины добавляются в каталог
  ядра вместе с подписями en/ru (тест проверяет, что подписи есть).
- Ссылки на объекты в формах (сечение → материал) — зависимости модели, а не свойства; поле выбора объекта —
  в бэклоге до 3.1.
- Формы аргументов команд (кроме `object` из выделения), множественный выбор, перетаскивание узлов, режимы
  «Базовый/Эксперт», общий выбор единиц, связь «клик по этапу → узел дерева» — в бэклоге.
- Иконка «Настройки» на панели активностей — с «Модулями» в 1.14 (ADR 0013, «Последствия»).
