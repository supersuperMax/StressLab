# ADR 0005. Context keys и выражения `when`

- Статус: принято
- Дата: 2026-10-12
- Источник: `docs/architecture.md` §4.2–4.3, задача 1.4 из `docs/plan.md`
- Код: `core/include/fem/core/context/` (`fem::context`)

## Контекст

Оболочка не содержит МКЭ-кнопок: меню, контекстная панель и вкладки появляются из манифестов модулей с условием
`when` (§4.2), а условия вычисляются заново при изменении context keys (§4.3). Нужно решить, какой язык условий
принять, какие значения могут иметь ключи, кто и как их объявляет, как сообщать об ошибках в условиях из чужого
манифеста и как не пересчитывать сотни условий на каждое изменение выделения. Ключи модуля должны исчезать
вместе с ним (CLAUDE.md, правило 5).

## Решения

1. **Язык — `when` из VS Code в объёме задачи:** `&&`, `||`, `!`, `==`, `!=`, `in`, скобки, `true`/`false`,
   текст в одинарных кавычках, числа:

   ```
   expression := or
   or         := and ('||' and)*
   and        := unary ('&&' unary)*
   unary      := '!' negated | primary
   negated    := '!' negated | 'true' | 'false' | '(' expression ')' | key
   primary    := 'true' | 'false' | '(' expression ')' | key [ ('==' | '!=') literal | 'in' key ]
   literal    := text | number | 'true' | 'false'
   ```

   `&&` связывает сильнее `||`. Слева от сравнения всегда ключ, справа от `==`/`!=` — литерал, справа от `in` —
   ключ. Текст без экранирования (как в VS Code), поэтому не содержит `'`. Число —
   `-?цифры(.цифры)?([eE][+-]?цифры)?`, конечное. Ключ — имена из букв, цифр, `_` и `-` через одиночные точки,
   первым идёт буква или `_` (`model.hasMesh`, `solver.my-solver.available`); `true`, `false`, `in`
   зарезервированы; регистр значим. Пробелы — пробел, табуляция, переводы строк.
2. **Два отличия от VS Code, оба — ошибки вместо тихого смысла.** Слово без кавычек справа от `==` в VS Code —
   текст (наследие старого парсера); у нас это ошибка с подсказкой взять слово в кавычки, иначе `stage == solve`
   неотличимо от сравнения с ключом. `!` применяется к ключу, `true`/`false`, скобкам или другому `!`, но не к
   сравнению: `!a == 'x'` — ошибка с подсказкой `!(a == ...)`, а не `(!a) == 'x'`.
3. **Значения ключей** — `ContextValue`: нет значения, boolean, number (double; целые приводятся), UTF-8 текст,
   список текстов. Ключ сам по себе ложен для «нет значения», `false`, `0`, `''` и пустого списка. `==` истинно
   только для значений одного вида (`2 == 2.0`, но не `'2' == 2` и не `true == 1`); «нет значения» не равно ничему,
   поэтому `!=` для необъявленного ключа истинно. `a in b` — `b` список и содержит текст `a`.
4. **Ошибки синтаксиса — исключение `WhenSyntaxError`** (`ContextError` с кодом `syntax`): колонка с 1 в символах
   (как у журнала, ADR 0004 п. 10), смещение в байтах и причина; `what()` — `column N: причина`. Сообщается первая
   ошибка слева. Причины написаны для автора манифеста и называют ожидаемое и найденное: `expected a value after
   '==' (text in single quotes, a number, true or false), found key 'solve'; write 'solve' to compare with text`;
   для `&`, `|`, `=` и `"` — подсказка правильного символа. Это сообщения для разработчиков, как у
   `CommandError`; пользовательский текст — через локализацию по коду. Вложенность скобок и `!` ограничена
   100 уровнями, чтобы выражение из сломанного манифеста не исчерпало стек.
5. **Ключи объявляются.** `ContextKeys::declare(KeySpec{name, owner, type, initial})`: владелец, вид значений и
   начальное значение. Писать можно только в объявленный ключ значением его вида (иначе `unknown_key` или
   `invalid_value`), поэтому опечатка в имени ключа или вид значения ловятся на записи. Читать выражениям можно и
   необъявленные ключи: кнопка модуля может зависеть от ключа другого модуля, который ещё не включён. Повторное
   объявление с той же спецификацией ничего не меняет (так модуль переживает перезагрузку манифеста), с другой —
   `duplicate_key`. `remove_owner` убирает ключи модуля вместе со значениями; ключи ядра (`fem.core`) не
   убираются.
6. **Инкрементальный пересчёт.** `watch(expression, listener)` хранит выражение и индекс «ключ → подписки».
   Изменение значения ключа (`set`, объявление с начальным значением, `remove_owner`) пересчитывает только
   подписки, читающие изменённые ключи, каждую один раз за изменение; запись того же значения не пересчитывает
   ничего. Слушатель вызывается, только когда значение выражения отличается от последнего переданного ему.
   Сначала пересчитываются все затронутые подписки, затем вызываются слушатели; слушатель может менять ключи и
   подписки, его изменения пересчитываются сразу, а у каждой подписки хранятся последнее вычисленное и последнее
   переданное значения — поэтому слушатель не получает устаревшее значение и не получает одно значение дважды.
   Счётчик `watch_evaluations()` делает пересчёт наблюдаемым для тестов и диагностики.
7. **Пакетная запись** `set({{key, value}, ...})` проверяет все значения до записи и пересчитывает подписки один
   раз: оболочка меняет `selection.type` и `selection.count` вместе, и условие на оба ключа не мигает.
8. **Ключи ядра** (`CoreKeys`, owner `fem.core`): `model.hasMesh` (в документе есть объект ядра типа `mesh`),
   `history.canUndo`, `history.canRedo`. Обновляются по событию «модель изменилась» Command Bus: стеки undo/redo
   меняются только вместе с ним (ADR 0004 п. 8), поэтому внутри транзакции ключи не меняются. Множество сеток
   ведётся по созданным и удалённым объектам события, без обхода документа. Остальные ключи объявляют их
   владельцы: `stage`, `selection.*`, `tree.selectedNodeType` — оболочка (1.12), `job.*` — Job Manager (1.6),
   `solver.<id>.available` — адаптеры решателей (3.x).
9. **Нормальная форма** `WhenExpression::to_string()`: пробел вокруг бинарных операторов, скобки только где
   меняют смысл, литералы как написаны. Разбор нормальной формы даёт её же; на этом стоят тесты грамматики, а
   оболочка может показывать условие в подсказках и журналах.

## Рассмотренные альтернативы

- **Пересчитывать все условия на любое изменение ключа** — проще, но меню, контекстная панель и палитра дают
  сотни условий, а выделение в 3D-виде меняется на каждый клик; задача прямо требует пересчёта только зависимых.
- **`fem::command::Value` как значение ключа** — тип уже есть, но в нём отдельно целые и числа, пути и словари,
  которых язык `when` не сравнивает; свой тип короче и задаёт семантику `==` и истинности в одном месте.
- **Слова без кавычек как текст, как в VS Code** — совместимо с привычками авторов расширений VS Code, но
  неоднозначно с ключами и прячет опечатки; явная ошибка с подсказкой дешевле.
- **Ошибка разбора как возвращаемое значение** — `std::expected` появится только в C++23, а ядро сообщает об
  ошибках исключениями (`ModelError`, `CommandError`); загрузчик манифестов (1.5) ловит исключение и добавляет
  файл и строку.
- **Ключи без объявления, как `setContext` в VS Code** — меньше церемоний, но запись в ключ с опечаткой молча
  создаёт новый ключ, и ключи выключенного модуля нельзя убрать по владельцу.

## Последствия

- В таблице contribution points (`docs/architecture.md` §4.2) нет точки для объявления ключей, хотя §4.3 говорит,
  что модули их объявляют. Пока модуль объявляет ключи кодом (`ContextKeys::declare`); нужна ли точка
  `contextKeys` в манифесте, решит задача 1.5.
- Оболочка (1.12) строит видимость и доступность через `watch`; палитре команд понадобится объяснение «почему
  недоступно» (`docs/interface-design.md`, палитра команд) — разбор, какая часть условия ложна.
- Python API (1.8) даст доступ к ключам; `ContextValue` переводится в типы Python без потерь (кроме целых больше
  2^53).
- Операторы порядка (`<`, `<=`, `>`, `>=`), `not in` и `=~` из VS Code не реализованы; грамматика допускает их
  добавление без изменения смысла существующих условий.
