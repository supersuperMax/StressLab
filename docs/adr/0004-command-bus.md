# ADR 0004. Command Bus, undo/redo и журнал сессии

- Статус: принято
- Дата: 2026-10-12
- Источник: `docs/architecture.md` §2 и §4.6 п. 5, задача 1.3 из `docs/plan.md`
- Код: `core/include/fem/core/command/` (`fem::command`), `core/include/fem/core/model/document_editor.h`,
  `core/include/fem/core/model/change_set.h`

## Контекст

Правило 3 из CLAUDE.md: все изменения модели идут через Command Bus, каждая команда имеет id, пишется в журнал
строкой Python и поддерживает undo. После задачи 1.2 у `Document` были открытые методы изменения, а ADR 0002
оставил на 1.3 их закрытие и восстановление удалённого поддерева с прежними id. Нужно решить, как команда
получает undo, где граница «прямой записи», что считать шагом истории и в каком виде писать журнал, чтобы он
воспроизводился в новом документе с тем же результатом.

## Решения

1. **Undo записывается, а не пишется руками.** Задача формулирует команду как пару execute/undo; здесь
   команда — только обработчик (`CommandHandler`), а все её изменения проходят через `DocumentEditor` и
   записываются в `ChangeSet`. Каждая запись хранит значение, которое заменила: существование объекта (узел
   `std::map::extract` вместе с объектом и место среди соседей), имя, свойства, данные, одна зависимость,
   единицы. Применение записи меняет местами её значение и значение в документе, поэтому одна и та же запись
   служит undo и redo, а большие данные (`std::shared_ptr<const ObjectData>`) не копируются. Удаление поддерева
   — это извлечение объектов от листьев к корню, поэтому undo возвращает их с теми же id на те же места, с
   именами и индексом зависимостей. Обработчик не может «забыть» undo или разойтись с execute, а undo работает и
   после того, как модуль-автор команды снят с регистрации.
2. **Прямая запись закрыта.** Изменяющие методы `Document` приватны; изменить документ можно только через
   `DocumentEditor`, которого создаёт лишь `CommandBus` (friend). Шина выдаёт редактор выполняющейся команде; вне
   команды он бросает `ModelError(outside_command)`. `set_owner_enabled` остаётся открытым: включение модуля —
   не изменение модели (ADR 0002 п. 4). `Document` больше не перемещается: на него ссылаются шина и виды.
3. **Шаг истории** — команда вне транзакции или вся внешняя транзакция. Команда, которую запускает другая
   команда (`CommandContext::execute`), входит в её шаг и в журнал не пишется: журнал повторяет внешний вызов.
   Команда без изменений модели (запуск задания, просмотр) пишется в журнал, но шага не создаёт. Новый шаг
   очищает redo.
4. **Транзакции** — RAII-объект `Transaction`: `commit()` делает из внешней транзакции один шаг и одну запись
   журнала, вложенная сливается во внешнюю, деструктор без `commit()` откатывает. Undo/redo внутри транзакции и
   внутри команды, как и транзакция внутри команды, запрещены (`invalid_state`).
5. **Ошибки атомарны.** Исключение обработчика откатывает изменения команды (вложенной — только её), шаг не
   создаётся, журнал не пишется, исключение уходит вызывающему без изменений. Аргументы проверяются по схеме, а
   строка журнала формируется до запуска, поэтому журнал не может отказать после изменения модели.
6. **Id.** Undo не возвращает счётчик id: id не переиспользуются (ADR 0002 п. 2), а `stresslab.undo()` есть в
   журнале, так что воспроизведение берёт те же id. Откат неудачной команды или транзакции счётчик возвращает:
   их нет в журнале, и воспроизведение не должно сдвигать id.
7. **История и выключенные модули.** Undo/redo, которые изменили бы объект выключенного модуля, вернули бы его,
   добавили бы под него объект или удалили бы то, от чего он зависит, отклоняются `ModelError(opaque_object)`;
   шаг остаётся в стеке и выполнится, когда модуль включат.
8. **Событие «модель изменилась»** (`on_model_changed`) приходит один раз на завершённый шаг с изменениями:
   команда, commit внешней транзакции, undo, redo. В нём причина, метка (id команды или метка транзакции) и итог
   шага — созданные, удалённые и изменённые объекты и смена единиц. Промежуточные состояния транзакции наружу не
   видны, откат событий не шлёт. Журнал получает запись раньше слушателей события.
9. **Аргументы.** Схема — список именованных аргументов (`ArgSpec`) с типом (`boolean`, `integer`, `number`,
   `string`, `path`, `object`, `list`, `dict`, `any`), обязательностью и значением по умолчанию. Имена — ключевые
   слова Python (snake_case, не keyword). Значение — `fem::command::Value`: None, bool, int64, double, UTF-8 текст,
   путь, список, словарь с текстовыми ключами. Путь — отдельный вид, а не текст, поэтому журнал пишет
   `Path("...")` без знания схемы. Шина нормализует аргументы (целое → число для `number`, текст → путь для
   `path`; `None` у необязательного аргумента означает «не передан») и в журнал пишет нормализованные значения.
10. **Формат журнала `.slpy`** — скрипт Python: заголовок (`import stresslab`, `from pathlib import Path`), строки
    `stresslab.cmd("id", key=value)`, `stresslab.undo()`, `stresslab.redo()` и блоки
    `with stresslab.transaction("метка"):`. Аргументы — в порядке схемы, только переданные (значения по умолчанию
    не пишутся). Значения: числа как `repr()` в Python (кратчайшее представление, экспонента вне диапазона
    1e-4…1e16, NaN и бесконечности запрещены), текст в двойных кавычках с UTF-8 как есть и экранированием
    управляющих символов и U+2028/U+2029, пути в generic-форме с `/` на всех ОС, словари с ключами в байтовом
    порядке. Вложенные транзакции уплощаются во внешний блок. Файл — UTF-8 без BOM, `\n`, сброс после каждой
    записи. До Python API (1.8) журнал читает внутренний парсер-заглушка, понимающий ровно эти конструкции.
11. **Команды ядра** `model.create`, `model.rename`, `model.set_properties`, `model.remove`,
    `model.add_dependency`, `model.remove_dependency`, `model.set_units` (owner `fem.core`) повторяют закрытые
    методы `Document`, чтобы скрипты, дерево и панель свойств могли править модель в терминах Model IR.
    Заблокированное удаление — `ModelError(removal_blocked)`. Большие данные этими командами не задаются: им не
    место в журнале, их создают команды модулей (импорт, мешер), которые при воспроизведении читают файлы или
    считают данные заново. Команды ядра нельзя снять с регистрации.
12. **`Task`** — пока заглушка (`fem::task::Task`): команда может вернуть задачу в `CommandResult`, шина
    передаёт её вызывающему. Прогресс, отмена и результат — задача 1.6.

## Рассмотренные альтернативы

- **Ручной undo у каждой команды** (как `QUndoCommand`) — буквально «execute/undo», но каждый модуль писал бы
  обратную операцию сам, ошибки в ней портили бы модель, а undo пропадал бы вместе с выключенным модулем.
- **Снимок документа на каждый шаг** — просто, но копирует свойства всех объектов на каждый клик; записи
  изменений копируют только изменённое, а сетки разделяются указателем.
- **`nlohmann::json` вместо `Value`** — тип уже есть в ядре, но не различает текст и путь, поэтому `Path(...)`
  в журнале зависел бы от схемы, а round-trip значения — от команды.
- **Журнал транзакций плоским списком команд** — короче, но undo после воспроизведения отменял бы по одной
  команде вместо всей группы: история не совпала бы с исходной.

## Последствия

- Журнал воспроизводится тождественно, если команды детерминированы (одни и те же аргументы и модель дают один
  и тот же результат) и в новом сеансе включены те же модули: включение модулей сейчас в журнал не пишется
  (оно появится командой в 1.5/1.15).
- Загрузка проекта (2.1) — не изменение модели; ей понадобится свой путь создания объектов с заданными id мимо
  шины, его решит задача 2.1.
- Стек undo пока не ограничен; лимит — настройка из задачи 1.7.
- Python API (1.8) реализует `stresslab.cmd`, `stresslab.undo/redo` и `stresslab.transaction` поверх этой шины;
  тогда парсер-заглушка станет не нужен для запуска журналов, но останется для чтения без интерпретатора.
- Форматирование чисел использует `std::to_chars(double)`; на macOS это требует deployment target ≥ 13.3
  (учесть в 3.11).
