# ADR 0024. Импорт Abaqus `.inp`: нативный модуль, данные и проблемы через C ABI

- Статус: принято
- Дата: 2026-10-18
- Источник: задача 3.2 из `docs/plan.md` (решение «на каком языке парсер» — перед задачей); `docs/architecture.md`
  §3 (Passthrough), §4.4 (виды модулей), §5 (`fem.format.abaqus-inp` — C++ парсер), §7; ADR 0002 (Model IR),
  0006 (менеджер модулей), 0023 (типы статики); пункты бэклога «Большие данные через C ABI», «Стороны „верх/низ“
  оболочечных элементов»
- Код: `extensions/fem.format.abaqus-inp/` (читатель `src/inp/`, связка с ABI `src/module.cpp`, манифест,
  схемы, переводы); ядро: `core/include/fem/extension_abi.h` (`create_object`, `report_problem`),
  `core/include/fem/core/command/problem.h`, `CommandContext::report`, `CommandBus::on_problem`,
  `core/include/fem/core/extension/open_file.h`, поле `command` у `fileFormats`; `extensions/CMakeLists.txt`
  (раскладка встроенных модулей); оболочка — «Файл → Импорт…» и вкладка «Проблемы»; headless — проблемы в
  stderr; справочник `docs/extensions/fem.format.abaqus-inp.md`

## Контекст

Открытие `.inp` начинает сценарий этапа 3. Файлы Abaqus/CAE и CalculiX бывают на миллионы элементов, а импорт
должен положить в модель сетку, наборы и объекты `fem.model.structural`, сохранив всё непонятое на своих местах
для экспорта (3.3). У платформы не было ни способа передать нативному модулю большие данные (C ABI знал только
JSON-аргументы команд), ни общего «открыть файл модели» (`onOpenFile` никто не вызывал, у `fileFormats` не было
команды), ни канала, по которому модуль сообщает предупреждения во вкладку «Проблемы».

## Решения

1. **Парсер на C++, модуль `kind = "native"`.** Читатель — статическая библиотека `fem_inp_reader` без ядра
   (C++20, nlohmann/json), модуль `fem_format_abaqus_inp` линкует её со связкой `module.cpp` и видит платформу
   только через `fem/extension_abi.h`. Так модуль собирается как сторонний, а тесты проверяют читатель
   напрямую. Python в хосте расширений отвергнут: сетки он уже передаёт через shared memory, но разбор
   миллионов строк в Python в 5–10 раз медленнее, а `.frd` (3.6) всё равно пойдёт тем же нативным путём.

2. **Большие данные через C ABI.** `FemCommandApi` дополнен в конце (версия ABI осталась 1, модули проверяют
   `struct_size`): `create_object(call, object_json, data, &id)` создаёт объект как часть команды. `object_json` —
   аргументы `model.create` и необязательный `"unique_name": true` (при занятом имени берётся `имя-2`, `имя-3`…:
   повторный импорт в ту же модель). `FemObjectData` — сетка (`FemMeshData`: метки и координаты узлов, блоки
   `FemElementBlock` с типом нейтральной нумерации), набор узлов, набор элементов или поверхность (пары
   «элемент, сторона»). Платформа копирует массивы один раз и проверяет их так же, как `Mesh`/`NodeSet`/`Surface`;
   ошибка — `FEM_ERROR` и `last_error`, исключения границу не пересекают. `ArrayData` через ABI не добавлен:
   3.2 он не нужен, вид данных добавится с чтением `.frd` (3.6).

3. **Проблемы команд — общий механизм ядра.** `fem::command::Problem` (важность, текст как в манифесте
   `%ключ%` с аргументами, файл и строка, владелец и команда). Команда сообщает их `CommandContext::report`, шина
   отдаёт сразу всем `CommandBus::on_problem` — до того, как команда закончилась, поэтому проблема видна и у
   упавшей команды (так импорт говорит, где файл неверен). Проблемы не отменяются undo и не пишутся в журнал.
   Текст переводит платформа каталогами модуля (`problem_text`), поэтому смена языка не требует кода модуля.
   Нативный модуль сообщает их `report_problem(call, json)`. Окно показывает предупреждения и ошибки во вкладке
   «Проблемы», а факты (`info`) — в строке подсказки; headless печатает всё в stderr. Хост Python пока не умеет
   `report_problem` (бэклог).

4. **«Открыть файл модели».** У `fileFormats` новое поле `command` — команда этого же модуля с аргументом
   `path` типа `path` (проверяется при разборе манифеста). `extension::find_import_format` ищет формат роли
   `model-import` включённого модуля по расширению без учёта регистра; `open_model_file` вызывает
   `activate_on(onOpenFile:<имя>)` и затем команду формата — в журнал попадает она
   (`stresslab.cmd("inp.import", path=…)`), повтор журнала читает файл заново. Оболочка получила «Файл →
   Импорт…» с фильтром из реестра (слов `inp` и `abaqus` в `shell/` нет). Импорт **добавляет** объекты в текущую
   модель; открытие `.inp` новым документом, стартовый экран и перетаскивание — задача 3.10.

5. **Встроенные модули раскладываются в дереве сборки.** Библиотеке нативного модуля нужно место рядом с
   манифестом, а не в исходниках. `extensions/CMakeLists.txt` копирует все встроенные модули (кроме `src/`,
   `tests/`, `CMakeLists.txt`, `__pycache__`) в `build/<preset>/builtin-extensions/<папка>/`, библиотеки
   нативных модулей собираются туда же; `FEM_BUILTIN_EXTENSIONS_DIR` приложения указывает на эту папку — так
   будет выглядеть установленное приложение (3.11). Тесты, которые ставят `fem.demo` и `fem.model.structural`
   из исходников, не изменились; правка Python-модуля попадает в копию со следующей сборкой.

6. **Детали и инстансы — сетка на инстанс.** У каждого `*INSTANCE` своя сетка (имя инстанса), координаты
   детали перенесены, затем повёрнуты вокруг оси a–b (порядок `*INSTANCE` Abaqus), метки узлов и элементов — как
   в файле. Наборы детали есть у каждого её инстанса; наборы сборки — на тех сетках, где у них есть члены, с тем
   же именем (набор на двух инстансах — два объекта, нагрузка зависит от обоих). Совпадение имени набора сборки
   с набором детали — `<сборка>.<имя>` и сообщение. Узлы и элементы самой сборки (опорные точки) — сетка с
   именем сборки; файл без деталей — одна сетка с именем файла. Сечение детали — по объекту на инстанс
   (`<инстанс>.<набор>`, если инстансов больше одного). Плоская сетка с перенумерацией отвергнута: номера
   узлов перестали бы совпадать с файлом.

7. **Passthrough — объект `abaqus_keyword`** модуля: ключевое слово, его текст как в файле (строка ключевого
   слова и строки данных, без комментариев), файл (относительно главного), строка, позиция `index` в развёрнутом
   списке ключевых слов и, где был, `part`/`assembly`/`instance`/`material`/`step`. Родитель — шаг, материал или
   корневой объект файла `abaqus_input` (имя файла, `*HEADING`). Правила: ключевое слово, понятое частично,
   делится (понятые строки — в IR, остальные — passthrough с той же строкой ключевого слова); параметр, который
   меняет смысл (`OP=NEW`, `AMPLITUDE`, `TYPE=VELOCITY`…), отправляет всё ключевое слово в passthrough; ссылка на
   неизвестное или ушедшее в passthrough имя — тоже. Определения сетки и наборов в passthrough не уходят (на
   них ссылается всё остальное): неизвестный их параметр пропускается с предупреждением, а то, без чего сетка
   была бы неверной (`*NGEN`, `*NCOPY`, `*SYSTEM`, `*PARAMETER`, `SYSTEM=C`), — отказ. Одинаковые предупреждения
   «сохранено без интерпретации» сводятся в одно с числом.

8. **Типы элементов.** Узлы Abaqus для всех читаемых форм совпадают с нейтральной нумерацией (клин проверен по
   таблице сторон). Блок сетки — на каждый тип Abaqus; типы по блокам записаны в объект `abaqus_element_types`
   (ребёнок сетки), чтобы экспорт и `validate()` решателя (C3D10M → C3D10, 3.5) знали исходный тип. Типы этапа 3
   (C3D4/10, C3D8/20 и R-варианты, S3, S4/S4R, B31) описываются формой и сечением полностью; прочие с известной
   формой (C3D10M, C3D8I, C3D6/15, S8R, B32…) читаются с предупреждением; неизвестные (CPS4, R3D4…) — в
   passthrough. Интегрирование сечения — по типам его набора, смесь полного и редуцированного делит набор
   (ADR 0023 п. 4).

9. **Кодировки.** BOM UTF-8 и UTF-16 LE/BE побеждают; без BOM — UTF-8, а если байты не UTF-8, аргумент
   `encoding` команды: `auto` (по умолчанию) читает Windows-1252 с предупреждением, есть `windows-1251`,
   `windows-1252`, `latin-1`, а `utf-8` отказывает. Числа читаются без учёта локали процесса (Qt ставит
   `LC_NUMERIC` из окружения на Unix), с экспонентой `D`. Единиц в `.inp` нет: значения берутся в системе единиц
   модели без пересчёта, импорт сообщает это фактом (`info`).

10. **Импорт синхронный.** Команда разбирает файл и создаёт объекты в одном шаге undo; 1 млн C3D10 читается за
    секунды в Release (замер в PR). Это отклонение от правила 7 CLAUDE.md: у шины нет команды «разобрать в
    задаче, применить одним шагом undo на потоке модели», а у C ABI нет задач. Механизм нужен и мешерам
    (этап 5) — в бэклоге.

## Рассмотренные альтернативы

- **Python-модуль в хосте расширений** — без работы над ABI, но медленнее на больших сетках (п. 1).
- **Связать нативный модуль с `femcore`** — модуль получил бы `Document` и `Mesh` напрямую, но зависел бы от
  C++-типов и сборки платформы, а сторонний модуль так не сделает. Отклонено.
- **Сетка на деталь и преобразование инстанса как свойство** — точнее повторяет Abaqus, но решателю,
  просмотрщику и наборам сборки нужны координаты в сборке. Отклонено.
- **Предупреждения как результат команды** — их увидел бы только тот, кто вызвал команду, а не вкладка
  «Проблемы» и не headless. Отклонено.
- **Библиотека модуля в папке исходников** — артефакты сборки в дереве исходников и конфликт Debug/Release
  разных пресетов. Отклонено.

## Последствия

- Экспорт (3.3) возвращает `abaqus_keyword` на места по `index` и `part`/`assembly`/`instance`/`step`, пишет
  инстансы деталями или плоско и сообщает это `describe_losses`; ему понадобится чтение больших данных через
  C ABI (сетка и наборы) — расширить `FemCommandApi` тем же способом.
- Чтение `.frd` (3.6) добавит в `FemObjectData` вид `ArrayData`.
- Проверки этапов (3.9) и `validate()` решателя (3.5) пользуются тем же каналом проблем.
