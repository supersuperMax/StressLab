# ADR 0019. История проекта на libgit2: голый репозиторий из файлов в памяти, журнал версии, автоснимки

- Статус: принято; п. 9 уточнён в ADR 0020 (восстановление берёт ещё не выданный id)
- Дата: 2026-10-16
- Источник: задача 2.3 из `docs/plan.md`; `docs/architecture.md` §3.1 («Что видит пользователь», «Технология»);
  `docs/interface-design.md` §12 (словарь, откат, автоматические версии); ADR 0017 (папка проекта), ADR 0018 п. 6
  (2.3 передаёт в очистку блоки всех версий)
- Код: `storage/` (`repository.h`, `history.h`, `src/names.{h,cpp}`, `project.h` `store_project` и
  `write_project_files`, `project_format.h` `read_object`, `session.h` `ProjectSession::history`, новые коды
  `ProjectErrc`), `core/` (`DocumentEditor::restore`, `CommandSpec::snapshot_before`,
  `CommandBus::on_before_command`, поле манифеста `snapshotBefore`), `python/bindings/src/history.cpp`,
  `python/stresslab/history.py`, строки `project.error.*` в `shell/l10n/`

## Контекст

После 2.1–2.2 проект — папка с каноническими JSON-файлами и блоками данных, но сохранение перезаписывает файлы:
вернуться к прошлому состоянию, держать варианты конструкции и привязать результат расчёта к точной модели
нельзя. Архитектура выбрала git через libgit2. Нужно было решить, как git видит проект, как хранить «журнал
версии», что считать автоматической версией и кто её делает, как назвать ветки именами пользователей и как
восстановить один объект через Command Bus с undo.

## Решения

1. **Голый репозиторий `.fem/git` без рабочего каталога libgit2.** Версия строится в памяти из `ProjectFiles`
   (тех же, что пишет сохранение) деревом git и читается обратно в `ProjectFiles`; индекс, checkout, фильтры и
   `core.autocrlf` libgit2 не участвуют, поэтому в git ровно те байты, что в папке, на любой ОС. Дерево версии
   повторяет папку: `project.json`, `model/…`, `refs/blobs.json` и служебный `.fem/journal.slpy`. Блоки данных
   в git не попадают: они в `.fem/objects`, версия ссылается на них через `refs/blobs.json` (ADR 0018).
   `storage::Repository` — обёртка libgit2 без `Document`; `storage::ProjectHistory` — операции над документом
   и папкой, у каждого `ProjectSession` своя (`session.history()`).

2. **libgit2 изолирован от настроек машины.** Пути поиска конфигурации (system, xdg, global, programdata) пусты:
   `~/.gitconfig` пользователя не меняет поведение истории и тестов. Проверка владельца репозитория выключена
   (проект на общем диске открывается): мы не запускаем хуков, фильтров и checkout, через которые чужой
   репозиторий мог бы навредить. `fsync` для `.fem/git` включён. Автор версий — `ProjectHistory::set_author`
   (`stresslab.history.set_author`), по умолчанию имя пользователя ОС и почта `unknown` (libgit2 не принимает
   пустую почту). Настройка автора в окне — 2.6.

3. **Версия = сохранение + коммит, сделанные из документа.** `commit` сохраняет проект (папка становится
   версией) и делает коммит на текущем варианте; Ctrl/Cmd+S и автосохранение только сохраняют. «Есть изменения
   не в истории» (`has_changes`) — точное сравнение файлов документа с файлами версии, а не флаг: undo до
   состояния версии — изменений нет, пустых версий не бывает (`nothing_to_commit`). Версии модулей в
   `project.json` при сравнении не учитываются: обновление модуля — не изменение модели. Без версий
   сравнивается с пустой моделью.

4. **Журнал версии.** Каждая версия хранит `.fem/journal.slpy` — записи шины с предыдущей версии (команды,
   undo/redo, действия проекта). Строка самой фиксации в журнал версии не входит. Журнал с последней версии
   пишется в `.fem/journal.slpy` папки при каждом сохранении и читается при открытии, поэтому переживает
   перезапуск; после фиксации файл удаляется. Переключение варианта и stash заменяют его журналом нового
   состояния, `stash_pop` возвращает журнал отложенных изменений. Журнал восстановления версии — одна строка
   `stresslab.history.restore_version(...)`.

5. **Действия — строки журнала с именами, как их дали.** `stresslab.history.commit("…")`, `snapshot`,
   `branch("…", at="…")`, `checkout`, `tag`, `stash`, `stash_pop`, `stash_drop`, `restore_version`. Полные id в
   журнал не подставляются: при повторе журнала в новом проекте id версий другие (время, автор), а имена
   вариантов, меток и `main~N` дают ту же историю (тест `test_the_journal_replays_into_the_same_history`).
   Внутри команды или транзакции действия запрещены, без папки — `no_folder`.

6. **Варианты, метки, отложенные изменения.** Вариант — ветка, основной — `main`; метка — лёгкий тег;
   отложенные изменения — коммиты вида stash (родитель — версия, на которой отложили) под
   `refs/stashes/<10 цифр>`, а не `git stash` (тот работает с индексом и рабочим каталогом). Версию называют
   вариантом, меткой, id или его началом (от 4 цифр), с `~N` — на N версий назад по первым родителям;
   существующий вариант или метка важнее похожего id.
   - `checkout` варианта переключает на него; метки или версии — открывает версию «на просмотр» (detached):
     фиксировать там нельзя (`detached`), сначала «Сделать вариантом отсюда» (`branch` + `checkout`).
   - С изменениями не в истории `checkout` отказывает (`uncommitted_changes`): окно 2.6 предложит
     зафиксировать или отложить.
   - `stash_pop` только на той же версии, где отложили, и без изменений; иначе `stash_conflict` — перенос на
     другую версию был бы слиянием (раздел 5 плана).

7. **Имена пользователей в ссылках.** Ссылки — файлы, а libgit2 на Windows ограничивает их путь 260 символами
   (считает символы UTF-8; `core.longpaths` к ссылкам не применяется). Поэтому текст вне ASCII (кириллица)
   хранится в имени ссылки как есть, а ASCII кроме `[A-Za-z0-9_-]`, ведущий `-` и первая буква имён устройств
   Windows пишутся `%XX`; точка всегда `%2E`, так что правила git о `..`, `.lock` и точках не срабатывают.
   Имя — UTF-8 до 64 символов без управляющих, экранированное не длиннее 200 байт (`invalid_name`).
   Имена, различающиеся только регистром латиницы и кириллицы, считаются одним (`already_exists`) на любой
   ОС: на Windows и macOS это был бы один файл. `git branch` показывает читаемые имена.

8. **Восстановление версии — новая версия поверх (revert-семантика).** Незафиксированное сначала становится
   автоматической версией, затем модель старой версии фиксируется как новая версия вида `restore` с трейлером
   `StressLab-Restored`; последующие версии остаются. `nextObjectId` — больший из текущего и старого, чтобы id
   объектов, созданных после старой версии, не выдавались повторно (ADR 0002 п. 2).

9. **Восстановление одного объекта — команда шины `history.restore_object(object, version)`** (владелец
   `fem.history`): один шаг undo, строка журнала `stresslab.cmd("history.restore_object", …)`. Объект читается из
   версии без декодирования остальных сеток (`read_object`). Есть сейчас — возвращаются имя, свойства, данные и
   зависимости; удалён — возвращается с прежним id новым `DocumentEditor::restore` (как undo удаления: место
   среди соседей по id, те же проверки, что у `create`; зависимые объекты снова его видят). Другая
   `schemaVersion` или зависимость на отсутствующий объект — ошибка: сначала восстановить его.

10. **Автоматические версии.** `snapshot(reason)` делает версию вида `automatic`, если есть изменения или версий
    ещё нет, и возвращает версию, равную модели, — к ней 2.5 привяжет результат. Рискованные операции модули
    объявляют сами: `snapshotBefore = true` у команды в манифесте → `CommandSpec::snapshot_before`; шина перед
    командой верхнего уровня (не вложенной и вне транзакции) шлёт `on_before_command`, и история делает
    автоснимок с трейлером `StressLab-Before: <id команды>`. Без папки или на просмотре версии снимка нет;
    ошибка снимка останавливает команду. В журнал такой снимок не пишется: он следует из команды.

11. **Вид версии — трейлеры сообщения** (`StressLab-Kind: automatic | restore | stash`, `StressLab-Before`,
    `StressLab-Restored`, `StressLab-Branch`). Текст автосообщений английский («Before fem.mesh.rebuild»,
    «Restored version 3f2a1c0: …»); окно 2.6 покажет локализованную подпись по трейлерам, так что история не
    зависит от языка того, кто её писал.

12. **Очистка проекта** передаёт в `clean_project` блоки `refs/blobs.json` всех версий, достижимых из вариантов,
    меток, отложенных изменений и HEAD (ADR 0018 п. 6); `refs/blobs.json`, общий у многих версий, читается
    один раз.

## Рассмотренные альтернативы

- **Рабочий каталог и индекс libgit2 (обычный `git add/commit/checkout`).** Тогда байты в git зависели бы от
  фильтров и `autocrlf`, а checkout libgit2 пришлось бы согласовывать с нашим сохранением и блоками. Папку и
  так пишет `save_project`.
- **Журнал в git notes или в сообщении коммита.** Notes живут отдельными ссылками и теряются при переносе;
  сообщение — текст для людей, журналы бывают длинными. Файл дерева идёт вместе с версией.
- **`git stash`.** Работает с индексом и рабочим каталогом, которых у нас нет.
- **Ссылки с `%XX` для всего не-ASCII.** Короче для правил, но длинное кириллическое имя упирается в 260
  символов пути на Windows (так и упал первый вариант теста меток).
- **Восстановление объекта командами ядра (`model.create`, `model.set_properties`).** Удалённый объект получил
  бы новый id, а зависимые объекты остались бы со сломанной зависимостью; данные сеток в журнал не помещаются.
- **Автоснимок в Job Manager.** Job Manager не знает документа и вызывается из любого потока; запуск расчёта —
  команда модуля, флаг на ней покрывает и его.

## Последствия

- Каждое `has_changes`, `commit`, `checkout` и автоснимок кодируют модель целиком (как сохранение); на больших
  сетках это заметно — бэклог «кэш ссылок на блоки» (2.2) помогает и здесь.
- Объекты git создаются только для чтения; удалять папку проекта своими средствами надо с учётом этого
  (тест headless снимает атрибут на Windows).
- Удаление вариантов и версий с корзиной на 30 дней, настройка автора в окне, слияние и перенос отложенных
  изменений на другую версию — позже (бэклог, раздел 5 плана).
- Сохранить как… в другую папку переносит модель и журнал с последней версии, но не историю.
