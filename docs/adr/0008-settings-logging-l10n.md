# ADR 0008. Настройки, логирование и локализация

- Статус: принято
- Дата: 2026-10-12
- Источник: `docs/architecture.md` §2 и §4.2 (`settings`, `localization`), `docs/interface-design.md` §10,
  задача 1.7 из `docs/plan.md`
- Код: `core/include/fem/core/settings/` (`fem::settings`), `core/include/fem/core/l10n/` (`fem::l10n`),
  `core/include/fem/core/log/log.h` (`fem::log`), `core/include/fem/core/user_folders.h`,
  `core/include/fem/core/bindings.h`, каталоги ядра `core/l10n/*.json`

## Контекст

С задачи 1.5 манифест разбирает `contributes.settings` (тип, значение по умолчанию, описание, `enum`,
`minimum`, `maximum`) и `contributes.localization` (язык и путь к каталогу), но значения настроек нигде не
проверялись, формата каталога не было, а строки манифестов хранились как есть (ADR 0006 п. 9). Ядру нужны
настройки двух уровней (пользователь и проект), журнал работы в папке пользователя и переводы ru/en с первого
дня, причём модули встраиваются и выключаются без перезапуска (правило 5): их настройки и переводы должны
появляться и исчезать вместе с ними, а данные — сохраняться.

## Решения

1. **Схема настройки — запись манифеста.** `settings::Schema` — это `extension::SettingContribution`, без
   второго типа. Манифест получил одно поле `scope = "project" | "user"`: `project` (по умолчанию) — значение
   можно задать и у пользователя, и в проекте; `user` — только у пользователя (пути к программам, язык,
   параметры машины). Значение по умолчанию: `default`, иначе первое из `enum`, иначе `false`, `0` или `""` —
   так `value(key)` всегда подходит к схеме.
2. **Три источника значения**: по умолчанию < пользователь < проект. `Settings::value` — значение в силе,
   `state` — все уровни и откуда взято значение (для формы настроек). Настройки ядра (`fem.core`, все `user`):
   `general.language` (`""` — язык системы), `history.undoLimit` (по умолчанию 100, `0` — без лимита;
   закрывает пункт бэклога из 1.3) и `log.level`.
3. **Проверка по схеме** (`validate`): тип (`integer` — только целое JSON, `3.0` не целое; `number` — конечное;
   текст и путь — корректный UTF-8, путь без нулевого байта), `enum`, `minimum`/`maximum`, `scope`. Ошибка —
   `Issue{code, key, level, message, args}`: `message` для разработчиков и лога, текст для пользователя —
   строка ядра `settings.error.<code>` с аргументами `args` (`Issue::text`), тип подставляется переведённым.
4. **Ничего не теряется.** Значение без схемы (модуль выключен или не установлен) и значение, не подходящее к
   схеме, остаются на своём уровне и записываются обратно в файл как были, но не действуют — действует уровень
   ниже. Неподходящие значения видны в `issues()` и в логе; значения без схемы проблемой не считаются. Когда
   схема возвращается (модуль включили), значение проверяется заново. `set` неподходящее значение отвергает
   (`SettingsError`) и ничего не меняет.
5. **Повтор ключа.** Ключ настройки уникален среди модулей (реестр, ADR 0006), но может совпасть с ключом ядра.
   Схема с занятым ключом отвергается с `duplicate_setting` в `issues()` и логе, остальные схемы модуля
   добавляются; модуль включается.
6. **Файл настроек** — JSON
   `{"format": "stresslab.settings", "formatVersion": 1, "values": {"<ключ>": <значение>}}`: ключи
   отсортированы, отступ два пробела, UTF-8 как есть, `\n`, перевод строки в конце — сохранить → загрузить →
   сохранить даёт те же байты (правило 6). Ключи плоские (`solver.threads`), как в VS Code, чтобы файл было
   удобно править руками. Файл пользователя — `<config>/settings.json` (п. 11); где лежит файл проекта, решит
   формат папки проекта (2.1), `Settings` получает путь. Запись — через временный файл и переименование, так
   что сбой посреди записи оставляет старый файл. Отсутствующий файл — пустой уровень; повреждённый —
   `SettingsError(invalid_file)`, уровень не меняется.
7. **Настройки — не модель.** Они меняются без Command Bus, undo и журнала: правило 3 касается модели, а
   настройки пользователя не должны откатываться вместе с моделью. События — `on_changed(key)`, только когда
   меняется значение в силе (`set`, `reset`, `clear`, загрузка, появление или исчезновение схемы). Запись
   изменений настроек в журнал для сценариев — в бэклоге.
8. **Каталог строк** — JSON одного языка:
   `{"format": "stresslab.l10n", "formatVersion": 1, "strings": {...}, "modules": {"<id>": {...}}}`.
   `strings` — строки владельца каталога, `modules` — переводы для других модулей и для ядра (`fem.core`):
   языковой пакет — модуль, у которого есть только `modules`. Строка — текст с подстановками `{name}`
   (`{{`/`}}` — фигурные скобки) или объект форм множественного числа CLDR (`zero`, `one`, `two`, `few`,
   `many`, `other`; `other` обязателен), выбираемых по аргументу `count`. Каталог проверяется целиком при
   загрузке: неизвестные ключи, формы, сломанные подстановки — ошибка с причиной.
9. **Поиск строки** `(owner, key)`: языки `fallback_chain(language)` — сам язык, его укороченные теги, затем
   `en` (`pt-BR → pt → en`); в каждом языке — сначала каталог владельца, затем `modules` других каталогов в
   порядке id владельцев. Не нашлось нигде — текстом служит ключ. Правила множественного числа берутся по
   языку найденной строки: английская строка для русского запроса склоняется по-английски. Правила — для
   `ru`, `uk`, `be` (one/few/many/other) и английские для остальных; дробное число — `other`.
10. **Строки манифестов** — как в VS Code: текст вида `%key%` целиком — ключ строки модуля
    (`Localization::manifest_text`), остальной текст показывается как есть. Реестр хранит строки
    непереведёнными, переводит оболочка при построении меню и форм, поэтому язык можно сменить без
    перезапуска (`on_language_changed`). Описания настроек ядра — `%setting.<ключ>%`.
11. **Каталоги ядра** (`core/l10n/en.json`, `ru.json`) встраиваются в библиотеку при сборке
    (`cmake/EmbedCatalogs.cmake`, байты массивом, а не строковым литералом — у MSVC ограничена его длина), чтобы
    `--headless` и тесты не зависели от файлов рядом с исполняемым. Тест следит, что у каждого языка те же
    ключи, те же подстановки и те же формы, что у английского.
12. **Язык.** `set_language` нормализует тег (`ru_RU.UTF-8 → ru-RU`, `zh-hant-tw → zh-Hant-TW`); пустой или
    неверный — `en`. Язык без каталогов допустим: строки берутся из английского. `system_language()` —
    язык интерфейса Windows (`GetUserDefaultUILanguage`) или `LC_ALL`/`LC_MESSAGES`/`LANG`. Связка
    `bind_language` берёт язык из настройки `general.language`, пустое значение — язык системы.
13. **Папки пользователя** (`user_folders`) — по правилам ОС: Windows — Roaming AppData для настроек и Local
    AppData для логов (через `SHGetKnownFolderPath`, широкие пути); macOS — `~/Library/Application Support` и
    `~/Library/Logs`; Linux и прочие — XDG (`$XDG_CONFIG_HOME`, `$XDG_STATE_HOME`, относительные значения
    игнорируются). Имя папки — `fem::kProductName` (на Linux — строчными). Логика — чистая функция от входов,
    поэтому правила всех ОС проверяются тестами на любой.
14. **Логирование** — spdlog. Каждая часть пишет в свой логгер по категории (`fem::log::logger("settings")`);
    все логгеры делят приёмники, которые подключает объект `Logging`: файл с ротацией и, для `--headless`,
    stderr. Без `Logging` (библиотека, тесты) сообщения никуда не идут, а уровень логгеров — `off`, так что
    сообщения даже не форматируются. Строка: `2026-10-12 14:03:51.207 [warning] [settings] [<поток>] текст`,
    перевод строки `\n` на всех ОС, сброс после каждой строки, чтобы при падении не терять последнее.
15. **Свой приёмник ротации.** Штатный `rotating_file_sink` spdlog открывает файл узким именем в ANSI-кодировке
    Windows и не открывает папку пользователя с буквами вне неё (кириллическое имя на английской Windows,
    как в CI). `RotatingFileSink` открывает файл через `std::filesystem`: `stresslab.log`, `stresslab.1.log`, …,
    ротация по размеру (5 МиБ) и при открытии (каждый запуск — новый файл, 5 файлов). Если файл не удаётся
    переименовать (его держит другой процесс), запись продолжается в текущий.
16. **Связки** (`fem/core/bindings.h`) соединяют части, которые друг о друге не знают: настройки и каталоги
    следуют за включением модулей (`bind_settings`, `bind_catalogs`; каталог, который не загрузился, — в
    `Localization::issues()` и логе, модуль всё равно включается), язык, лимит undo и уровень лога — за
    настройками. Каждая применяет текущее состояние сразу и следит, пока жива подписка.

## Рассмотренные альтернативы

- **Собственный тип схемы настроек** (отдельно от записи манифеста) — два одинаковых описания и перевод между
  ними; запись манифеста уже хранит всё, включая исходную таблицу для формы.
- **Неподходящие значения из файла отбрасывать** — проще, но правка в старой версии модуля или опечатка в файле
  молча стирала бы настройку пользователя при следующем сохранении.
- **Настройки через Command Bus** — дало бы журнал и undo, но смешало бы предпочтения пользователя с историей
  модели: отмена правки модели откатывала бы язык или путь к программе.
- **Вложенный файл настроек** (`{"solver": {"threads": 4}}`) — красивее, но ключи с точками приходят из
  манифестов и в VS Code пишутся плоско; плоский файл проще править и сравнивать.
- **Ключи каталогов общие для всех модулей** (как в Qt `.ts`) — конфликты ключей между модулями; ключ в
  пространстве владельца не требует соглашений об именах.
- **gettext / Qt Linguist** — ядро не зависит от Qt GUI, а gettext неудобен для подключаемых модулей и
  плохо работает с путями Unicode на Windows; формат JSON уже читается (nlohmann/json).
- **Каталоги ядра файлами рядом с программой** — ещё одна вещь, которую установщик и тесты должны найти.
- **`SPDLOG_WCHAR_FILENAMES`** — меняет тип имён файлов во всём API spdlog только на Windows и требует
  пересборки порта vcpkg с другой опцией; свой приёмник — около ста строк.

## Последствия

- Оболочка (1.11–1.13) строит форму настроек по `Settings::schemas()` и `state()`, показывает
  `Issue::text`, переводит заголовки и описания через `manifest_text`; при смене языка пересобирает меню.
  Строка `settings.ignored` (сколько настроек не действует) — для этой формы. Язык системы на macOS оболочка
  берёт из Qt (`QLocale`) и передаёт в `set_language`, если `general.language` пуст.
- Приложение (`app/`, 1.10) при старте: `Logging` в `user_folders().logs`, `Settings::load_file` из
  `user_folders().config / "settings.json"`, связки из `bindings.h`.
- Хранилище проекта (2.1) решает, где лежит файл настроек проекта, и загружает его в уровень `project`; при
  закрытии проекта — `clear(Level::project)`.
- Python API (1.8) даёт доступ к настройкам и переводам; запись `settings.set` в журнал — в бэклоге.
- Числа в переведённых строках пишутся с точкой: формат чисел по языку — в бэклоге.
