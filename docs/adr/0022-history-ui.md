# ADR 0022. Интерфейс истории: панель «История», версия только для просмотра, сравнение и ключевые показатели

- Статус: принято
- Дата: 2026-10-17
- Источник: задача 2.6 из `docs/plan.md`; `docs/interface-design.md` §12 («Словарь», «Панель „История“»,
  «Ежедневная работа», «Варианты конструкции», «Откат»); ADR 0019 (история), 0020 (дифф), 0021 (кэш результатов);
  пункты бэклога «Выбор отдельных правок…», «Устаревшие результаты в окне», «Порядок полей в тексте диффа»
- Код: `shell/` (`history_controller.h`, `history_panel.h`, `history_graph.h`, `history_text.h`,
  `version_bar.h` — полоса просмотра и переключатель вариантов, `comparison_view.h`, `main_window.h`,
  `project_actions.h` — вариант в заголовке, `contribution_ui.h` — `stage_bar_end`, `commands.cpp`,
  `icons/history.svg`, строки `history.*`, `comparison.*`, `versionBar.*`, `variantSwitcher.*`), ядро
  (`CommandBus::set_read_only`, `CommandErrc::read_only`, точка расширения `resultIndicators`, настройка
  `history.gitTerms`), `storage/` (`ProjectHistory::on_changed`, `describe_rows`, `ResultInfo::indicators`),
  `python/stresslab/results.py` (`put(indicators=)`), `docs/extension-guide.md` §3.7a

## Контекст

После 2.3–2.5 у проекта есть история, дифф и кэш результатов, но пользоваться ими можно только из Python.
Задача 2.6 — интерфейс §12: граф версий и вариантов, просмотр версии только для чтения, фиксация версии в
боковой панели, переключение вариантов, имя варианта цветом, экран сравнения с таблицей различий и ключевыми
показателями. Results IR появится в 3.1, 3D-вид — в 3.7: сравнение пока без двух 3D-видов, а показателям
нужен источник, который не зависит от формата результата.

## Решения

1. **Окно работает через `HistoryController` поверх `ProjectHistory`.** Каждое действие окна — вызов истории,
   который она сама пишет в журнал (`stresslab.history.checkout("…")` и т. д.); нового в журнале нет. Состояние
   (вариант, версия, `log(all)`, варианты, метки, отложенные изменения, результаты) перечитывается по новому
   сигналу ядра `ProjectHistory::on_changed` — после каждого действия истории и после изменений кэша результатов
   (`put`, `pin`, `unpin`, `remove`, `prune_inactive`) — и по `ProjectSession::on_changed`. Поэтому действия из
   консоли Python тоже обновляют панель. Неудачи не модальные: «Проблемы» и строка-подсказка, тексты причин —
   строки `project.error.*`.

2. **Просмотр версии — `checkout(<id>)` и шина «только для чтения».** Версия открывается как в ADR 0019
   (HEAD отделён), а окно включает новый режим ядра `CommandBus::set_read_only(true)`: команда, изменившая модель,
   откатывается и отклоняется (`CommandErrc::read_only`), в транзакции тоже; undo и redo отклоняются; команды,
   ничего не менявшие (экспорт, вид), работают; `replace_document` (открытие проекта, другой версии) разрешён.
   - Режим ставит окно, а не история: без окна (headless, Python в отдельном процессе) отделённый HEAD
     по-прежнему разрешает правки (ADR 0019, тесты 2.3). Правило 9 не нарушается: это ограничение интерфейса, а
     не возможность. Консоль Python окна идёт через ту же шину и тоже только читает.
   - Полоса над 3D-видом: «Вы смотрите версию от … «…». Она только для просмотра» и кнопки **[Вернуться к
     текущей]** (checkout варианта, откуда пришли; иначе `main`; иначе варианта, на линии которого версия),
     **[Сделать вариантом отсюда]** (`branch` + checkout) и **[Восстановить]** (вернуться, затем
     `restore_version` — новая версия поверх). Текст в одну строку, усечённый, целиком — во всплывающей подсказке.
   - Версия открывается двойным щелчком (Enter) или пунктом «Открыть для просмотра» контекстного меню, а не
     одиночным щелчком, как пишет §12: checkout сохраняет проект и перезагружает модель, а одиночный щелчок нужен,
     чтобы выбрать две версии для сравнения. Отклонение от документа.

3. **Изменения не в истории перед переключением** варианта или открытием версии: вопрос «Зафиксировать и
   перейти / Отложить и перейти / Отмена» с полем подписи, заполненным автоподписью (`Workbench::ask_pending`
   подменяют тесты). Выбросить изменения из вопроса нельзя: §12 предлагает зафиксировать или отложить, а
   отложенное удаляется в панели («Отложенные изменения»: [Вернуть] [Удалить]).

4. **«Зафиксировать версию» — форма в панели**, не модальное окно: поле подписи и список изменений
   (`describe(diff(текущая версия))`, ADR 0020). Ctrl/Cmd+Shift+S — действие меню «Файл» и палитры, открывает
   панель с формой. Пустая подпись — автоматическая: первые три изменения через «; » (до 200 символов) и
   «и ещё N изменений»; для первой версии — «Первая версия». Подпись — на языке интерфейса в момент фиксации.

5. **Граф — чистая раскладка `layout_graph`** (`shell/history_graph.h`, тесты без Qt). Дорожка на вариант:
   основной первым, остальные по имени; версия принадлежит первому варианту, чья линия первых родителей её
   достигает, поэтому общая с основным вариантом часть — на его дорожке, а вариант без своих версий дорожки не
   получает. Версии, которых не достигает ни один вариант (отложенные изменения, просматриваемая версия), — на
   своих серых дорожках. Скрытые фильтром версии пропускаются: ребро идёт к ближайшим показанным предкам.
   - Ряд — две строки. Первая: узел (пустой кружок — автоверсия, коралловое кольцо — где модель), чипы вариантов
     их цветом, «вы здесь» коралловым контуром (акцент бренда), метки контуром, подпись (серым у автоверсий).
     Вторая: автор · время · разделы дерева, которые версия изменила (заголовки типов из `describe_rows` диффа с
     первым родителем; читается один раз на версию) · «есть результаты» / «результаты закреплены» · «⚠
     результаты устарели» у последней версии варианта, у которого есть результаты, но не её.
   - Фильтры: автоматические версии (видны по умолчанию), только с результатами, только с метками, по автору.
     Текущая версия видна всегда.

6. **Цвет варианта.** Основной — синий, остальные — один из шести цветов по FNV-1a имени: одинаково на всех
   компьютерах и в каждом сеансе. Ни серого (цвет версий без варианта), ни кораллового (только акценты, §7
   бренд-кита). Цветом показаны переключатель в конце полосы этапов (виджет панели; этапы модулей вставляются
   перед ним — `ContributionHosts::stage_bar_end`) и дорожки графа. Заголовок окна ОС цветным быть не может, в нём
   имя: «крыло — Композитная обшивка[*] — StressLab». Переключатель — меню вариантов в один щелчок, «Новый
   вариант…», «История проекта»; при просмотре версии он серый и называет её. В панели тот же выбор — список
   вверху.

7. **Сравнение — экран вместо 3D-вида** (стопка виджетов центральной зоны; закрывается кнопкой). A и B —
   текущая модель, варианты, метки и версии, выбранные в графе («Сравнить» с двумя выбранными версиями, с одной —
   против текущей модели; «Отметить для сравнения» / «Сравнить с отмеченной»). A всегда раньше: текущая модель
   уходит в B. Дифф — `ProjectHistory::diff(A, B)`.
   - Таблица различий по разделам дерева: раздел (тип объекта, «Материал (2)») → объект → поля «было / стало».
     Строки даёт новая функция storage `describe_rows` — то же, что `describe`, по одному полю, с теми же
     подписями, единицами и `x-enumTitles`; объекты выключенных модулей — по членам сырого JSON. «Было» —
     красноватым, «стало» — зелёным, полупрозрачными для обеих тем.
   - Если B — текущая модель, объекты отмечаются и **восстанавливаются из A** командой `history.restore_objects`
     одним шагом undo — частичное восстановление §12 «Откат» (целые объекты; по полям — бэклог).
   - Два синхронных 3D-вида — отдельной задачей после 3.7 (как и сказано в задаче).

8. **Ключевые показатели — точка расширения `resultIndicators` и значения в записи результата.** Модуль
   объявляет показатель (`id`, `title`, `quantity` из каталога величин) — описание, как у остальных точек;
   значения кладёт тот, кто прочитал результат: `ResultCache::put(..., indicators)` и
   `stresslab.results.put(..., indicators={...})` — id → число в единицах модели, конечное (`invalid_data`
   иначе). В `entry.json` и описании закреплённого результата это член `indicators`, только если показатели
   есть: формат записи прежний, старые записи и golden-пакеты 2.5 не меняются. Показатели версии — у её
   результата, использованного последним, в котором они есть; у текущей модели — показатели её версии, если
   изменений нет. Таблица: показатели модулей в порядке реестра, затем неизвестные по id; A, B с единицами
   модели каждой стороны; разница в процентах по значениям в СИ. Точки расширения нет в таблице
   `docs/architecture.md` §4.2 — расхождение с документом, описано здесь и в `docs/extension-guide.md` §3.7a.

9. **Словарь.** Строки оболочки с ключом `<key>.git` — тот же текст в терминах git («Commit», «ветка», «тег»,
   «stash», «detached HEAD»); настройка ядра `history.gitTerms` (по умолчанию выключена). `history_text` берёт
   вариант `.git`, если настройка включена и строка есть, иначе обычную. Переключается на лету (сигнал
   `HistoryController::terms_changed`).

10. **Активность «История»** (иконка «часы с веткой», `shell/icons/history.svg`) — вкладка рядом с деревом
    модели, закрытая, пока её не откроют; после «Модель», перед «Модули».

## Рассмотренные альтернативы

- **«Только для чтения» в ядре при отделённом HEAD.** Изменило бы ADR 0019 и сценарии headless (правка
  просматриваемой версии, затем `branch` + `checkout`), а нужно это только окну.
- **Просмотр версии без checkout, в отдельном документе.** Дерево, свойства и 3D-вид работают с одним
  документом шины; второй документ потребовал бы второй шины и переключения всех панелей.
- **Раскладка графа как у git-клиентов** (упаковка дорожек). Линия варианта меняла бы колонку и цвет от ряда
  к ряду; дорожка на вариант читается проще, а вариантов в проекте единицы.
- **Показатели в Results IR (3.1).** Его ещё нет; показатели в записи кэша ничего не стоят и останутся, когда
  Results IR появится: модуль чтения результатов (3.6) будет класть их при `put`.
- **Модальный диалог «Зафиксировать версию».** §12 требует «короткое окно в боковой панели».

## Последствия

- Открытое сравнение с текущей моделью пересчитывается при каждом изменении модели, а дифф с текущей моделью
  сохраняет её блоки в папку (как `has_changes`, ADR 0019): на больших сетках это заметно. Сравнение закрывают,
  когда оно не нужно; кэш ссылок на блоки — в бэклоге с 2.2.
- Переключение, просмотр и восстановление синхронны (сохранение и загрузка проекта): на больших проектах окно
  замирает. Пункт бэклога «как `Task`» дополнен историей.
- Разделы, изменённые версией, читаются диффом при первом показе: для сотен версий первое открытие панели
  занимает время чтения их файлов из git.
