# ADR 0013. Оболочка из реестра contributions: меню, этапы, палитра, доступность команд

- Статус: принято
- Дата: 2026-10-13
- Источник: `docs/architecture.md` §4.2–4.3 и §4.6, `docs/interface-design.md` §4–7, задача 1.12 из
  `docs/plan.md`, `resources/branding/stresslab-kit/guidelines.md` §8, пункты бэклога «Меню „Правка“»,
  «Почему недоступно», «Порядок пунктов меню», «Падение модуля в интерфейсе», «Ключи `job.*`»
- Код: `shell/` (`contribution_ui.h`, `commands.h`, `command_palette.h`, `stages.h`, `menu_order.h`,
  `icons.h`, `problems.h`, `workbench.h`, `main_window.h`), `core/include/fem/core/context/when.h`
  (`WhenExpression::unmet`), `core/include/fem/core/extension/contributions.h` (`enablement`,
  `SubmenuContribution`), `core/include/fem/core/job/job_keys.h`, `app/src/application.h`

## Контекст

После 1.11 окно — каркас без содержимого: полоса этапов и панель активностей пусты, в меню только пункты
оболочки. Реестр contributions (ADR 0006) и context keys с `watch` (ADR 0005) уже есть. Задача — строить
зоны из реестра и пересобирать их без перезапуска, когда модуль включают и выключают и когда меняются ключи;
палитра команд показывает всё, недоступное — серым с причиной, команды выключенных модулей — с «Включить».
Архитектура оставляла открытыми: что делает команду недоступной (у команд не было условия), как модуль
называет своё верхнее меню (`location` — путь id без подписей), как сортировать пункты (`group` был просто
текстом), какие этапы стандартные и чей ключ `stage`, откуда иконка модуля без своей иконки.

## Решения

1. **`ContributionUi` строит всё, что внесли модули**, по `ContributionRegistry`: меню, контекстную панель,
   контекстные меню, полосу этапов, панель активностей, вкладки нижней панели и горячие клавиши. Пересборка
   целиком — по событиям `extension.enabled` и `extension.deactivated` и по смене языка. Видимость и
   доступность — по `ContextKeys::watch` всех условий (`when` мест показа, `enablement` команд, `stage ==
   '<этап>'` для отметки этапа); любое изменение условия обновляет состояние всех элементов синхронно
   (элементов десятки, вычисление дешёвое; рекурсивное обновление, например сброс этапа, откладывается до
   конца текущего). Записи реестра копируются: после выключения модуля в UI не остаётся указателей на его
   данные. Панели модулей (активности и вкладки) при пересборке не пересоздаются, пока модуль включён, —
   раскладка и ручное закрытие остаются.

2. **Доступность команды — новое поле манифеста `enablement`** (как в VS Code): `when` мест показа решает,
   *где видно*, `enablement` — *можно ли запустить* (серый пункт). Команда недоступна ещё, если у неё есть
   обязательный аргумент: оболочке нечего передать до форм 1.13 (причина «Нужны аргументы: file»). Причина
   строится из `WhenExpression::unmet` (новое в ядре): у цепочки `&&` — ложные операнды, всё остальное
   (`||`, `in`, `!(…)`) — одним условием. Условие описывается строкой оболочки `condition.<ключ>` («сетка в
   модели» для `model.hasMesh`), `condition.not.<ключ>` для отрицания, `stage == 'x'` — «этап «X»»; иначе
   условие показывается как записано. Значение условия может не измениться, а причина — измениться (из двух
   ложных операндов стал ложным один), поэтому меню обновляются при открытии (`aboutToShow`), кнопки
   контекстной панели — перед показом подсказки; палитра считает причины при открытии.

3. **Меню.** `location` — путь id через `/`: первый сегмент — верхнее меню, следующие — подменю. Меню оболочки
   `file`, `edit`, `view`, `help` получают пункты модулей в конец, после разделителя. Стандартные меню модулей
   подписывает оболочка (`menu.<id>`): `geometry`, `mesh`, `materials`, `steps`, `solve`, `results` — в этом
   порядке, потом прочие по подписи, `tools` последним, всё перед «Справкой». Прочие id подписывает новая точка
   `[[contributes.submenus]] id/title` (id уникальны между модулями, как другие id реестра); без подписи
   показывается id. Меню модуля без видимых пунктов скрыто; пункт с командой, которой нет ни на шине, ни в
   реестре, не строится.

4. **Порядок пунктов — `group` в форме VS Code `"<группа>@<порядок>"`**: группы по имени (текст, «1_run» перед
   «2_stop»), внутри — по целому порядку, потом по подписи; без группы — в конце; между группами разделитель.
   Порядок — только целое число (`std::from_chars` для `double` нет в libc++ старых macOS).

5. **Контекстная панель** — `QToolBar` над 3D-видом (`objectName` `contextToolbar`), крупные иконки с
   подписями, не больше 12 видимых команд (`ContributionUi::max_toolbar_commands`); остальные и группа `more` —
   в меню кнопки «⋯». Команда без иконки получает иконку модуля по умолчанию (п. 9). Пустая панель скрыта.
   Если 3D-вид узкий, `QToolBar` сам уносит лишние кнопки в своё меню расширения.

6. **Контекстные меню** строятся по запросу (`context_menu(location)`) из видимых сейчас пунктов; окно
   подключает `tree` (дерево модели) и `viewport` (3D-вид). Узлы дерева и `tree.selectedNodeType` придут в 1.13.

7. **Полоса этапов.** Стандартные этапы — `geometry`, `mesh`, `materials`, `steps`, `solve`, `results`
   (подписи `stage.<id>`), всегда на полосе и в этом порядке. Этапы модулей — только в слоты `before:`/`after:`
   стандартного этапа; несколько в одном слоте — в порядке реестра (по id модуля, затем по манифесту). Этап с
   другим якорем (в том числе этапом модуля) не показывается и пишется в лог: ядро не знает стандартных этапов,
   поэтому манифест его не отклоняет. Ключ `stage` (текст, владелец `fem.shell`, начальное значение
   `geometry`) объявляет оболочка; клик по этапу меняет ключ, отметка следует за ключом. Если текущий этап
   скрылся (условие ложно, модуль выключен), ключ возвращается на `geometry`.

8. **Панель активностей и вкладки.** Активность — панель ADS `activity:<id>` вкладкой рядом с деревом модели,
   закрытая до клика; кнопка — её `toggleViewAction` (не больше одной на модуль — это уже проверяет манифест).
   `icon` у `activityBar` стал необязательным. Вкладка — панель ADS `tab:<id>` в области журнала; новая вкладка
   не отнимает передний план у текущей. `when` открывает и закрывает вкладку только при смене значения, так что
   вкладку, закрытую руками, оболочка не открывает сама; после `restore_layout` состояние вкладок по `when`
   применяется заново (раскладка, сохранённая без модуля, закрыла бы его вкладку).

9. **Иконки.** Иконка модуля — монохромный SVG, который рисуется маской в цвет палитры в момент отрисовки
   (`QIconEngine`): обычная — `WindowText`, недоступная — `PlaceholderText`, выделенная — `HighlightedText`,
   отмеченная — `Accent`. Смена темы перекрашивает иконки без пересборки. `icon` — путь в папке модуля или id
   записи `icons`. Иконка по умолчанию — «горячая» коралловая плитка-четверть малого символа
   (`stresslab-symbol-small-color.svg`): путь берётся из файла кита как есть и обрамляется по границам плитки
   с полями 12 %; файлов-копий и перерисовок нет (guidelines §7–8).

10. **Горячие клавиши.** На каждое сочетание — одно действие окна; срабатывает первая привязка, чьё условие
    истинно (одна клавиша может делать разное на разных этапах, и Qt не видит двусмысленного сочетания).
    Сочетания оболочки (`Mod+Q`, `Mod+Shift+P`, Undo/Redo…) не отдаются модулям — такая привязка пишется в
    лог. Пункт меню показывает клавишу своей команды (`Qt::WidgetShortcut`, срабатывает только через действие
    окна с проверкой `when`).

11. **Палитра команд** — всплывающий `QDialog` (`Qt::Popup`) по `Mod+Shift+P` и из меню «Вид»: все команды
    `command_index()` (включённых и выключенных модулей) и действия оболочки (Undo/Redo, Выход, О программе,
    полноэкранный режим, переключатели зон). Строка: «Категория: Подпись», клавиша, модуль; недоступные серые с
    причиной; команда выключенного модуля — «В модуле «X», он выключен» и кнопка «Включить»
    (`ExtensionManager::enable`; если `plan_enable` бросает — причина вместо кнопки). Поиск — все слова
    запроса без учёта регистра в подписи, id и имени модуля. Enter запускает доступную команду и закрывает
    палитру, на выключенном модуле — включает его, палитра остаётся открытой.

12. **Запуск команд** — `Commands::run`: `CommandBus::execute(id)` без аргументов (журнал и undo как у
    любого вызова), ошибка — в лог и в строку-подсказку.

13. **«Правка»** — Отменить/Повторить с подписью шага (`undo_label`, подпись команды модуля), доступность по
    `history.canUndo`/`canRedo`, клавиши — стандартные клавиши ОС (`QKeySequence::Undo`/`Redo`).

14. **«Проблемы».** Вкладка — список сообщений (новые сверху), заголовок «Проблемы (n)». `extension.crashed`
    (переведённый `crash_message`) и `extension.activationFailed` попадают туда и в строку-подсказку.

15. **Ключи `job.*`** — `fem::job::JobKeys` в ядре (владелец `fem.core`, как велит ADR 0005): `job.running`
    (есть задание в очереди или в работе) и `job.active` (сколько их). События заданий приходят из рабочих
    потоков; пересчёт переносится в поток модели функцией `post` (окно — очередь Qt, headless —
    `Interpreter::call_soon`), в очереди не больше одного пересчёта. `Application` теперь владеет `JobManager`
    с `LocalExecutor`.

16. **Тесты** — GoogleTest, как в 1.11, плюс Qt Test (`QTest::keyClick`, `mouseClick`, `keyClicks`) для
    клавиш и кликов; модули пишутся в тестах манифестами, их код — фальшивый runtime. Тест скриншотов рисует
    окно с демонстрационным модулем.

## Рассмотренные альтернативы

- **Доступность как «ИЛИ» всех `when` мест показа** — без правки манифеста, но смешивает «где видно» и «можно
  ли запустить»: команда с `when = "stage == 'solve'"` на контекстной панели оказалась бы доступной в этапе
  «Расчёт» без сетки. Отклонено (п. 2, выбор в обсуждении плана).
- **Только стандартные верхние меню** (остальные сегменты пути — разделы) — без новой точки, но модуль
  «Оптимизация» не получил бы своего меню, которого ждёт §4.3. Отклонено (п. 3).
- **Скрывать недоступные пункты, как VS Code.** §7 интерфейса прямо просит серый пункт с причиной. Отклонено.
- **Точечное обновление элемента по своему `watch`.** Меньше работы на изменение, но лимит контекстной панели,
  видимость меню по видимости пунктов и сброс этапа всё равно требуют пересчёта соседей. Отклонено (п. 1).
- **Отдельный исполняемый файл на QTest (`QTEST_MAIN`)** — второй каркас тестов в ctest и CI. Отклонено (п. 16).
- **Одна боковая панель, которую активность подменяет (как в VS Code).** В ADS проще и привычнее Workbench
  держать панель активности вкладкой рядом с деревом. Пока так; вернуться, если вкладок станет слишком много.

## Последствия

- `docs/architecture.md` §4.2 не знает `enablement`, `submenus` и необязательной иконки активности —
  расхождение записано здесь и в PR.
- 1.13: контекстное меню `tree` для узлов, ключи `tree.*`/`selection.*`; формы аргументов сделают доступными
  команды с обязательными аргументами (п. 2).
- 1.14: встроенные активности оболочки («Модули», «Настройки») придётся держать отдельно: `ContributionUi`
  очищает панель активностей при пересборке.
- 3.5: ключ `job.solver` (Job Manager не знает решателей) — вместе с адаптером CalculiX.
- Клавиши пунктов нативного меню macOS (`WidgetShortcut`) локально не проверялись — только CI и ручная проверка
  на macOS.
