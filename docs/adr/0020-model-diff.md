# ADR 0020. Сравнение версий в терминах модели и частичное восстановление

- Статус: принято
- Дата: 2026-10-16
- Источник: задача 2.4 из `docs/plan.md`; `docs/architecture.md` §3.1 («Сравнение вариантов», «Риски»);
  `docs/interface-design.md` §12 (сравнение вариантов, откат части модели); ADR 0017 (файлы проекта), ADR 0018
  (описание данных в файле объекта), ADR 0019 (история, восстановление одного объекта)
- Код: `storage/` (`diff.h`, `src/diff.cpp`, `project_format.h` `read_project_records`, `history.h`
  `ProjectHistory::diff` и команда `history.restore_objects`), `core/` (`DocumentEditor::restore` берёт ещё не
  выданный id, строки `diff.*` и `model.type.*` в `core/l10n/`), `python/bindings/src/history.cpp`,
  `python/stresslab/history.py` (`diff`, `restore`), `Session::attach` и `Interpreter::attach` с `Localization`

## Контекст

После 2.3 версии и варианты есть, но понять, чем они отличаются, можно только по файлам. По §3.1 сравнение
должно говорить в терминах модели («Сечение skin-upper: толщина 2 → 3 мм; добавлена нагрузка gust-2; сетка
перестроена (48 312 → 61 007 элементов)»), работать и для объектов модулей через `propertySchemas`, показывать
объекты выключенных модулей сырым JSON и позволять вернуть часть модели: только материалы, только нагрузки,
один объект. Нужно было решить, по чему строить дифф (документы или файлы), как адресовать поля, где делать
текст и как устроить частичное восстановление.

## Решения

1. **Дифф строится по файлам двух состояний, без блоков данных.** `diff_files(before, after)` читает
   `ProjectFiles` (версию истории или текущую модель) через `read_project_records`. Этот вызов проверяет файлы
   так же, как `read_project`, но не декодирует данные. Файл объекта уже описывает свои данные (`"data":
   {"kind": "mesh", "nodes": …, "elements": …}`, ADR 0018), а смену блока видно по хэшу в `refs/blobs.json`.
   Поэтому сравнение версий с гигабайтными сетками не читает сетки. Объекты выключенных и неустановленных
   модулей сравниваются как любые другие: для диффа это тот же JSON. Документ (`model::Document`) не нужен,
   так что сравниваются и две старые версии, не открытые в окне.

2. **Что считается изменением.**
   - Изменения модели: единицы, объекты по id (добавлен, удалён, изменён), имя, родитель, версия схемы,
     зависимости (добавленные и снятые), свойства и данные.
   - Не изменения: версии модулей в `project.json` и `nextObjectId` (как `has_changes`, ADR 0019 п. 3).
   - Свойства сравниваются по листьям: объекты JSON — по членам, рекурсивно; списки и скаляры — целиком.
   - Путь листа — JSON Pointer без ведущего `/` с экранированием `~0`/`~1` (`solver/tolerance`). Так же поля
     называют формы и `model.set_property`.
   - `1` и `1.0`, `0.0` и `-0.0` различаются, как в файлах: сравниваются тексты значений.
   - Нет значения и `null` — разные вещи (`std::optional`).
   - `to_json(ModelDiff)` даёт детерминированный JSON для скриптов и golden-тестов.

3. **Текст — `describe(diff, {localization, registry})`, строка на изменение.** Изменения одного объекта
   идут через запятую в одной строке.
   - Тип объекта называется по `treeNodeTypes.title` модуля, типы ядра — строками `model.type.*`.
   - Поле называется по `title` из формы (`form::FormIndex`). Значение поля с `x-quantity` пишется с единицей
     модели (`model_unit`, строки `unit.*`); если единицы модели сменились, у каждой стороны своя. Значение
     выбора пишется по `x-enumTitles`.
   - Сетка: «перестроена (N → M элементов)» с формами множественного числа (`count`).
   - Владельца нет в реестре (модуль выключен или не установлен) → строка `diff.raw` с сырым JSON только
     различающихся членов файла (`{"properties":{"c":10.0}} → {"properties":{"c":12.0}}`). У добавленного
     или удалённого объекта — весь его JSON. Объекты ядра сырыми не бывают.
   - Без реестра (обычный Python) типы и поля называются своими id, и ничего не считается выключенным.
   - Строки лежат в каталогах ядра: текст нужен в headless и в Python, не только в окне. Список изменений
     окна «Зафиксировать версию» (2.6) — эти же строки.

4. **`ProjectHistory::diff(from, to)`; без `to` — с текущей моделью.** Текущая модель кодируется как при
   сохранении: блоки пишутся в хранилище папки, как у `has_changes`. Сравнение — чтение: в журнал не пишется
   и версий не делает. В Python `stresslab.history.diff(a, b=None)` возвращает `Diff` (`objects`, `units`,
   `lines`, `find`, `empty`, `str(diff)` — строки через «; »). Структура и строки приходят одним вызовом.
   - Строки делаются на языке приложения. `Session::attach` и `Interpreter::attach` теперь принимают
     `Localization` (окно и headless передают свою). Без неё строки ядра на английском, а реестр берётся у
     прикреплённого `ExtensionManager`.

5. **Частичное восстановление — команда `history.restore_objects(version, types, objects)`.** Владелец —
   `fem.history`; один шаг undo; строка журнала `stresslab.cmd("history.restore_objects", …)`; в Python —
   `history.restore(version, types=…, objects=…)`.
   - Выбор: `types` (`"material"` — все объекты типа, `"owner/material"` — объекты одного модуля) и/или
     `objects` (id).
   - Выбранный объект становится таким, как в версии:
     - изменённый получает прежние имя, свойства, данные и зависимости (общий код с `history.restore_object`);
     - удалённый после версии возвращается со своим id, родители раньше детей;
     - **созданный после версии удаляется**: «нагрузки как было» значит и без новых нагрузок.
   - Объекты, которые уже как в версии, не трогаются. Единицы модели не восстанавливаются.
   - Команда возвращает id изменённых объектов.
   - Ошибки, при которых вся команда откатывается (шина отменяет уже сделанные шаги):
     - объект выключенного модуля, который пришлось бы менять или удалять;
     - родитель, которого нет ни в модели, ни в выборке;
     - другая версия схемы;
     - пустая выборка;
     - id, которого нет ни в модели, ни в версии.

6. **`DocumentEditor::restore` берёт id, который документ ещё не выдавал** (уточняет ADR 0019 п. 9). При
   сравнении вариантов объект, созданный в другом варианте после ветвления, имеет id больше `next_id` этого
   документа. Раньше `restore` отказывал («id the document issued»). Теперь id занимается, а `next_id`
   становится больше него. После undo он остаётся занятым, как у `create`, поэтому id не выдаётся повторно.
   Иначе объект пришлось бы создать с новым id, и зависимости на него в той же версии сломались бы.

## Рассмотренные альтернативы

- **Дифф двух загруженных документов.** Пришлось бы декодировать все сетки обеих версий, а объекты
  выключенных модулей сравнивать как непрозрачные. Файлы содержат всё нужное.
- **Дифф строк JSON (обычный git diff).** Показывает строки файлов, а не поля. Не знает, что
  `refs/blobs.json` и `"data"` — одна сетка, и не говорит на языке форм.
- **Текст в оболочке (Qt).** Скрипты и headless остались бы без описаний, а автосписок изменений версии
  пришлось бы делать дважды.
- **`restore_objects` только для изменённых и удалённых объектов, без удаления новых.** Тогда «вернуть
  нагрузки» оставляло бы нагрузки, которых в версии не было, и модель не совпадала бы с версией по нагрузкам.
- **Восстанавливать объект другого варианта с новым id.** Ломает зависимости на него внутри той же версии и
  связь «тот же объект» между вариантами.

## Последствия

- Числа в тексте пишутся без разделителя разрядов и с точкой (`48312`): `Localization` пока не форматирует
  числа по языку. В бэклоге.
- Русские строки нейтральны к роду («Добавлено: Нагрузка gust-2»), а заголовки типов и полей пишутся, как
  в дереве и формах, с большой буквы.
- Свойства в тексте идут по указателям, а не в порядке формы (`x-order`). В бэклоге, к экрану 2.6.
- Id выдаются в каждом варианте независимо: разные объекты двух вариантов могут иметь один id. Восстановление
  такого объекта отказывает (другой тип). Решать со слиянием, раздел 5 плана; в бэклоге.
- Отметить галочками отдельные правки — это восстановление по полям и перенос между вариантами (2.6 и
  раздел 5). `restore_objects` работает с целыми объектами.
