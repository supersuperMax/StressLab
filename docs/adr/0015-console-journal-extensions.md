# ADR 0015. Консоль Python, журнал сессии и менеджер модулей

- Статус: принято
- Дата: 2026-10-14
- Источник: `docs/interface-design.md` §4 (нижняя панель, панель активностей), §6 («Менеджер модулей»,
  «Профили»), §14 пп. 2, 4, 5; `docs/architecture.md` §4.5, §4.6 пп. 4, 5, 10, §4.7; задача 1.14 из
  `docs/plan.md`; пункты бэклога «Удаление и обновление модулей» и «Встроенные активности оболочки»
- Код: `core/include/fem/core/command/journal.h` (`SessionJournal`), `core/include/fem/core/extension/`

  `python/embed/include/fem/python/console.h`, `shell/` (`python_console.h`, `journal_panel.h`,
  `extensions_panel.h`, `required_modules_bar.h`, `file_dialogs.h`, `workbench.h`, `main_window.h`,

## Контекст

После 1.13 вкладки «Журнал» и «Консоль Python» — заглушки, встроенный Python работает только в `--headless`
и `--python`, а менеджер модулей есть лишь как API ядра (`ExtensionManager`, профили из 1.5). Ядро не умело
удалять модули из индекса и перечитывать их манифесты, не знало, каким модулям принадлежат непрозрачные
объекты, и нигде не хранило, что пользователь выключил или поставил из папки: при каждом запуске окно
включало всё.

## Решения

1. **Журнал сессии — `command::SessionJournal` в ядре.** Подписан на `CommandBus::on_journal`, держит записи
   сессии в памяти, `text()` — заголовок `journal_header()` и записи, `save(path)` пишет через временный файл.
   Вкладка «Журнал» (`JournalPanel`) показывает записи по мере появления; «Сохранить журнал как скрипт…» —
   на вкладке, в меню «Файл» и в палитре, системным диалогом файла, расширение `.slpy` дописывается.
   Сохранённый файл — тот же формат, что `--journal` в headless, и запускается `stresslab --headless
   run-script`. Отдельный файл журнала, который окно пишет само (на случай падения), не делался — задача его
   не называла.

2. **Консоль — `stresslab._console.Console` на Python, обёрнутая трижды.** Логика (неполный оператор
   через `code.InteractiveConsole`, перехват stdout/stderr кусками «вывод/ошибка», трейсбек без кадров
   консоли, `exit()` как ошибка, а не выход из программы, дополнение `rlcompleter` по пространству консоли с
   импортированным `stresslab`) — на Python и проверяется pytest в обычном и встроенном интерпретаторе.
   `python::Console` (C++, `python/embed`) зовёт её через nanobind с GIL. Оболочка видит только интерфейс
   `shell::ConsoleEngine` и не линкуется с Python; приложение (`app/src/console_engine.h`) связывает одно с
   другим. Без Python (не запустился) вкладка говорит почему, остальное окно работает.

3. **Код консоли выполняется в потоке окна.** Модель однопоточная (ADR 0002), а `stresslab.cmd` меняет её
   напрямую, поэтому строка консоли работает там же, где команды меню. Цена: долгий код блокирует окно, вывод
   появляется по завершении, прерывания нет. Команды из консоли идут через Command Bus и попадают в журнал и
   undo, как любые другие (правило 3). Дополнение: одно совпадение подставляется, несколько — общее начало и
   список (`QCompleter`); пространство имён команды без собственной команды (`stresslab.model`) дописывается
   без `(`.

4. **Ядро: `uninstall`, `reload`, `updates`.** `uninstall(id)` сначала выключает модуль и зависящие (как
   `disable`), затем забывает его; папка на диске остаётся, объекты в модели — непрозрачными; встроенные
   модули удалить нельзя. `reload(id)` перечитывает манифест из папки модуля: включённый модуль и зависящие
   выключаются, манифест заменяется, они включаются снова, что не включилось — в отчёте. `ExtensionInfo`
   остаётся по тому же адресу. `updates()` — модули не из поставки, у которых в папке теперь другая версия.
   Вкладка «Обновления» показывает их до появления каталога.

5. **Новые события менеджера: `installed`, `uninstalled`, `updated`.** Оболочка держит указатели на
   `ExtensionInfo` и вклады; после удаления и перечитывания они недействительны, и подписчики должны
   перестроиться. `installed` шлётся и при `scan`.

6. **Что пользователь изменил в менеджере, хранится между сессиями — `extension::UserModules`** в
   `<папка настроек>/modules.json`: выключенные модули и папки модулей, поставленных из папки.
   Детерминированный JSON (`stresslab.modules`), round-trip тест. При запуске окно ставит модули из этих папок
   и включает всё, кроме выключенных (`Application::enable_user_modules`). Сохраняется после каждого
   изменения в менеджере (`Workbench::save_modules`) состоянием менеджера (`user_modules(manager)`): в
   «выключенные» попадают все совместимые невключённые, в том числе не включившиеся из-за зависимостей.
   Хранить «включённые» вместо «выключенных» отклонено: новый модуль поставки был бы выключен у всех, кто
   уже запускал программу.

7. **Модуль из папки ставится по ссылке, не копией.** Менеджер запоминает папку и помечает модуль
   «Локальный»; «Удалить» забывает папку, но не стирает её. Так автор модуля правит его на месте и получает
   «Обновить». Предупреждение «модуль не проверен» показывается при установке из папки, а не при каждом
   включении: иначе переключатель задавал бы вопрос на каждом щелчке.

8. **Менеджер модулей — встроенная активность «Модули».** Панель (`ExtensionsPanel`) — вкладка рядом с
   деревом, открывается иконкой 🧩. Поиск по имени, id и описанию; вкладки «Установленные», «Каталог» (пустая
   с пояснением) и «Обновления». Строка модуля: переключатель, версия, метка «Локальный», причина
   несовместимости или ошибки запуска; щелчок открывает карточку: описание, версия, автор, откуда модуль,
   **что он добавляет в интерфейс** по точкам таблицы `docs/interface-design.md` §6 (`contribution_lines`),
   зависимости и их состояние, папка; кнопки «Включить/Выключить», «Настроить» (раздел модуля в настройках,
   `SettingsPanel::show_section`), «Удалить» (не для встроенных). Списки перестраиваются по событиям
   менеджера в цикле событий, а не внутри сигнала переключателя, который они удаляют.

9. **Предупреждение о скрываемых узлах.** Выключение, удаление и применение профиля считают объекты модели
   тех модулей, что будут выключены, и спрашивают: «В открытой модели 3 узла модуля «Динамика». Они будут
   скрыты, но сохранятся в файле…» (множественные формы ru/en), заодно называя модули, которые выключатся
   вместе с ним. Без таких узлов и зависящих модулей выключение идёт сразу. Вопросы — немодальные
   `QMessageBox` окна с именами объектов (как диалог рабочих пространств): модальные окна запрещены модулям,
   а не оболочке, но немодальные удобнее тестировать.

10. **Профили — `ProfileLibrary` в ядре и раздел «Профиль» менеджера.** Файлы `<папка настроек>/profiles/
    *.json` в формате 1.5, имя файла из имени профиля (кириллица и пробелы как есть, запрещённые символы и
    имена устройств Windows заменяются), профиль ищется по имени внутри файла. «Применить» с тем же
    предупреждением (`ExtensionManager::plan_profile` говорит, что выключится), «Сохранить текущий как…»,
    «Удалить», «Импорт…»/«Экспорт…» файлом. В `layout` профиля — раскладка окна в формате рабочих пространств
    (`layout_to_json`), применяется вместе с модулями; пустая раскладка окно не трогает.

11. **Полоса «Модели нужны модули… [Включить] [Открыть без них]»** (`RequiredModulesBar`) над 3D-видом.
    Источник — `ExtensionManager::needed_modules()`: владельцы объектов документа, которые не включены;
    не установленные названы отдельно и без «Включить». Полоса смотрит на модель только по
    `MainWindow::check_required_modules()` — при открытии модели, а не когда пользователь сам выключил модуль.

12. **Встроенные активности оболочки: «Модель», «Модули», «Настройки»** — первые на панели активностей,
    отдельной группой перед активностями модулей (`ContributionHosts::shell_activities`), с собственными
    монохромными иконками `shell/icons/*.svg`, перекрашиваемыми под тему. Это действия показа панелей, а не
    вклады: при пересборке панели они возвращаются первыми.

13. **Выбор файлов и папок — через `FileDialogs` в `Workbench`.** По умолчанию системные диалоги (§10), в
    тестах — функции теста. Подтверждения — немодальные окна с именами (п. 9).

14. **Манифест: необязательное поле `author`** в `[extension]` — карточка показывает его (§6 «автор»).

## Рассмотренные альтернативы

- **Консоль в отдельном потоке или процессе.** Окно не блокировалось бы, но модель однопоточная, а
  процессу пришлось бы проксировать весь API. Отклонено (п. 3), прерывание долгого кода — в бэклоге.
- **Своё дополнение по реестру команд без `rlcompleter`.** Знало бы только команды; `rlcompleter`
  дополняет и переменные консоли, и API `stresslab`, а обёртки команд уже отдают `__dir__`. Отклонено.
- **Копировать модуль из папки в папку пользователя.** Надёжнее при удалении исходной папки, но автор
  модуля терял бы правку на месте и метку «Локальный» пришлось бы хранить отдельно. Отклонено (п. 7).
- **Хранить состояние модулей в настройках пользователя.** Настройки идут через схемы модулей и форму; список
  папок и выключенных модулей — не настройка, а состояние менеджера. Отдельный файл проще (п. 6).
- **Карточка модуля во вкладке центральной области, как в VS Code.** Центр занят 3D-видом; карточка внутри
  боковой панели со «← Все модули» не мешает работать с моделью.

## Последствия

- `docs/interface-design.md` §6 говорит о состоянии внешнего ПО в карточке («Abaqus: найден…»): данных для
  него нет до `detect()` решателей (3.5) — в бэклоге. Каталог пуст до каталога модулей (этап 6).
- `docs/architecture.md` §4.1 не знает поля `author`, а §4.5 — файла состояния модулей и папки профилей;
  они описаны здесь.
- Открытие проекта (2.1) вызывает `check_required_modules()`; пока список нужных модулей берётся из
  непрозрачных объектов документа, а не из файла проекта.
- `stresslab.extensions.enable/disable` в Python — задача 1.15; консоль 1.14 уже даёт место, где их вызвать.
- Зависимости python-модулей (`pip --target`) остаются в бэклоге: установка из папки их не ставит.
