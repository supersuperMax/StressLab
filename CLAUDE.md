# CLAUDE.md — StressLab

Этот файл кладётся в корень репозитория. Claude Code читает его в начале каждой сессии.

## Что это за проект

StressLab — кросс-платформенный пакет МКЭ (аналог Ansys/Abaqus) с модульной оболочкой в стиле VS Code. Ядро открыто под MIT; платные модули появятся позже. Первый релиз умеет только **линейную статику**. Облачного режима в первых версиях нет, но архитектура не должна ему мешать.

Полные проектные документы:
- `docs/architecture.md` — архитектура, стек, модель данных, система модулей, хранение и история проекта.
- `docs/interface-design.md` — интерфейс, точки встраивания модулей, история версий глазами пользователя.
- `docs/plan.md` — поэтапный план работ. Текущий этап и задача указаны в начале каждого промпта.

Перед изменением в незнакомой подсистеме прочитай соответствующий раздел этих документов. Если код расходится с документом, не меняй документ молча: опиши расхождение в PR и, если решение новое, добавь ADR в `docs/adr/`.

## Название и бренд

Продукт называется **StressLab**; до задачи 1.2a рабочее имя было FEM-APP. Решение — `docs/adr/0003-naming.md`.
`docs/architecture.md` и `docs/interface-design.md` написаны до переименования и используют старые имена: читай их через эту таблицу.

| Что | Старое имя | Новое имя |
|---|---|---|
| Продукт | FEM-APP | StressLab |
| Исполняемый файл | `femapp` | `stresslab` |
| Python-модуль и вызовы в журнале | `femapp`, `femapp.cmd(...)` | `stresslab`, `stresslab.cmd(...)` |
| Журнал сессии | `.fempy` | `.slpy` |
| Папка проекта | `.femproj` | `.slproj` |
| Архив проекта | `.femx` | `.slpack` |
| Пакет модуля | `.femext` | `.slext` |
| Манифест модуля | `fem-extension.toml` | `stresslab-extension.toml` |

Не переименовываются: пространство имён `fem::`, библиотека `femcore`, id модулей `fem.*`, опции CMake `FEM_*`.

- Имя продукта в коде берётся из одной константы, а не пишется литералом: `fem::kProductName` (`core/include/fem/core/product.h`) в C++ и `PROJECT_NAME` в CMake. Тест `CoreProduct.NameMatchesCMakeProject` следит, чтобы они совпадали.
- Старые имена вне этой таблицы, ADR и двух проектных документов выше ловит `python/tests/test_naming.py`.
- Бренд-кит `resources/branding/stresslab-kit/` — источник истины, правила в его `guidelines.md`. Файлы не перерисовывать и не перекрашивать (§7). Сборка берёт пути к иконкам и логотипам из `cmake/Branding.cmake`, а не из своих копий.
- Цвета: графит #1B1F24 (основной), коралловый #FF5A36 (только акценты), бумага #F4F5F7. Шрифт интерфейса — Inter (рекомендован, пока не подключён).

## Стек (не менять без ADR)

- C++20, CMake ≥ 3.28, vcpkg (manifest mode), Ninja.
- Qt 6 Widgets + Qt Advanced Docking System (только в `shell/`).
- VTK 9 (только в `extensions/fem.results.viewer` и `shell/viewport`).
- OpenCASCADE, Gmsh, Netgen — не раньше этапа «Препроцессинг».
- HDF5, zstd, nlohmann/json, toml++, fmt, spdlog, libgit2, Eigen.
- Python 3.12 встроенный, привязки через nanobind; тесты Python — pytest.
- Тесты C++ — GoogleTest. CI — GitHub Actions: Windows x64, macOS arm64, Ubuntu.

## Раскладка репозитория

```
core/          libfemcore: Model IR, Command Bus, Context Keys, when-выражения,
               Extension Manager, Job Manager, Task, Settings, логирование. БЕЗ Qt GUI и VTK.
storage/       папка проекта .slproj, детерминированный JSON, хранилище блоков, история (libgit2)
python/        nanobind-модуль `stresslab`, extension host (отдельный процесс), журнал .slpy
shell/         Qt-оболочка: окно, доки, дерево, свойства, палитра, полоса этапов, нижняя панель
app/           исполняемый `stresslab` (GUI и `--headless`)
extensions/    встроенные модули, каждый в своей папке с stresslab-extension.toml
tests/         unit-тесты, golden-модели (tests/models/*.inp + ожидаемые результаты)
cmake/         CMake-модули: Branding.cmake (пути к иконкам и логотипам), EmbedCatalogs.cmake (строки ядра)
resources/     не-код: бренд-кит в resources/branding/
docs/          документы, ADR, руководство по модулям
```

## Архитектурные правила (нарушение = блокер ревью)

1. **Ядро не знает про МКЭ-специфику кроме Model IR.** Решатели, форматы, мешеры, постпроцессинг — модули в `extensions/`. В `core/` и `shell/` не должно быть слов `calculix`, `abaqus`, `inp`.
2. **`core/` и `storage/` собираются и тестируются без Qt GUI и VTK** (опция `FEM_BUILD_GUI=OFF`). Допустим только Qt Core, если без него нельзя; по умолчанию стандартная библиотека.
3. **Все изменения модели идут через Command Bus.** Каждая команда имеет id, сериализуется в строку Python для журнала и поддерживает undo.
4. **Модуль встраивается, а не рисует.** UI модуля описан в манифесте (contribution points из `docs/architecture.md` §4.2). Оболочка не содержит МКЭ-кнопок, зашитых в код.
5. **Включение/выключение модуля без перезапуска**: всё, что внёс модуль (`owner`), исчезает из реестра и UI; данные модуля в модели сохраняются как непрозрачные блоки.
6. **Детерминированная сериализация.** Сохранить → загрузить → сохранить даёт идентичные байты. Сортированные ключи, фиксированный формат чисел, `\n` как перевод строки. Каждый новый тип объекта получает такой round-trip тест.
7. **Долгие операции асинхронные**: возвращают `Task` с прогрессом и отменой, UI не блокируется.
8. **Job Manager отделяет «что запустить» от «где запустить»** (основа будущего облачного запуска). Адаптер решателя не вызывает `subprocess` сам, а отдаёт `JobSpec`.
9. **Всё доступно без GUI**: любой сценарий, который можно сделать мышью, можно сделать из `stresslab --headless run-script`.
10. **Лицензии**: GPL-код (Gmsh, CalculiX) только отдельным процессом, никогда не линковать. TetGen не использовать. Новая зависимость — проверить лицензию и записать её в `docs/dependencies.md`.

## Кросс-платформенность

- Пути только через `std::filesystem` / Qt, UTF-8 везде. Тесты с путями, содержащими кириллицу и пробелы.
- Не использовать Intel MKL, Windows-only или Linux-only API без абстракции.
- Горячие клавиши через абстракцию Ctrl/Cmd.

## Стиль кода

- C++: clang-format (файл в корне), `snake_case` для функций и переменных, `PascalCase` для типов, пространство имён `fem::`. Без исключений через границу C ABI модулей.
- Python: ruff + black, типизация, `from __future__ import annotations`.
- Идентификаторы, комментарии, сообщения коммитов — на английском. Строки интерфейса — через систему локализации, ru и en с первого дня; не писать текст UI литералами в коде.
- Маленькие PR: одна задача из `docs/plan.md` = одна ветка = один PR.

## Сборка и тесты

```bash
cmake --preset core-debug          # только core/storage/python, без GUI (быстро, для CI и облачных сессий)
cmake --build --preset core-debug
ctest --preset core-debug
cmake --preset full-debug          # всё, включая Qt/VTK
pytest python/tests extensions
```

Перед тем как сказать «готово»: сборка проходит, `ctest` и `pytest` зелёные, новый код покрыт тестами, `clang-format` и `ruff` чистые. Если тяжёлые зависимости (Qt, VTK) не собираются в текущем окружении, собери и протестируй `core-debug` и честно напиши в PR, что GUI-часть не собиралась.

## Как работать над задачей

1. Прочитай задачу в `docs/plan.md` и связанные разделы документов.
2. Для задачи больше ~300 строк сначала выдай план (plan mode) и дождись подтверждения.
3. Сначала тесты или golden-данные, затем код.
4. Не расширяй объём задачи. Замеченное «по пути» запиши в `docs/backlog.md`.
5. В конце обнови `docs/plan.md`: отметь задачу выполненной, допиши отклонения.
