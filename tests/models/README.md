# Эталонные (golden) модели

Модели с аналитическим решением, на которых проверяется любой решатель StressLab: адаптер CalculiX (3.5),
чтение его результатов (3.6) и все следующие. Приёмка этапа 3 — «golden-модели проходят на трёх ОС с заданной
точностью». Решения и причины — `docs/adr/0026-golden-models.md`.

| Файл | Что это |
|---|---|
| `<id>.toml` | описание модели: задача, тип элементов, параметры, густота сетки, проверки (значение, формула, допуск, где измерять) |
| `<id>.inp` | входной файл Abaqus, который читают и Abaqus, и CalculiX; **пишется генератором**, руками не правится |
| `generate.py` | строит сетки и пишет `.inp` по описаниям |
| `golden.py` | обвязка: импорт `.inp` → решатель → проверки, отчёт |
| `analytic_solver.py` | «решатель»-заглушка для тестов обвязки: пишет точные решения как Results IR |

Единицы всех моделей — мм, т, с (силы в Н, напряжения в МПа, плотность в т/мм³); сталь E = 210 000 МПа, ν = 0,3.

## Модели

Измеренное значение — среднее (`mean`) или сумма (`sum`) компоненты по узлам в указанном месте последнего кадра
последнего шага. Отклонение считается от аналитического значения; проходит, если оно не больше допуска.
Столбец «Abaqus 2023» — проверка самих моделей настоящим решателем (локально 18.10.2026, файлы как есть, вывод
`*OUTPUT, FIELD`, напряжения в узлах — среднее значений элементов): отклонение от аналитики — это погрешность сетки, допуск взят с запасом под другие решатели.

Подробности задач:

- **Консоль.** Ось балки — x, заделка — все узлы торца x = 0 (`ENCASTRE`), сила −z делится поровну между узлами торца
  x = L. Формула Эйлера—Бернулли не учитывает сдвиг (+0,2 % при L/h = 20) и стеснение Пуассона в заделке —
  отсюда отклонения порядка 0,5 % у объёмных элементов. Сетка C3D10 — кубы 5 мм, каждый разбит на 6 тетраэдров.
- **Пластина с отверстием.** Центр отверстия — начало координат, нагрузка вдоль x. Моделируется четверть
  (x ≥ 0, y ≥ 0; `XSYMM` на x = 0, `YSYMM` на y = 0). S4: все узлы закреплены по z, растяжение — узловые силы на
  кромке x = 200, согласованные с линейной кромкой (половина на угловых узлах). C3D8: половина толщины,
  `ZSYMM` на срединной плоскости z = 0, растяжение — отрицательное давление `*DSLOAD` на грани x = 200. Сетка —
  O-образная от отверстия до квадрата 100 × 100 со сгущением к отверстию (первый элемент ≈ 0,5 мм), дальше
  регулярная. Формула Peterson для брутто-напряжения: Kt = (3 − 3,14·r + 3,667·r² − 1,527·r³)/(1 − r), r = d/W.
- **Толстостенный цилиндр.** Ось — z, моделируется четверть кольца длиной 10 мм; на торцах z = 0 и z = 10 узлы
  закреплены по z (плоская деформация), давление `*DSLOAD` на внутренней поверхности. Окружное напряжение на оси
  x — это S22, радиальное перемещение — U1. Напряжения Ламе не зависят от осевого условия, перемещение — зависит
  (формула для плоской деформации).
- **Куб под гравитацией.** Сумма реакций должна равняться весу с точностью решения системы — это проверка
  гравитации (`*DLOAD … GRAV`) и плотности, а не сетки.

## Формат описания

```toml
title = "Cantilever beam, tip load, C3D20"   # для отчётов
problem = "cantilever"        # cantilever | plate_hole | thick_cylinder | cube_gravity — что строит генератор
element = "C3D20"             # тип элементов Abaqus
model = "cantilever_c3d20.inp"

[units]                       # аргументы model.set_units перед импортом
length = "mm"
mass = "t"
time = "s"
temperature = "degC"

[parameters]                  # числа; ими пользуются генератор и формулы проверок
L = 200.0
P = 100.0
# ...

[mesh]                        # густота сетки для генератора
divisions = [20, 2, 2]

[[checks]]
name = "tip deflection"
field = "U"                   # имя поля и компоненты — как в Abaqus: U/U1..U3, S/S11..S23, RF/RF1..RF3
component = "U3"
box = [[200.0, -5.0, -5.0], [200.0, 5.0, 5.0]]   # или point = [x, y, z]
reduce = "mean"               # mean (по умолчанию) | sum | min | max | maxabs
formula = "-P * L**3 / (3 * E * b * h**3 / 12)"  # Python, имена — параметры и pi, sqrt, sin, cos, tan, exp, log
expected = -1.52381           # должно совпадать с формулой до 1e-5, иначе описание не читается
rel_tol = 0.02                # и/или abs_tol; проходит |измерено − expected| ≤ max(abs_tol, rel_tol·|expected|)
```

Место задаётся координатами: точка или прямоугольный ящик, расширенный на 10⁻⁶ размера сетки. Метки и наборы не
используются, потому что сетка результатов — своя у каждого решателя. Узлы без значения в выбранном месте —
ошибка проверки, а не ноль.

## Как прогнать свой решатель

Решатель для обвязки — объект с методом `solve(model, workdir) -> документ результатов`: `model` — документ, в
который импортирован `.inp` (Model IR), результат — Results IR (`docs/extensions/fem.model.structural.md`:
`result_step` → `result_frame` → `result_field` со своей сеткой). Поля — `nodal` или `elementNodal` (значения
элементов в узле усредняются). Адаптер решателя (`docs/architecture.md` §6) оборачивает в `solve` свои
`validate`, `write_input`, `run` и `read_results`.

Прогон идёт внутри приложения, где загружается модуль импорта `.inp`, например
`stresslab --headless run-script прогон.py`:

```python
import sys
from pathlib import Path

sys.path.insert(0, "tests/models")
import golden

for case in golden.load_cases():                  # или load_cases(ids=["cube_gravity"])
    report = golden.run_case(case, MySolver(), Path("work") / case.id)
    print(report.format())                         # строка на проверку: ok/FAIL, измерено, ожидалось, допуск
    report.assert_passed()
```

`run_case` импортирует модель в активный документ (он должен быть пуст) и после решения отменяет импорт, поэтому
модели можно прогонять подряд в одном процессе. `golden.evaluate(case, results)` проверяет готовый документ
результатов без импорта.

## Как изменить модель

1. Поменять описание `<id>.toml` (параметры, густоту сетки, проверки; новая модель — новый `.toml` и, если нужна
   новая задача, функция в `generate.py`).
2. `python tests/models/generate.py` — перезаписать `.inp`; `python tests/models/generate.py --check` — сверка.
3. Прогнать модель настоящим решателем и обновить таблицу выше; аналитику пересчитывает формула описания.
4. `pytest python/tests/test_golden_models.py` — описания читаются, файлы совпадают с генератором, точное решение
   проходит, неверное на 10 % — нет.
